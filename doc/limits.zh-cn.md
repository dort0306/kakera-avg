# 验证与限制

当前应用版本 v0.11.2。本文记录检查方法、已实现范围的结果、资源与内存边界，以及未实现/未验证的能力。历史版本的验收记录只代表当时范围，不能当作本轮复测。

## 验证方法

```powershell
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo run --locked -- --check
```

`--check` 完整校验剧情、UI、JS、资源和引用后退出，不打开窗口；显式 `--renderer d3d11` 可同时验证设备。包发布后还应在源码外运行 `--check`，并分别验证 KPAK 1/2 的独立重载。

v0.11.2 的完整回归为 315 项通过、2 项忽略、0 失败；`--check` 显示 demo 31 场景、4 变量、3 JS 文件、20 UI 页面与 2 视频、1 模型。实际结果与未验项见 [v0.11.2 验收记录](v0.11.2-validation.zh-cn.md)，下一版本待执行项见 [v0.11.3 验证计划](v0.11.3-validation-plan.zh-cn.md)。

## 已实现范围内未验证项

- 组合标签与分页的 GUI 点击、全部 DPI、128 组件/1024 实例/8 层嵌套及全槽翻页压力项未逐项实机执行，不计入通过。
- 多显卡、高 DPI 跨屏、实际驱动丢失、设备声音与主观听感分别以验收记录为准；自动化检查不能替代 GUI、设备流或听感验收。
- 历史验收记录中的 GUI、DPI、设备和听感结论不自动适用于新版本；未重跑的项目按未验证处理。

## 未支持能力

- 首发 Windows x64；未提供 Vulkan/Metal 原生后端，只保留接口。
- 未提供跨平台视频、任意 JS tick、CSS/DOM/富文本/回滚、网络流/包内 seek/精确音画同步。
- Live2D 未实现 physics3 求解、完整动作混合、自动口型和高级 offscreen。
- 粒子与总音量属于 v0.11.3 待实现规划，当前 API 不可用，见 [PLAN.md](../PLAN.md)。
- 编辑器、AI 客户端与 DAP 适配器未实现；只保留规划文档归档。

## 资源与内存边界

KPAK 2 打开时只读取 80 字节头和尾部索引，按资源/块读取并解压，固定 1MiB 原文块；每个流仅保留当前块。索引及每块均有 SHA-256，块校验成功后才交给消费者。普通启动按需验证；`--check` 和打包自检扫描所有唯一块，能发现未使用资源的损坏。SHA-256 检错不提供签名或来源认证。

| 容器 | 包与逻辑总量 | 单文件 | 文件数 | 读取方式 |
| --- | --- | --- | --- | --- |
| KPAK 2 | 1TiB | 64GiB | 100000 | 常驻受限索引，独立分块按需读取 |
| KPAK 1 | 512MiB | 128MiB | 10000 | 整包解压到内存 |

KPAK 2 索引最多 128MiB，最多 1048576 唯一块；具体二进制契约见 [格式规范](kpak-format.zh-cn.md)。这些是容器硬上限，不代表已经以 1TiB 实机验收。

工程热更继续校验完整快照；打包使用私有暂存和流式指纹，只复制并复查发布依赖、附加文件及清单。两者都需要足够临时磁盘空间。`ContentSource.read` 仍限制 128MiB，流式 `open`/`copy_to` 最大 64GiB。视频流式复制到 Media Foundation 的临时文件，不再构造整视频 `Vec`；仍有 16 段、1920×1080、60fps、300 秒和 PCM 缓存预算。没有直接从包 seek 播放或网络流。

当前播放器仍在准备阶段解码所有已声明的图像/字体/音频/模型并准备视频，原解码缓存预算保持；v0.8.1 消除了整包/整视频字节缓冲，并未实现所有资源随场景进入才解码。大游戏启动仍有资源校验与视频临时文件复制时间。

## 发布与限制说明

发布目录中的源码引用链接供仓库开发环境查阅；本地发行目录不携带 Rust 源码或游戏散文件。发布程序只读 exe 旁 `game.kpak`，不监控散文件；坏包失败，不回退目录。第三方许可必须随包保留，见根目录 [README](../README.md#许可证)。
