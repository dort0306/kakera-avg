# v0.3 界面增量验收

日期：2026-10-23。Windows，release v0.3.0，`games/demo`（content-version 2）。通过 computer-use 操作实际窗口并观察每步画面。基线验收保留在 [v0.2 记录](v0.2-ui-validation.zh-cn.md)，本文件记录本版实际执行的检查。

## 环境与隔离

```powershell
cargo build --locked --offline --release
./target/release/kakera-avg.exe --save-dir target/gui-v03 --no-audio
```

使用全新 `target/gui-v03`，未覆盖已有用户槽位或 v0.2 验收目录。开始时测试设置文件误含未知字段 schema_version，程序正确提示并回退默认值；随后通过设置窗口将文字速度改为 0 完成分支验收。末尾改为每秒 2 字素簇复查逐字门控及菜单暂停。设置文件本身不带 schema_version。

## 实际结果

| 检查 | 操作与观察 | 结果 |
| --- | --- | --- |
| 初始条件选项 | opening 继续进入 question，仅显示散步与结束，不显示邀请 | 通过 |
| otherwise 兜底 | 未散步直接结束，到 decision 再继续，进入 refuse，显示房间安静的结尾 | 通过 |
| 更新与循环 | 散步一次返回 question；历史显示信任 1、已相识“是”、心情“期待”，有四条记录和散步选择 | 通过 |
| 普通 case | 散步一次再结束，经 decision 进入 friendly，显示“下次再一起走走吧” | 通过 |
| 邀请解锁 | 重开后散步两次，question 出现第三个邀请按钮，前两项保持原顺序 | 通过 |
| 首命中优先 | 选择邀请，经 decision 进入 accept；未被同时满足的普通信任条件截走 | 通过 |
| 六槽 UI | 保存窗口显示六个独立槽位，在空槽 1 保存，提示成功并显示 question 预览 | 通过 |
| 完全退出与恢复 | Alt+F4 后确认进程 exit 0；重新启动从 opening 开始，再手动读取槽 1 | 通过 |
| 变量、历史及选项恢复 | 恢复 question，邀请可见；历史显示六条、两次散步，信任 2、已相识“是”、已邀请“否”、心情“期待” | 通过 |
| 恢复后继续运行 | 再选邀请，经 decision 正确进入 accept | 通过 |
| 重开清状态 | 再次重开，进入 question 后历史仅两条，信任 0、两个 bool 为“否”、心情“平静”，邀请隐藏 | 通过 |
| 逐字门控 | 速度 2：opening 第一下空格仅补全，第二下进入 question；question 逐字期间无选项，补全后只出现满足条件的两项 | 通过 |
| 菜单暂停 | question 部分文字时打开历史，间隔观察文字保持不变；关闭后从原进度少量继续，没有补完暂停时段 | 通过 |
| 中文与布局 | 普通窗口 1282×751、最大化 2048×1104 的稳定画面中中文完整、三按钮无重叠；游戏等比 16:9，最大化左右留黑边；逐字中整句定位未漂移 | 通过 |

槽位文件同时检查为 schema 3，包含当前位置 question、六条历史、当前变量和初始变量检查点。可公开复现的相同结构见 [存档示例](v0.3-save.example.json)，该示例由本次新槽位生成并由自动测试校验恢复。

## 验收边界

- 本轮实际 UI 使用 `--no-audio`；三通道纯计划和音频解码回归测试通过，但本轮未测试设备输出、主观听感或热拔插。
- 信任达到 3 隐藏散步、所有选项均不可用、恶意输入、动态更新失败回滚、1000 条历史裁剪和非法存档由自动测试覆盖，未逐项通过 GUI 构造。
- 未复验所有 DPI、窗口最小尺寸、其他操作系统或任意作者内容。v0.2 的覆盖确认、坏档窗口等完整矩阵保留原验收结论，本版不将其冒称为重新逐项点击。
- 验收结束已正常关闭应用；未提交或推送 Git 变更。
