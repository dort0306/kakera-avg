## 实现

- 删除 Frame.video、story frame.video 解析、剧情视频绘制/输入/自动推进、ctx.skipVideo、game.videoPlaying/videoSkippable；视频仅作为 UI sequence 步骤。VideoCue 移到 media 呈现模块，不再属于领域 Model。
- 新增 on.frameEnter/Exit、on.screenOpen/Close，ID/name 注册解析及严格目标校验，候选回调整批最多 32 命令/16 次页面派发。JS 仍隔离、同步、无随机/时钟/宿主 IO。新生命周期不混合设置、CG 等持久 IO；原 game.enter 保持独立白名单。
- frameExit 打开 UI 保留原剧情与完整待续状态；frameEnter 打开 UI 将该幕与 UI 同事务提交。同幕 UI 返回不重放已进入幕的 enter，避免视频回环；返回新幕可再次自动进入下一 UI。ctx.present/resume 为受固定隐藏槽约束的交接能力。
- flow-checkpoint.json 保存 source/continuation、页面/原栈、UI 变量、演出 ID 及 entered/exited/active；整体 2MiB，原子覆盖。源/续接会话均完整重放，二者还须是同一状态或恰好一次合法 Controller 推进；UI 栈、变量、资源和来源再次校验，不能用未知原栈导致渲染索引崩溃。
- 返回候选包括待提交隐藏槽和已准备媒体；场景断点暂停时文件仍 active，继续提交时才写完成标记。成功写 inactive 墓碑；恢复活动隐藏槽时只重开 UI，视频从零，不重放 game.enter/frameEnter/Exit。
- save 9 每条 resume_to 必填，可为 null；显式返回边与普通路由分别校验、裁剪和重放。旧 save 8 拒绝且不迁移。普通自动槽继续独立轮换，隐藏槽不进入槽位列表、监控或资源包。

## 真实窗口与跨进程

使用 target/v090-gui-saves 独立目录，没有操作作者原有存档。

1. 默认呈现后端窗口从 opening → question → intro，打开“片头动画演示”后继续；文字完整后由 frameExit 自动打开 story-intro，screenOpen 自动开始真实 MP4，覆盖层可见测试画面并显示 00:00:01.353。窗口画面保持 16:9，中文与布局正常，窗口标题随当前页面显示 intro。
2. 在视频中按空格跳过，关闭 story-intro 并恢复到 opening，没有穿透推进到 question；隐藏槽 active=false，stack=hud，序列为空。普通自动槽仍按原机制写入 auto-1 等文件。
3. 再次进入视频后，在播放中按 Alt+F4 正常退出；磁盘隐藏槽 active=true、exited=true、entered=false，source=intro、continuation=opening、栈 hud/story-intro、sequence=story.intro。普通自动槽没有因此多出隐藏槽或混合文件。
4. 同目录以 CPU 呈现后端重启，恢复 story-intro 并再次播放真实 MP4，画面从零开始（观察到 00:00:01.800）；按空格后正常返回 opening，隐藏槽写 inactive 墓碑，普通自动槽继续轮换（观察到 auto-10）。两次启动均使用 --no-audio。
5. 跨进程恢复没有重放 game.enter/frameEnter/Exit，只重建 UI 生命周期并从零播放；普通自动槽继续独立轮换，未被隐藏槽覆盖。

本轮未人工穷举全部 DPI/全屏/跨显示器、视频失焦音画同步、200 槽跨进程矩阵、真实设备丢失或主观听感；这些项目不能由确定性测试替代。视频素材中的旧片头文字属于原测试素材，不是播放器版本。
