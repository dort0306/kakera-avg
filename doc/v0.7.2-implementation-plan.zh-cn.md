# v0.7.2 背景输入与带截图存档落地策略

制定日期：2026-10-25，先于功能代码。目标：非控件区域左键继续、右键隐藏/恢复 HUD，保存时附带可查看的时间和游戏截图。纯剧情 Controller/Model 不增加 UI、时钟、GPU 或 IO。

## 1. XML/JS 输入扩展

UI schema 2 增加 screen 的 background-click/background-right-click 两个可选事件属性，严格验证已注册 on.ui，禁止保留生命周期名。只向顶层页面派发，不穿透菜单；普通按钮/选项/滑条/开关及滚动区域优先，禁用控件也阻挡背景点击。黑边、窗口外、工程浮窗、提示、失焦不触发背景事件。按下与释放都必须在可用背景区，同一次手势不得同时触发控件和背景、不得拖出按钮后误推进。

demo 增加 hudVisible UI bool：scene 保持可见，HUD 放入独立 panel。左键背景在 HUD 隐藏时先恢复，不推进；正常时按 canAdvance 调用现有 ctx.advance，沿用转场跳过/逐字补全/推进仲裁。右键背景切换可见性；右键控件不触发。选项完成时不会默认选择，菜单不继承底层背景事件。HUD 显示状态瞬时、不入档，隐藏不等于暂停；空格保留已有行为。

## 2. 存档契约与时间

保留 story 7/UI 2/save 6/KPAK 1。现有 saved_at_unix_ms 已为实际保存时间，本版将其作为可读本地日期时间暴露到手动/自动槽元信息。save 6 增加可选 screenshot 对象，旧无截图档仍可加载；不猜测或迁移更早存档。截图为固定 320×180 PNG、Base64 存入同一个 JSON，严格格式/尺寸/压缩与展开预算；整个文件仍同目录临时文件+原子替换，截图、时间与 Session 不分离提交。

GUI 手动存档要求有效截图，获取/编码/校验失败时提示并保留旧档和 UI 计划；无窗口的 SaveStore 纯 API 可继续写无截图档。自动保存等待对应已提交场景实际呈现后写入，截图失败保留已有档并停用 autosave，不撤销剧情。pending 期间不接受新剧情输入，避免把尚未显示的场景与旧图混存；不把历史重放作为每次截图写入的前置重复工作。

## 3. 截图来源与 GPU 边界

Windows D3D11 host 缓存最近窗口/最近无菜单游戏画面的 GPU 副本，并标记场景呈现 revision；同场景自循环也更新 revision。手动保存优先使用同 revision 的菜单前游戏画面（含台词/HUD），没有时只能使用同 revision 的已呈现窗口，绝不拼接其他场景截图。捕获客户区，不捕获桌面、系统标题栏或其他应用。

正常帧只进行受预算约束的 GPU 拷贝，不逐帧回读/编码；仅在实际保存时读回并缩为 320×180。GPU/WARP 和 CPU 像素模式共用窗口捕获接口；设备重建清理旧设备捕获，等待新帧后保存。资源创建/截帧在宿主更新阶段，文件 IO 在 App 更新阶段，绘制仅产出形状与像素，不执行写档。为其他宿主保留捕获提供接口，未实现时明确报告而非保存黑图。

## 4. 元信息与 UI

当前十个手动槽及十个自动槽提供 savedAt、hasScreenshot、image 等只读字段。缩略图只在菜单资料刷新时校验/解码/上传，换页清理旧预览纹理，不在绘制或逐字 tick 读盘。image-bind 支持槽位的受信任运行时图片 ID，不开放文件路径。demo 保存/读取/自动档卡片显示时间、截图、位置预览及按钮；旧档显示“无截图”占位。
