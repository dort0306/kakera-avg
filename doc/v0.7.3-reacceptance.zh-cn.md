## 待修复问题

### 1. [P1] Ctrl 没有抑制或重置自动播放等待

- 位置：[App 输入门控](../src/app.rs#L445)、[自动播放计时及仲裁](../src/app.rs#L569)。
- `auto_play.tick` 每次仍独立累计时间，未检查 Ctrl；最终分支为 `skip || auto_advance`，松开 Ctrl 时也未重置自动播放。
- 使用真实 App/egui 更新路径复现：初始未读句，文字速度 80、自动等待 0.2 秒、自动播放开启；Ctrl 按住的一次 0.15 秒更新让短句自然显示完整，再松开 Ctrl 更新 0.06 秒。期望留在 opening、重新等待，实际进入 second（沿用按住期间的 0.15 秒）。
- 另一次 0.25 秒更新覆盖低帧率/卡顿边界：Ctrl 仍按住，句子在该次更新完成；只读快进在更新开始时判定为未读，自动播放却直接推进到 second。
- 两个探针分别为 `reaccept_release_restarts_autoplay_delay`、`reaccept_ctrl_suppresses_autoplay_and_release_restarts_delay`，均失败。
- 修复验收应覆盖按住/松开、未读句完成当帧、长帧、菜单/失焦/自动截图等待，以及每次更新至多一个剧情提交。

### 2. [P2] 非暂停模态页被 Ctrl 穿透

- 位置：[skip_held](../src/app.rs#L445)、[blocked](../src/app.rs#L173)，对比已有 [State::keyboard](../src/interface/host.rs#L30)。
- 合法 XML 可声明 `modal="true" pause="false"`，用来让底层动画继续。空格检查栈深并拒绝此时的宿主剧情输入，Ctrl 只检查 paused，没有使用同样的顶层门控。
- 探针建立 hud + menu 两层栈，两页均 pause=false；全部快进开启，当前句完整。`State::keyboard=false`，按 Ctrl 一次，期望停在 opening，实际进入 second。
- `reaccept_modal_page_blocks_ctrl_even_if_animation_is_unpaused` 失败。demo 菜单默认 pause=true，因此常规 demo 菜单操作不足以发现此问题。

### 3. [P2] 已读数量限制只在读取端生效

- 位置：[ReadHistory::mark/save](../src/read_history.rs#L67)，对比 [load 数量验证](../src/read_history.rs#L47)。
- `mark` 没有 100000 条限制，`save` 也不验证数量。依次标记字符串 ID `0` 至 `100000`（共 100001 条），写盘成功且清除 dirty；立即加载同一文件却报“已读进度超过 100000 条”。此数据低于共用 2MiB JSON 上限。
- 探针 `reaccept_saved_marks_must_be_loadable_at_the_count_limit` 失败。下次启动会把该文件作为坏文件按空集处理，可能丢失可用已读进度。
- 修复应确保宿主永不原子替换出自身拒绝读取的已读文件；同时验证已存在未知 ID、数量临界值、2MiB 上限及写失败保留旧文件/dirty 的语义。
