# 多起始幕与 UI 首次进入

2026-10-29。已有 ctx.resume(frame)、XML 页面及读档能力可复用，但宿主启动仍自动执行唯一入口且首次显式选幕会留下默认幕历史，XML/JS 无法阻止这些宿主副作用，故最小扩展 Rust 启动与入口校验。story 8/UI 3/save 9/KPAK 1/2 不变。

- story.entry 为至少一个、空白分隔的 ID/name 列表；全局装配后解析，未知、重复或 ID/别名重复指向同幕拒绝，保留源位置。列表顺序不决定播放器自动进入哪个幕。
- 启动先显示 UI initial 页面；首次必须 ctx.resume("起始幕")、ctx.restart("起始幕") 或载入手动/自动槽。首次不带目标的 resume/restart、推进、保存和自动播放拒绝；不执行 game.enter/frameEnter/Exit，不播放剧情音频，不生成自动档或已读。
- 首次显式选择只允许声明的入口，以初始变量和单条起点历史建立候选；不沿用 inactive 隐藏槽或虚构默认幕返回边。正常剧情中的 resume 保持续接变量/历史语义。ctx.restart(frame) 始终建立新会话；运行中无参 restart 仅单入口可用。
- 活动隐藏交接槽仍按现有完整验证恢复；坏槽保留并提示，回到初始 UI。首次 UI 演出无剧情时不虚构隐藏会话。
- 重建渲染/热更新不能把待选择状态变成已进入。两种包保留所有入口及 ID/name 映射；所有起点的条件与 game.enter 计划均验证。
- demo 增加主菜单、普通/另一故事线入口及载入按钮，交互仅 XML/JS。新增回归覆盖入口解析、首次选择/未选择阻挡、变量历史、生命周期、载入/隐藏槽隔离和原子失败；运行规定检查，GUI/设备/听感单独记录。

GUI 复验修正：发起进入的 UI 事件先切换根页时，以已准备候选栈作为幕回调比较/恢复基线；不能把主菜单切 HUD 误当成幕回调发起的隐藏交接，不能重复派发该事件已完成的页面回调。真正 frameEnter/Exit 打开的页面仍完整准备并持久交接，返回事件指定的 HUD。
