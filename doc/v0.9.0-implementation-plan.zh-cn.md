# v0.9.0 UI 视频与双向生命周期

应用版本 0.9.0，story 8/UI 3/save 9，demo content-version=9，KPAK 1/2 保留。现有 XML/JS 没有页面/幕成对生命周期、受约束的 UI 返回剧情和隐藏持久交接事务，故扩展这些 Rust 宿主边界；布局、演出、目标选择继续由 XML/JS 编写。

- 视频仅保留 UI ui-media.sequence.video；删除 Frame.video、frame XML video、剧情视频输入/渲染/推进分支、game.video* 与 ctx.skipVideo。Media 播放器属于呈现层，不引用领域 VideoCue。
- JS 注册 on.frameEnter/Exit(frameID或name, fn)、on.screenOpen/Close(screenID, fn)，使用与 on.ui 相同的隔离命令收集。正常离幕在完成控制器条件/更新/目标校验后调用 exit，随后 enter；自循环也触发，历史重放不触发。game.enter 的原职责保留。
- frame 生命周期打开页面时，先保存完整 continuation 再交给 UI，保留旧会话/音频，不提前进入下一幕；UI 页面生命周期可 ctx.sequence 自动播放，close 可 ctx.resume(frame) 继续，省略 frame 恢复待续位置。普通 UI 也可 ctx.present(screen) 显式交给 UI。
- 页面开关回调在候选栈上求值，关闭按顶层向下、打开按下层向上，允许继续修改页面；整批命令最多 32、生命周期派发最多 16，循环与重复操作拒绝。回调仅收集命令，失败不部分提交。
- 唯一隐藏槽 flow-checkpoint.json，schema 1，完整保存 active、source/continuation 快照、UI 变量/页面栈、待续幕是否已进入、演出 ID（恢复从零播放）、原页面栈；不含纹理/音频/时钟指针。独立于手动槽与普通自动槽，排除监控/打包。先完整校验与准备，再原子覆盖，再提交。完成写 inactive 墓碑，重启不重复返回；写失败保留旧文件和旧状态。大小仍受 2MiB 严格限制，超过预算拒绝交接。
- 启动优先验证并恢复 active 隐藏槽；坏文件提示且不修改当前剧情。交接中禁止普通存读档/重开/设置或其他持久 IO 混合；全局偏好不在隐藏槽内。热更在交接完成后再替换。
- story 8/UI 3 保留；save 升到 9，每条 history 明确 resume_to（可为 null），显式 UI 返回目标只允许存在场景、变量不被任意改写，重放验证 UI 返回边与普通路由。旧 save 8 不迁移；demo content-version 升到 9；KPAK 1/2 保留。

验证严格拒绝 frame.video、四种生命周期/别名/自循环/首末顺序/失败回滚/循环预算、视频自然结束与跳过只关页一次、隐藏槽损坏/原子失败/跨进程恢复/墓碑/普通槽隔离、返回后变量/历史重放、两格式打包，GUI/设备流/听感分别报告。同步 API/README/指南/AGENTS/版本与发布脚本，历史文档仅归档。
