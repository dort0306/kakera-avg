# UI XML 拆分与发布合并策略

日期：2026-10-28，先于功能代码。应用维持 v0.8.3；story 8/UI 3/save 8、KPAK 1/2 不变。

## 契约

- 既有 XML/JS 没有读取并展开外部 XML 的能力，因此仅扩展 UI 加载/诊断与发布装配的 Rust 边界；页面交互仍使用已有 XML/JS，不向游戏脚本开放 IO。
- UI 入口由 story 的 interface.src 指定，通常为 ui.xml；入口根保留 schema/width/height/initial/title/title-bind。根级 include 只有 src，路径相对游戏根，为受限 .xml 文件。
- 被引入文件以 `<ui schema="3">` 为根，只能有 schema 属性；内容为 variables、gallery、screen、include。支持嵌套引入，按声明顺序深度优先展开。仅支持根级完整页面/数据分组，不引入组件模板或 screen 内片段替换。
- 每文件 variables/gallery 各至多一组，跨文件合并后统一校验变量、CG、页面、控件 ID、资源、绑定与事件；禁止覆盖。允许跨文件前向引用。单文件 UI 继续使用同一当前 schema。
- 最多 128 文件、16 层（入口为第 1 层）；源 XML 累计及合并 XML 各最多 1MiB。保留原有 64 页/1024 控件/8 层节点、128 变量/256 CG 等全局预算。循环、重复/大小写重复路径、越界路径、未知字段/命名空间/混合 schema 及缺失引用拒绝；工程快照/打包沿用链接拒绝规则，目录直接读取继续校验真实路径边界。
- 所有读取通过 ContentSource；XML 节点不离开加载阶段。编译源映射用于静态错误和运行时控件/标题位置，指向作者原文件行列。工程热更仍以完整固定候选验证，坏拆分不替换旧状态。
- KPAK 1/2 均将 UI 入口替换为不含 include 的完整 XML，并移除实际展开的 UI 子文件；入口逻辑路径不改（常规工程为 ui.xml），避免覆盖自定义路径工程中的同名无关文件。JS/素材/显式附加的其他文件保留，源工程不改写。
- 依赖选择自然记录全部 UI 引入；候选重载、依赖集合、清单/源指纹复查及完整包自检继续先于原子提交。低层单文件 UI 无 include 时原字节保持，避免无意义重写。

## 验证与交付

- 覆盖嵌套/根路径、跨文件变量/CG/页面/事件、实体/注释、标题与控件源位置；坏路径、循环/重复、未知结构、重复 ID/组、缺失/坏 UTF-8/XML/schema、文件/深度/总字节与全局节点预算。
- 覆盖两种 KPAK 的真实 CLI 和底层发布路径：包独立重载、无子 UI 碎片、JS/附加 XML 保留、源文件不变、确定性及源改变时旧包保留；工程监控坏编辑回滚/修复恢复。
- 将 games/demo 拆为可运行示例；同步 API、README、发布指南、KPAK、编辑器参考和 AGENTS。运行 fmt、Clippy、完整测试、demo --check、发布包完整检查；GUI/听感未复测项明确说明。
