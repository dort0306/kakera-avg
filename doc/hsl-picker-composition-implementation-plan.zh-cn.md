# HSL 选色器职责拆分落地方案

日期：2026-10-30。状态：**已实现**（2026-10-30 落地，实际记录见 [验收方案](hsl-picker-composition-validation-plan.zh-cn.md) 的“实际落地与验收记录”）。依据用户最新要求：控件仅显示色相环、内部正方形选色区、可选透明度滑块；颜色预览和十六进制文本交由作者 UI 组合。验收要求见 [验收方案](hsl-picker-composition-validation-plan.zh-cn.md)。

本方案覆盖 [HSL 方形选色器](hsl-square-picker.zh-cn.md) 中与内置预览、HEX 和尺寸有关的说明。该文此前的测试通过是历史记录。职责拆分本身不改变颜色数学与提交链路；“正常接受后回跳”按验收方案的真实 App 链路门槛重新测试，结论只写入验收记录，本文不预先声称已修复。

## 1. 范围与必要宿主改动

作者独立预览可由现有 panel/image/nine-patch 的 color-bind 实现，HEX 显示可由 label.bind 绑定同一 UI string；接受草稿继续使用普通 on.ui / ctx.value / ctx.setUi，无需新增命令、变量类型、资源路径或 IO。

现有内置预览、文字与预留空间由 Rust 控件绘制和布局硬编码，XML/JS 无法关闭，故必须对宿主控件做最小调整。此次不新增 preview/show-hex 等属性，不提供旧外观开关，不再维护两套布局。

### 控件内保留

- H 色相环、S/L 正方形及其选择标记。
- alpha=true 时的透明度条、条内棋盘底、渐变和滑块标记。
- 必需的焦点/禁用反馈和裁剪。焦点描边属于交互反馈，不是颜色预览。

### 控件内删除

- 独立颜色预览矩形、它的棋盘底和相关几何字段。
- HEX 文本、文本坐标、文本绘制及为它保留的高度。
- 旧“点击预览区”的专用命中语义及相关测试假设。

alpha 条中的颜色渐变与棋盘底是编辑 A 的必要反馈，不能随独立预览一起删掉。删除的是颜色字符串的内置绘制，**不是事件中的颜色编码**；ctx.value 仍输出九字符大写 #RRGGBBAA。

## 2. 冻结布局与尺寸契约

所有尺寸先按 UI 逻辑坐标计算，再统一乘舞台缩放；不随 DPI 重复缩放。width/height 是整个控件的外矩形，绘制及命中均受该矩形和父裁剪限制。

设 W/H 为控件宽高，透明度条高 18、与色盘框间距 8，两者均为逻辑单位：

| 项目 | alpha=false | alpha=true（含省略属性） |
| --- | --- | --- |
| 色盘外附加高度 R | 0 | 26（8+18） |
| 色盘框直径 D | min(W,H) | min(W,H−26) |
| 内容组总高 | D | D+26 |
| 最小尺寸 | 128×128 | 128×154 |
| 建议紧凑尺寸 | 256×256 | 256×282 |

- 整个内容组在外矩形中水平/垂直居中。色盘框为 D×D；圆心位于其中心。矩形额外空间是作者给定长宽比产生的居中留白，不是旧预览/HEX 占位。
- 保持现有环和内方形相对比例：环外半径 D/2−6，环内半径为外半径的 0.82；正方形边长为外半径×0.78×√2，中心与环一致。正方形四角不进入色环。
- alpha 条在色盘框下方 8 处，高 18；左右距控件外矩形各 8，宽 W−16。不再绘制中间预览行。透明度条宽度跟随作者控件宽度，不跟随较窄色盘直径。
- alpha=false 时完全不创建/绘制/命中 alpha 子区，不分配其 Tab 焦点，不保留该 26 高度。
- 加载校验与渲染采用同一尺寸定义，D 至少 128；不依靠绘制时 max(1) 或静默扩容接受非法尺寸。原有有限值、正尺寸、节点和八个 picker 预算保持。
- 旧 256×320 等合法矩形继续按新规则布局；不根据历史尺寸启用旧预留空间。这是同一 UI 3 契约下的控件外观调整，不增加兼容解析器。

## 3. 输入和颜色提交契约

HSL 数学保持：横向 S=0…1，纵向从上到下 L=1…0，顶白/底黑。方形内部和边界可自由移动；拖出时按坐标夹取，按下锁定子区直到释放。保留灰色 H、黑白 H/S 和自身 RGBA 回显对应的浮点位置。

删除预览后，重新从实际布局确定色环/方形/alpha 的命中区域；不得沿用旧预览、HEX 或旧 alpha 行坐标。控件外矩形仍整体登记为 UI 输入阻挡区；矩形内间隙/留白按下不改色、不启动抓取、不发事件，也不穿透到剧情。外部作者节点按既有页面/遮挡规则处理，不扩大 picker 的命中区域去占用外部预览。

Tab/Shift+Tab 仍遍历环 → 方形 → alpha（若有）→ 其他控件。方向键、Escape、顶层/隐藏/禁用/失焦、页面变化、热更/读档/定义替换的清理和释放屏障保持。不把预览或 HEX 作为新焦点元素。

事件仍是一帧至多一个候选，由业务回调决定接受、修正或拒绝；渲染不直接改 UI string，也不在鼠标松开时直接写偏好文件。HEX 格式化仍可用于构造事件值，不得因为删除 painter.text 而删掉事件编码或规范化校验。

**回跳问题独立门槛：**正常接受候选的最小作者回调中，松开后绑定、方形标记、外部预览和外部 HEX 必须一致保持。拒绝候选时恢复已提交值属于原契约；不得为“防回跳”而强行保留被拒绝的候选。实现者若仍复现正常接受后回跳，应先记录事件/提交/下一帧绑定证据，另行修复并回归，不能把本职责拆分写成已修复。

## 4. 作者 UI 组合与 demo

不需要新的宿主预览/文本 API。作者可独立选择：仅选色器、加色块预览、加 HEX label，或把预览放在另一面板/页面。三个可视节点可共享同一个 ui.<string>；on.ui 将 ctx.value 写回该变量即可同步。需要标明变量名与绑定路径的区别，不使用旧快照值覆盖候选。

预览使用 color-bind 读取已提交 UI 草稿，HEX label 使用 bind 读取同一草稿。半透明预览要棋盘底时，由作者现有图片/面板组合提供；不为此增加新的宿主棋盘节点或背景 IO。预览和 HEX 都是可选的，不成为 color-picker 加载的前置引用。

demo 的 games/demo/ui/colors.xml 已有独立 colorPreview / colorPreviewText / bgValue / textValue，应保留并检查这些节点继续工作，避免另建重复预览。拟将两个 picker 分别改为 256×282（背景色）和 256×256（文字色）；x/y、按钮和其他节点以实际页面布局检查为准，不能仅减高度而不检查相邻间距。普通配色回调和应用/取消/恢复默认事务沿用现有 scripts/ui.js。
