# v0.7.2 维护修复记录

日期：2026-10-25。范围：通读全部代码与历史文档后发现的四个问题。本轮不提升版本号，不改 story/UI/save/KPAK schema，不改写既有验收记录；只修内部实现、兼容边界与文档，并补上缺失的测试。历史记录仍是 v0.7.2 功能验收的原始证据。

## 1. 问题与修复

### 1.1 `image-bind` 的报错文案与规则不一致

- 现象：`ui.xml` 里 `image-bind` 填了非法路径时，报错只写「需要 ui 字符串或 gallery item.image」，但校验实际允许 `gallery`、`slots`、`autosaves` 三种 repeat 模板的 `item.image`（v0.7.2 截图缩略图正是用后两者）。作者按提示排错会误以为存档页缩略图不受支持。
- 原因：v0.7.2 扩展了允许的数据集，只改了判断条件，没改错误串。
- 修复：文案改为「image-bind 需要 ui 字符串，或 gallery/slots/autosaves 模板的 item.image」。校验规则不变，因此既有内容不受影响。

### 1.2 demo 里不被读取的旧 `flow.xml`

- 现象：`games/demo/flow.xml` 是 v0.3 声明式规则的时代产物。story schema 4 起 loading 不再读取 flow（只有 schema 1–3 才走 flow 解析），但 `kakera-pack` 按「收集工程内未排除文件」的规则把它打进了发布包。历史验收（v0.4/v0.5）写的是「运行目录不含旧 flow.xml」，现状与之相反。
- 原因：demo 升到 schema 7 时没有清理这个历史文件；打包器也不该为此特判文件名。
- 修复：文件移到归档 `doc/archive/demo-flow-v0.3.xml`，并更新文件头注释说明归档身份。v0.3 规则的**可运行契约样例**仍在 `doc/v0.3-example/flow.xml`（被 `tests/variables_rules.rs`、`tests/audio.rs` 引用），没有被改动。
- 结果：demo 打包文件数 69 → 68，其余字节不变，包内 `--check` 通过。

### 1.3 内置兼容界面缺一条明确边界（新增自动档语义）

- 现象：没有 `<interface>` 的旧内容（story schema 1–3）由 `view.rs` + `menus.rs` 的内置界面呈现。它与 XML UI 是两套呈现实现，新交互只会进 XML 那套。直接的后果是自动档：`App::enter` 对任何内容都排队自动保存，而自动档入口（`repeat source="autosaves"`、`ctx.loadAuto`）只存在于 XML UI。旧内容因此会不断写出自己**永远读不回**的 `auto-1…10.json`。
- 原因：v0.6 引入自动档时没有区分「有 XML UI」与「内置兼容界面」两条呈现路径。
- 修复：
  - `PlayerApp::autosave_enabled()` = 存在 XML UI **且** 设置开启；`enter()` 用它替代裸 `settings.autosave`。兼容界面冻结在加入 XML UI 之前的行为（无自动档、无自动播放、无视频跳过、无 CG、无截图存档页）。
  - `main` 在加载完成后、且内容没有 `<interface>` 时打印一行：「界面：内容未提供 XML UI，使用内置兼容界面（story schema 1–3）；不写入自动档」。`--check` 同样可见。
  - 兼容界面本身不改绘制，也不删任何能力；`settings.json` 仍按原规则独立保存（设置与剧情槽无关）。
- 刻意未做：没有把自动档列表塞进内置菜单，也没有让自动档对旧内容静默生效。理由是兼容路径不扩张新特性，避免两套界面继续分叉。

### 1.4 Live2D GPU 贴图缓存以内存地址为键

- 现象：`Pixels::sources` 用 `(image.as_ptr(), width, height)` 作为缓存键。这依赖「贴图数组在缓存存活期内地址不变、且地址不被复用」这一隐含约定。模型重载/热更后释放的 `RgbaImage` 可能让新图落在同一地址，旧 GPU 纹理就会被错误复用（串图）；该约定也没有任何测试保护。
- 原因：早期为了跨帧复用贴图，直接借用了切片地址作身份。
- 修复：
  - `render::ModelDraw` 增加 `model: u64`——模型在本进程内的稳定身份。
  - `live2d::ModelAsset` 增加 `id`，由进程内单调计数器分配；构造 `ModelDraw` 时传入。
  - D3D11 缓存改为 `BTreeMap<(u64, usize), CachedSource>`，键为「模型身份 + 贴图序号」；记录尺寸与字节数，尺寸变化才重建；预算改为先算总量再记账，失败不留下半更新的计数。
  - 新增单测：同一身份重复合成复用纹素，另一身份即使贴图地址相同也不得共用，字节计数正确。
- 附带约束：API 第 20.5 节写明后续 Vulkan/Metal 后端**不得**用贴图内存地址作缓存键，必须按 `(model, 贴图序号)` 索引。
- 兼容性：`ModelDraw` 是 Rust 侧平台边界类型，新增公开字段会让外部 `PixelBackend` 实现与测试构造需要补该字段；仓库内唯一实现（`Pixels`）与测试桩（`tests/v07_gpu.rs`）已同步。

### 4.4 环境备注

首次回归在受限 shell（DSH 沙箱令牌）下运行时，`tests/v06.rs::real_mp4_…` 与 `tests/v07_content.rs::real_demo_…` 因 Media Foundation 返回 `0x80070005` 失败。用独立最小 P/Invoke 探针复现了同一错误（`MFCreateSourceReaderFromURL` 对任意路径均拒绝，`SHCreateStreamOnFileEx` 与普通文件读取正常），确认是沙箱令牌限制而非代码问题；切到普通权限后全部通过。后续在受限环境跑测试时，只要看到这两项（以及 `--check` 在视频资源处报拒绝访问），应先怀疑运行环境而不是内容或解码器。

## 5. 未覆盖与边界

- 兼容界面只做了「启动 → 渲染 → 关闭」的真实窗口冒烟；按钮级行为由 `tests/legacy_ui.rs` 在意图层覆盖，未在 GUI 里逐个点击验证（保存/读档的完整 IO 仍走 XML UI 既有验收）。
- 本次不涉及音频设备、主观听感、多显卡、高 DPI 或驱动设备丢失；这些延续既有未验收边界。
- 真实 Cubism 用例默认忽略，本轮未重新运行（需本地 SDK 路径）。
- 未新增 Vulkan/Metal 实现；第 20.5 节的新约束只是对后续后端的写法要求。
- demo 少一个文件会改变发布包字节数；README 中的「约 27.7MB / 约 21.6MB」仍是量级描述，精确值以 `kakera-pack` 输出为准。
