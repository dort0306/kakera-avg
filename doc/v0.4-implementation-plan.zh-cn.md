# v0.4 落地策略：由 XML 与 JavaScript 定义界面

制定日期：2026-10-23。本文先于 v0.4 功能代码落盘。基线为 v0.3.1 的 QuickJS 剧情回调、ContentSource、严格存档和逐字呈现；保留此前契约与文档。

## 1. 交付目标和边界

游戏作者无需编写或重新编译 Rust，即可定义游戏 HUD、自有存档/读档页、覆盖确认、设置、历史、CG 画廊、图片查看页，以及使用现有能力组合的新页面。XML 决定显示结构与样式，JS 决定点击/数值变化后的行为；Rust 提供绘制和受约束的宿主能力。

以图片素材为主，不实现 CSS、DOM、复杂约束布局、富文本、编辑器、动画系统、任意原生扩展或插件框架。首版为 16:9 设计坐标、绝对位置、父节点相对位置与裁剪，支持等比缩放、基本文字/颜色及可滚动的重复列表。扩展来自新增 XML 页面、通用节点、局部状态和 on.ui 回调，不要求把每个游戏的菜单写进 Rust。

## 2. 文件及兼容

story schema 5 在 schema 4 上增加必需的 `<interface src="ui.xml" />`，JS 文件仍由 scripts 清单引用；界面交互可以独立放 scripts/ui.js。ui.xml schema 1 声明设计宽高、初始屏幕、UI 变量、CG 清单与 screens。图像使用故事共享资源表的 image ID，所有文件经 ContentSource 启动时读取并缓存，修改后重启生效。

schema 1–4 继续使用原界面作为兼容入口；schema 5 必须完整提供 XML 界面，不能缺失时悄悄回退。错误提示保留引擎最小故障窗口，防止自定义界面失败后无法读到错误；正常游戏菜单不依赖这些窗口。UI-only 更新不改变剧情路由语义，样例 content-version 仍为 3，旧合法 schema 3 剧情槽可恢复。

## 3. XML 节点与基础样式

```xml
<ui schema="1" width="1280" height="720" initial="hud">
  <variables><int id="pendingSlot" initial="1" min="1" max="6" /></variables>
  <gallery><cg id="room" image="bg.room" title="午后房间" unlocked="true" /></gallery>
  <screen id="hud" modal="false" pause="false">
    <scene id="scene" x="0" y="0" width="1280" height="720" />
    <panel id="dialogue" x="36" y="505" width="1208" height="180" image="ui.dialogue">
      <label id="speaker" x="28" y="14" width="1000" height="30" bind="game.speaker" color="#F0CA89" />
      <label id="line" x="28" y="50" width="1146" height="80" bind="game.text" font-size="26" />
    </panel>
    <button id="openSave" x="896" y="20" width="88" height="38" text="保存" event="open-save" />
  </screen>
</ui>
```

节点为 scene、panel、image、label、button、slider、toggle、repeat。每个节点 ID 在文档内唯一；子坐标相对父节点。panel/repeat 可以有子节点，其他节点不允许子节点。XML 顺序决定绘制层次，后面的交互优先。基础属性为 x/y/width/height、#RRGGBB/#RRGGBBAA、font-size、radius，以及图片 stretch/contain/cover。按钮可配置普通/悬停/禁用图；无图时使用简单填色。

repeat 指定 source、columns、item-width/item-height、gap；其矩形为滚动视口，模板子节点相对每个 item。首版不支持 repeat 嵌套，避免 item 作用域歧义。节点最多 1024、深度最多 8；屏幕/图片/事件/绑定缺失、未知属性、重复 ID、非有限或非法尺寸都带 ui.xml 行列报错。

## 4. 只读绑定与数据集

bind、image-bind、visible、enabled、value 仅接受受支持的路径，不接受内联 JS 表达式；布尔可用 true/false 或 not:路径。所有求值均为只读查表，不在绘制执行脚本。

| 来源 | 数据 |
| --- | --- |
| game | frameId、speaker、text、complete、canAdvance、ended、noChoices、continueText |
| settings | text_speed、muted、bgm_volume、voice_volume、se_volume |
| ui | 作者声明的 int/bool/string 局部变量 |
| repeat choices | 可用选项 id、text；仅逐字完成后开放 |
| repeat slots | slot、title、preview、exists、loadable；六个槽位，坏档保留原因 |
| repeat history | id、speaker、text、choice；保留访问顺序 |
| repeat gallery | id、title、image、unlocked；来自 XML CG 清单与独立解锁记录 |
| repeat variables | id、label、value；用于自有状态页 |

game.text 的文字按完整句子布局、只显示可见前缀，保持逐字换行稳定；超出节点区域时有开发提示，不能静默裁掉正式台词。数据集在提交/菜单刷新边界准备并缓存，文字进度和完成状态可逐帧更新，不读盘。

## 5. JS UI 回调与宿主命令

```javascript
on.ui("open-save", ctx => ctx.open("save"));
on.ui("save-slot", ctx => {
  if (ctx.item.exists) {
    ctx.setUi("pendingSlot", ctx.item.slot);
    ctx.open("confirm-save");
  } else ctx.save(ctx.item.slot);
});
on.ui("confirm-save", ctx => { ctx.save(Number(ctx.ui.pendingSlot), true); ctx.close(); });
on.ui("text-speed", ctx => ctx.setting("text_speed", ctx.value));
on.ui("choose", ctx => ctx.choose(ctx.item.id));
```

ctx 中 game、vars、ui、settings、item、value 均为本事件的只读输入；vars 与 ui 的 int 继续精确使用 BigInt。按钮 value 为 null，slider 为 Number、toggle 为 boolean。回调同步收集命令，默认返回 undefined；Promise/异步任务仍拒绝。每个事件最多 32 条命令。

能力为 open/close、setUi、save/load/importLegacy、restart/advance/choose、setting、unlock、message。事件先验证整个命令列表，再执行至多一种有 IO/剧情副作用的操作；设置批量修改聚合为一次 settings.json 原子写入，多个 unlock 聚合为一次 profile.json 写入，不混合不同 IO 类型。所有局部 UI 更新先在副本完成校验，不能先切页再发现槽号非法。

save 默认不覆盖已有文件；覆盖必须显式传 true，样例由作者 XML/JS 确认页完成。load 仍验证完整历史；advance/choose 继续经过逐字门控和纯控制器，不提供任意 jump/setFrame 绕过入口。JS 不接触路径、文件句柄、纹理或可变 Session。

## 6. 页面、暂停及交互仲裁

屏幕声明 modal 与 pause。open 非模态页时切换根页面；open 模态页时入栈，close 返回上一页，最大 8 层，不允许重复入栈或关闭唯一根页。画面可以显示下层页面，但仅顶层接收输入。任一 pause 页、错误提示或失焦暂停逐字；恢复不补算时间。空间键仅在无模态菜单、未暂停的游戏页生效。

单次 egui 更新只提交一个 UI 事件或剧情意图。图片按钮、滚动列表和弹出确认不能穿透点击底层剧情。绘制返回事件，App 调 JS 与执行 IO；不把文件保存、脚本或场景推进放进绘制函数。

## 7. CG 与持久状态

CG 清单声明 id、image、title、初始 unlocked。解锁保存在独立 profile.json，按 story_id 隔离，schema 1 严格校验、未知 CG 拒绝；坏文件回退初值并提示，失败写入保留旧文件。局部 UI 变量和页面栈不进入剧情槽，重启恢复初值；设置仍是独立 settings.json。

提供可选 `on.ui("game.enter", callback)` 生命周期事件，在新 Session 提交前，以候选场景/变量构建只读上下文，可收集 unlock、setUi、message；不允许在该事件再次推进、读档或切换设置。成功读档/重开也经过这一入口。其计划或 profile 写入失败时保留旧 Session 与音频。历史验证重放不触发生命周期事件，避免读历史时重复执行宿主副作用。

样例将房间 CG 设为初始可看，凛 CG 在 accept 结尾解锁；查看大图由自有页面及 UI 局部状态完成。关闭应用、重启、重开剧情或读旧槽均不会撤销已获得 CG。

## 8. 模块边界与扩展

- model/controller 保持剧情领域与纯逻辑接口；不加入 egui、QuickJS 或 UI 导航对象。
- interface 数据、解析、绑定/命令验证与只读渲染分开，使用普通类型。新的画廊/存读档页面由 XML 模板定义，不专门写每一页 Rust 窗口。
- script 增加独立 UI 事件注册表，沿用隔离、预算、错误栈；剧情注册与返回格式不变，UI 命令不能混入剧情历史。
- App 负责准备只读数据、缓存、候选状态提交及 IO；assets 仍只在启动解码/上传 UI 图片。
- 新宿主能力必须添加明确 Rust 命令及校验。只新增页面、皮肤、布局、已有能力的交互和局部 UI 状态无需改 Rust。资源包继续通过 ContentSource 接入。

## 9. 实施顺序与验收

①本文与 XML/JS 契约；②UI 类型、严格解析、绑定、命令计划；③UI QuickJS 注册及隔离；④只读渲染与 App 提交/缓存；⑤独立 CG 进度、图片样例与完整菜单；⑥自动回归、窗口验证、发布及文档。

自动检查覆盖严格 XML/位置、绑定类型/资源/回调引用、模板和屏幕栈、非法命令整批回滚、坏槽/覆盖确认、设置及 CG 原子持久化、生命周期重放隔离、无设备音频回归和全部旧 schema。实际窗口检查图片皮肤、中文、稳定换行/16:9、补全/推进、菜单暂停/遮挡、自定义槽位覆盖确认、完全退出重启恢复位置/变量/历史、设置持久化、CG 锁定/解锁/大图/跨重启持久化。

完成后运行 fmt、Clippy -D warnings、完整 locked 测试、--check、release 与无 flow.xml 的便携包跨工作目录校验；readme、AGENTS 与实际验证记录同步。音频听感、设备热拔插和其他系统单独报告，不从逻辑测试推断。
