# v0.8.2 点九图、图集区域与发布场景 ID

日期：2026-10-25，先于功能代码。沿用 story 8 / UI 3 / save 8 与 KPAK 1/2；本版为新增语法/能力，应用版本升为 0.8.2。

## 实现决策

- 新增资源及 UI 专用 `<nine-patch>` 标签，直接读取 Android Studio 保存的源 `.9.png`：一像素边框的上/左定义可伸缩区，下/右定义内容区，加载时解析并去掉边框，绘制共享一张纹理。支持多伸缩段、保持角/固定段、内容 padding 和小尺寸收缩，不伪装成整图拉伸。不接受 APK 内已经编译/去边框的二进制 NinePatch。
- 普通 image（以及 panel/button 图片皮肤）新增 `region="x,y,width,height"`，原点为源图左上，单位为原始像素；`region-bind="ui.xxx"` 绑定 UI 字符串，脚本用现有 ctx.setUi 切换。只改变 UV 和源宽高，不裁剪/复制/重新上传纹理。region 与 region-bind 互斥，整批校验格式/类型/界限后提交；点九图不接受区域裁剪。
- 解析元数据/UV/分段绘制是现有 XML/JS 未具备的宿主能力，需要扩展 Rust；实际效果组合仍只在 XML/JS，图集切换复用现有命令，不增加任意路径/IO 或 tick。
- 用户已确认采用稳定作者别名。frame 的 id 可省略，省略时使用非空唯一 name 供入口/JS 注册和目标引用；工程使用该稳定名字作为临时内部 ID。打包只在候选中为缺省 id 的 frame 生成随机 UUID v4，保留 name 映射；源 XML/JS 不改写，不引入隐式顺序剧情。
- 显式 ID 保持不变。保存/重放使用实际 ID；game.frameId/ctx.frameId 对具名场景暴露作者名字。独立重新打包的随机 ID 会改变槽位契约，需提升 content-version；要跨构建稳定存档应显式固定 ID。无 id 又无 name、别名与其他 ID/别名冲突均报文件位置错误。
- KPAK 1/2 都先将生成后的候选独立加载验证，源指纹不变且全部成功后才原子写出；失败保留旧包。没有缺省 ID 的工程继续确定性打包。

## 验证与交付

点九覆盖合法/坏边框、padding、多段、固定边角、小尺寸和高 DPI 分段；图集覆盖区域边界、UV/contain/cover/镜像旋转、绑定动态切换与失败回滚、共享纹理及 repeat。UUID 覆盖两种包、名字/显式 ID 路由、条件/历史/存档、自循环、冲突/坏输入/源不改写/失败保留。

执行 fmt、Clippy、完整测试、demo 与发布包 --check，并实际检查 GPU/CPU 窗口中文、点九背景及 JS 图集切换；未测 GUI/设备听感等单列。更新 API、README、指南、AGENTS、发布脚本和验收，保留此前文档，不提交/推送 Git。

Android 源格式依据：[官方 NinePatch 说明](https://developer.android.com/develop/ui/views/graphics/drawables#nine-patch)、[Draw 9-patch 工具](https://developer.android.com/studio/write/draw9patch)。采用源 PNG 边框标记格式，不承诺 Android APK 编译资源兼容。
