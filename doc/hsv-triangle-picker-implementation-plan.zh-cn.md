# 工作包 C：三角 HSV 颜色选择器与玩家配色落地方案

起草日期：2026-10-29；版本定稿：2026-10-30。本文保留原落地设计，功能及后续修复统一归入 **v0.10.0**。下文现状、拟定接口和分工描述对应起草阶段；当前支持的接口与限制以 [API](xml-js-api.zh-cn.md) 为准，实际通过项和未验项见 [验收记录](ui-extensibility-validation.zh-cn.md) 与 [独立复验](ui-extensibility-independent-review.zh-cn.md)。

## 1. 需求拆分与必要扩展

要求是真正的“色相环＋三角形 SV 区域”，不是把矩形 SV 面板旋转一下，也不是仅提供三个数值滑杆。控件须能输出颜色，作者可用现有 on.ui/ctx.setUi 实现预览和取消，玩家可明确应用并在重启后保留。

当前已有静态颜色、label/图片/按钮、UI string 和事务，但没有 ColorPicker Kind、连续三角命中、color-bind 或任意配色偏好。静态图片加按钮无法合理表达连续 SV/HSV 选择，所以扩展 Rust 的仅是控件几何/输入、解析后的颜色绑定及受限偏好命令。布局、设置页、提示、确认、预览范围和按钮仍放 XML/JS。

不能假定现有 egui 颜色控件直接满足需求：锁定的 egui/ecolor 0.33.3 使用二维面板；本地 Hsva 涉及线性通道，HsvaGamma 也不能仅凭名字就当作本文的 sRGB HSV。可以复用经过验证的数学/绘制基础，不依赖其未公开私有组件，不为此升级依赖或复制另一套 GUI。

## 2. 第一版完整范围

| 阶段 | 必交付 | 不包括 |
| --- | --- | --- |
| C1 控件 | 色相环、固定方向 SV 三角、选择标记、预览、可选 alpha 条、指针/键盘编辑和事件 | 屏幕吸色、HDR、ICC、任意纹理输入、系统原生取色窗口 |
| C2 应用预览 | UI string 为颜色值，color-bind 从已验证缓存绘制；JS 决定如何响应 | 直接改剧情 Frame、纹理像素、全局 egui 主题或逐帧 JS |
| C3 玩家偏好 | 作者声明有限配色槽位、草稿/应用/取消/恢复默认、独立原子持久化 | 任意设置键、任意文件/路径、跨文件伪原子保存 |

三个阶段都要交付才算用户配色需求完整完成；可以逐阶段评审，不能做完色盘图就宣称已支持玩家配色。

## 3. 颜色值契约

- 对外值为未预乘的 sRGB RGBA 字节串，规范输出 **#RRGGBBAA，九个 ASCII 字符、十六进制大写**。不新增 VariableValue 变体，不把解释器对象放进 UI/Model。
- 作者静态初值和动态绑定可输入现有 #RRGGBB/#RRGGBBAA（大小写均可）；六位明确补 alpha=FF，准备缓存时规范化，不改写作者源文件。非法、空值、路径、CSS 名称、浮点对象/数组一律拒绝，不默认为黑色。
- HSV 运算明确针对编码后的 sRGB 通道（字节除以 255），H∈[0,360)，S/V/A∈[0,1]；不是线性光 HSV 或 HSL。360 度归零，负数/NaN/无穷等不是合法外部输入。
- 最后写字符串时对每通道按 round(clamp(x,0,1)×255) 量化；最多允许数学往返一字节误差。不要把值经过预乘 Color32 再当存储，alpha=0 的非零 RGB 也必须保留。
- HSV 浮点、保留色相、拖拽进度和指针不写偏好/存档。普通 UI string 按现有契约属于 UI 局部值；隐藏交接若保存它仍只是普通 UI 变量，不能把它当成已提交玩家配色或保存控件指针。
- 不把浮点 H/S/V 直接传给当前仅接受安全整数/BigInt 的 ctx.setUi 数值通路；事件与草稿使用规范颜色字符串，浮点仅留在宿主呈现状态。

## 4. 拟新增 XML 控件

节点名冻结为 color-picker。属性表是接口设计，不是现行解析器已接受的写法：

| 属性 | 规则 |
| --- | --- |
| id/x/y/width/height | 沿用当前全局控件 ID、逻辑舞台坐标和尺寸校验 |
| value | 必需，且仅允许已声明的 ui.<string>；不是只读 colors 槽位、game/vars 或 repeat item |
| event | 必需，已注册普通 on.ui 事件；拖动只产生候选值，不直接改变变量 |
| alpha | 可选 bool，默认 true；false 隐藏 alpha 编辑条但保留输入颜色原有 alpha，不强制改成 FF |
| visible/enabled | 现有 bool 绑定语义；不可见无交互，禁用不改变值、但阻挡舞台背景输入 |

第一版不是容器，不接受子节点、图片/region、route、未知属性；禁止放在 repeat 中，避免按列表下标复用手势缓存。嵌套普通 panel 可以。建议尺寸 256×320；内部下方预览/alpha 区分别预留 32/64 个逻辑单位，色环区域直径 D=min(width,height−预留)，要求 D≥128。超小声明在加载/候选阶段拒绝，不在绘制里偷偷扩出控件矩形。

完整 UI 至多八个 color-picker，现有 1024 节点/8 层、UI XML 和 include 预算不变。即使全部同时可见也有明确几何上限，不依赖每帧偷偷减控件数量。

## 5. 事件与事务

事件返回 ctx.value=规范 RGBA 字符串，ctx.item 沿用普通控件空项；控件本身不调用 ctx.setUi。作者在已注册事件里接受、修改或拒绝候选，并通过 ctx.setUi 改 value 绑定变量，得到与 slider/toggle 相同的单事件业务模型。

初始显示、外部 setUi、打开页面、加载/恢复和布局重排都不自动回发“值已改变”事件，避免回调回环。一个 App 更新最多一个业务事件；同一拖拽本帧的多个指针移动合并为最新位置，不能按原生事件数量运行无限 JS。

控件可维护几何/焦点/抓取等呈现状态，业务颜色必须经 App 事务提交。渲染只读已提交颜色缓存与交互快照，返回有界候选颜色和交互变化；不在绘制中跑脚本、写文件、解码图片、创建纹理。App 检查候选页面/定义代数与当前绑定值，失效则丢弃。

JS 报错、绑定颜色非法或批次内其他命令失败时，不提交颜色/页面/IO；显示回到旧颜色，结束本次抓取并等待重新按下，避免错误回调每帧刷屏。若作者将候选修正为另一合法颜色，下一帧标记按最终提交值校正，不坚持显示未被接受的手势值。

## 6. 精确几何和颜色数学

色环围绕同心三角形。H 顶点为当前色相的纯色，W 顶点为白，B 顶点为黑；三角方向固定，不随色相旋转。以三角中心为原点：H 在正上，W 在左下，B 在右下，三个顶点同一外接圆上。

任意三角内点的重心权重为 wH/wW/wB，均非负且和为 1：

- V = wH+wW；当 V>ε 时 S=wH/V。
- 反向定位：wH=V×S，wW=V×(1−S)，wB=1−V。
- 编码 sRGB 颜色为 wH×pureHue(H)+wW×white+wB×black；绘制插值与选中值必须遵循同一空间，不做未经证明的双重 gamma 转换。
- 黑点 V=0 时 S 不可从 RGB 唯一恢复；保留同一控件最近的有效 S，首次显示黑色时取 0。灰色/白色/黑色保留最近有效 H，首次灰色初始化 H=0。

色环最上方为红色 H=0，顺时针增大，60/120/180/240/300 度依次为黄/绿/青/蓝/品红。色相环命中只按半径区间，三角命中用重心坐标。拖出三角时求**欧氏最近边/顶点投影**，不是随意把负权重置零再归一；后者通常不是最近点。

每次按下先决定环/三角/alpha 子区域，在本次抓取结束前锁定子区域，不能拖过边界就突然换成另一编辑方式。环拖出半径范围仍按当前位置角度调 H；三角拖出按最近点；alpha 拖出按条端点夹取。输入非有限坐标时丢弃该候选，不把 NaN 传播到颜色/mesh。

缓存至少记录最近有效 H/S、浮点手势值、最后确认 RGBA、抓取子区及作用域代数。H 在灰色上变化时 RGB 可能不变，可以只更新呈现缓存而不运行 JS；再次提高饱和度必须得到刚选的 H。不要每帧重新从灰色字符串求 H=0，或把自己的 setUi 回显当外部重置。

## 7. 输入所有权、焦点与清理

接入 B 的输入所有权，不再复制另一套 Ctrl/Space 判断。组件获得指针抓取或键盘编辑焦点时，相关输入不再传给舞台背景、剧情快进、推进或 UI 演出跳过。按下必须始于有效可见控件，黑边/遮挡/底层页/禁用区不能开始编辑；控件整个矩形应作为 UI 阻挡区域登记。

键盘用 Tab/Shift+Tab 在环、三角、alpha 与前后 UI 控件间顺序移动，alpha=false 时跳过该子区，不把焦点困在色盘。环左右调整 H（默认 1 度，Shift 为 10 度）；三角左右调整 S、上下调整 V（默认 0.01，Shift 为 0.1）；alpha 左右同级调整并夹在 [0,1]。控件拥有编辑焦点期间阻挡普通剧情键，即使 Space 等键不用于调色也不能向后穿透。只提供可读 HEX 显示，不顺带实现新的通用文本输入框。按钮焦点确认与普通前进仍遵守单意图规则。

Escape 结束本次抓取/编辑，不撤销已接受的 UI 草稿；设置页“取消”负责放弃整份草稿。失焦、页面关闭/顶层变化、热更、读档/重开、定义替换、绑定目标改变、开始快捷键捕获都取消抓取，清陈旧候选，恢复后须重新按下。不同页面/控件不可共享一个全局 lastHue。

## 8. 拟新增 color-bind 与缓存

仅有 picker 输出还不能让玩家配置现有静态颜色，故增加受限 color-bind，复用 ctx.setUi 而非新的任意绘图命令。

| 项目 | 拟定规则 |
| --- | --- |
| 绑定源 | ui.<string> 或 colors.<已声明配色槽 ID> |
| 可用节点 | panel/image/nine-patch/label/button/toggle；只作用于原有明确的颜色/tint 语义 |
| 互斥 | color 与 color-bind 二选一；未配置者沿用当前默认 |
| 不支持 | scene 整体着色、repeat 容器着色、slider 全局样式、任意 JS 表达式/路径/原始像素 |
| button | 与当前 color 一样控制背景/图片 tint，默认白色文字不被改成同一颜色；有色文字可用空按钮+label 组合 |
| nine-patch | 必须明确将缓存色作用到所有分段顶点，不能只解析属性却不绘制 tint |

准备阶段解析每个绑定并存拥有的 RGBA 缓存，保留声明的 UI 源文件/位置。初始值、隐藏节点、setUi 最终批次、偏好变化和热更候选都验证；坏值整批拒绝。绘制不可每帧解析十六进制，也不重建图片/点九纹理或滤镜缓存。

## 9. 作者配色槽与玩家持久化

为避免破坏 settings.json 的完整字段契约，另建有限的 UI 调色偏好。

### 声明与显示

拟增加 UI 根组 palette，包含 color 声明，必需 id/initial。槽位 ID 使用 [a-z][a-z0-9_]{0,63}，不含点，最多 32 个；整个 UI 装配后同命名空间全局唯一。initial 为合法颜色，独立于剧情变量/CG ID；可引用 colors.dialogue_background 等只读绑定。根组也允许在 include 子文件声明，深度优先合并、前向引用和原位置诊断沿用现有机制。

编辑页打开时，从当前已提交 colors 槽位复制到 ui.<draft>。picker 只编辑草稿；预览区用 color-bind 指向草稿，正式 HUD 指向 colors 槽位。取消关闭页面，不修改已提交配色；重开编辑页重新从已提交值初始化。不要把全局 HUD 直接绑到任意遗留草稿而称其为已保存配色。

### 拟定命令与文件

| 接口 | 行为 |
| --- | --- |
| ctx.colors | 普通 UI 的只读已提交配色快照，键只能是声明槽位 |
| ctx.colorPreference(slot, rgbaOrNull) | 保存一个槽位覆盖；null 删除该覆盖、恢复作者默认，不删除文件 |
| ctx.resetColors() | 单独恢复全部作者默认，原子写空覆盖表；不可与逐项修改混在同一批 |

固定 ui-colors.json，完整顶层字段为 schema_version=1、story_id、overrides。overrides **按格式设计就是稀疏表**，缺某槽位明确使用作者默认，不是给旧字段补值；文件本身缺顶层字段仍拒绝。键必须为当前声明槽位，值必须是规范九字符大写 RGBA。大小 16KiB；未知字段/槽位、重复 JSON 键、坏颜色、错 story/schema 或超限全部拒绝。

无文件使用作者默认；坏文件保留并提示一次后使用默认，不自动重写。以后新增槽位沿用其作者默认；删除/改名导致旧覆盖含未知 ID 时，明确提示并按坏文件处理，不做别名迁移。热更候选中删除仍被覆盖的槽位，先报告不兼容并保留旧状态，不能静默丢玩家配色；作者可先恢复默认或重启处理。

colorPreference/reset 属于同一种持久 Operation::Colors；仅普通 on.ui，生命周期与活动交接中禁止写。整批先验证槽位、全部局部变量/color-bind、最终 UI 状态和资源，再检查大小并同目录原子写，成功后一次替换偏好及缓存。多槽位可以聚合，但仍受 32 命令预算；重复修改同一槽位拒绝。不得与快捷键、settings/profile、剧情/存读档/退出混写。

写失败保持旧文件/已提交配色/UI，应用页草稿必须可重试。Profile、普通/自动/隐藏剧情槽、重开都不能回滚 overrides。隐藏交接只按原契约保存普通 UI 字符串；colors 只读快照始终来自当前独立偏好，不从隐藏变量猜出或写回配色。ui-colors.json 和大小写变体排除监控/两种包/显式附加与发布复制。

## 10. 绘制与预算

优先使用已有 egui mesh/白色纹理点绘制环、三角、alpha 棋盘格与标记；不每帧生成位图、上传渐变纹理或读回 GPU。色环采用固定且可复核的分段数（建议 192、必须包含六个色相边界），三角按前述 sRGB 插值；采用其他细分方案时须以像素和数学测试证明一致。

每控件最多 4096 顶点/8192 三角形，八个节点总预算有界；已有 UI primitive、裁剪和尺寸上限仍生效。alpha 仅预览/编辑颜色透明度，环/三角本身保持可辨认，不因当前 A=0 消失。指示标记须有黑白双边等高对比，不能与所选颜色融为一体。

Windows D3D11 与 CPU 像素模式共用原生 UI mesh 通路；这里不新增专用 HLSL，也不把 UI 色盘说成 Live2D CPU 合成能力。若发现现有 shader 的颜色空间处理与数学不符，先定位转换边界再修复，不允许在整张游戏画面上随意加 gamma 校正。

## 11. 修改地图与实施顺序

1. 新纯颜色/几何模块：严格 HEX、sRGB HSV、重心、最近点、标记和量化；不依赖 IO/Model/GPU。
2. interface.rs：Kind/属性/value 类型、尺寸/数量/非 repeat 限制、palette 声明、color-bind 与源位置；interface/source.rs 同时扩展根组装配，保持 include 预算和两种包合并。
3. host/data/custom/bridge：颜色解析缓存、只读 colors、受限命令、文件加载/保存和回滚。复用现有事务，不建立另一套主题插件/全局服务。
4. render 与 App 交互状态：mesh、标记、指针/键盘提案、B 输入所有权、一次事件及陈旧候选清理。特殊的灰色保色相也只在呈现状态。
5. demo XML/JS：对话面板/文字两个槽位，编辑页预览、应用/取消/默认，普通确认页可复用；不改剧情路由/变量。
6. 包/监控排除、API/README/指南与真实窗口验收。控件/配色偏好不进 SaveStore 剧情快照序列化。

落地后按阶段更新文档状态，记录真正支持的颜色空间、键盘操作、尺寸和预算；不能以“调用了一个 egui 取色器”作为三角控件完成证据。
