# v0.10.1 国际化准备：落地总方案

日期：2026-10-30。状态：**已接入 v0.10.1 实现**。本文保留设计依据与实施前源码事实，现行接口见 API 第 36 节，执行证据和未验范围见 [实际验收记录](v0.10.1-validation.zh-cn.md)。

## 1. 已确认的范围

用户确认：**玩家可以分别选择文本语言和语音语言**。本版包含两个必须分别交付的工作包：

| 工作包 | 落地方案 | 验收方案 |
| --- | --- | --- |
| A 宿主内部提示接入 fluent-rs | [宿主方案](engine-i18n-implementation-plan.zh-cn.md) | [宿主验收](engine-i18n-validation-plan.zh-cn.md) |
| B 作者可选的游戏文本/语音国际化 | [内容方案](game-localization-implementation-plan.zh-cn.md) | [内容验收](game-localization-validation-plan.zh-cn.md) |

A 仅把现有中文移入 Fluent 中文资源，提供后续增加语言的结构；不制作英文、日文等宿主翻译。B 由开发者声明支持语言和默认语言，默认不开启。每个通道按玩家明确选择优先，否则按系统首选语言列表命中；未命中则回到开发者为该通道声明的默认语言。两者不能混成“一个语言同时决定一切”。

宿主提示框架始终可用，不受游戏开关影响；游戏未启用国际化时仍使用原文字/语音。游戏选择其他文本语言也不会凭空产生其他语言的宿主提示；A 本版只有 zh-CN，因此宿主仍显示中文。

## 2. v0.10.0 实施前代码事实与宿主扩展依据

- `Cargo.toml` 当前没有 Fluent、语言标识或系统语言依赖。`src/main.rs`/`launch_console.rs`、App、加载/存档/资源/调试等层均有中文诊断，不能只替换一个提示窗口。
- `Frame.text`、`Choice.text`、人物显示名都是拥有的 String；`AudioCue.voice` 当前是音频资源 ID。`interface/data.rs` 构建剧情、历史、槽位等绑定；`assets.rs` 检查字形；`runtime::Bundle::load` 准备完整候选。
- `audio::AudioPlan::enter` 会替换语音及音效，连续 BGM 可继续；不能通过“切换语言时再调用 enter”实现，否则会重播无关声音。
- `settings.json` 是完整、严格的当前结构，不接受默补字段。语言偏好另存固定文件，沿用快捷键/配色的边界，不改旧设置字段。
- 现有 XML/JS 可以编写选择页、列表和按钮，但不能完成系统语言探测、FTL 校验/解析、全局语言资源选择及音频候选准备。因此新增这些 Rust 宿主能力；作者交互仍用 XML/JS，不开放任意文件、路径或逐帧脚本。

以上是对当前源码的核对，不是 v0.10.1 已完成的证据。接手前遵守 AGENTS.md 的历史资料顺序，并读 v0.10.0 的 [路线图](ui-extensibility-roadmap.zh-cn.md)、[验收](ui-extensibility-validation.zh-cn.md)、[输入修复](ui-extensibility-independent-review.zh-cn.md)。

## 3. 共同决策

1. Fluent 解释器、系统语言、字体、音频、文件 IO 均不进入 Model/Controller。领域错误使用稳定标识与拥有的参数；展示层负责本地化。历史和控制流只依赖稳定 ID、变量与路由，不能依赖翻译结果。
2. 宿主中文 FTL 编译进播放器；游戏 FTL/语言清单全部经 ContentSource 读取，禁止游戏覆盖宿主词条。两个资源域、版本、回退策略分别校验。
3. 一个 FluentBundle 对应一个语言目录。消息缺失回退由应用明确完成；不能把 bundle 的 locales 列表当成自动合并其他语言消息。
4. 不引入异步 runtime、ECS、消息总线、在线翻译、下载语言包或插件。候选准备阶段解析/格式化，绘制只读拥有的缓存；QuickJS 不拥有 Fluent 解释器。
5. 游戏语言匹配冻结为规范化后**精确匹配**。不隐式把 zh-TW 配成 zh-CN，不猜测脚本、地区或“最接近”的语言；开发者可明确声明需要的标识。详见 B 的决策表。
6. 生产宿主资源本版只有中文。测试可用临时伪语言/哨兵字符串证明框架分离和回退，但不能把测试假资源装进正式宿主包或宣称已完成其他语言翻译。
7. 拟保留 story 8/UI 3/save 9/profile 1/read 1、KPAK 1/2。扩展必须严格解析；未开启的同一契约继续接受现有字面量内容，不创建旧格式兼容解析器。新增游戏语言清单 schema 1、玩家语言偏好 schema 1；不更改隐藏槽格式。
8. 实现完成才把应用及打包默认版本升至 0.10.1。纯添加翻译、语言覆盖或开关不改变剧情 ID/变量/路由时，不自动提升 content-version；如同时改变这些档案契约，另行提升并明确旧档拒绝。

## 4. 先后顺序与集成边界

先做稳定宿主诊断 ID/中文资源和无 IO 的格式化门面，再做纯语言选择函数及清单加载；接入剧情/UI 文本缓存后接语音解析与语言事务，最后增加 XML/JS 设置页、打包/热更/跨进程验证。

A 应先让无游戏、坏包、CLI、加载失败也能给出本地化诊断；不能依赖成功载入 B。B 需要 A 的宿主提示，不能把游戏 FTL 自身的错误交回坏游戏 FTL 格式化。

共享修改点是 loader/runtime、interface/source/data/host、App/custom/lifecycle、save/包排除和文档。接手者按顺序合并，不能各自引入另一套语言全局单例。测试结果分为纯单元/事务集成/真实 GUI/设备流/听感，不能互相代替。

## 5. 当前非目标与限制

本版不承诺 RTL 布局、复杂脚本塑形、竖排、逐语言图片/Live2D/视频、视频多音轨、不同语言独立剧情路由或按语言重新获得已读资格。FTL 插值的方向隔离符不等于引擎已支持完整 RTL。语音国际化仅覆盖剧情 `AudioCue.voice`，BGM、SE、UI 角色音效和 sequence 视频音轨保持原契约。

不承诺将第三方库、OS 或驱动返回的自由文本翻译成中文；宿主给它们加本地化上下文并保留原始原因。资源/帧/变量 ID、路径、协议码和键位 token 不翻译。
