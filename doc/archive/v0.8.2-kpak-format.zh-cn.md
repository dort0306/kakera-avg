# KPAK 1 / KPAK 2 资源包规范

适用版本：v0.8.1。实现来源：src/package.rs、src/package/streaming.rs、src/package/staged.rs。所有数字均为 little-endian，路径为 UTF-8。

用户明确要求保留小包 KPAK 1，同时新增流式 KPAK 2。播放器按 magic 后的 version 自动选择，未知版本/flags 拒绝，不回退目录。默认生成 2；--format 1 显式生成 1。该兼容仅限包容器，不恢复旧 story/UI/save；两种包内都须为当前 story 8/UI 3，存档为 save 8。

两者没有加密、时间戳或签名。SHA-256 仅检测损坏，不认证来源。KPAK 1 的既有字节格式和上限不变，KPAK 2 独立定义如下。

## KPAK 1（小包，保持兼容）

规范来源：src/package.rs。版本 1 的字节格式保持不变，与 story/UI/save schema 独立。无加密、无时间戳、无签名；摘要只检查损坏。

### 外层

固定 64 字节头，所有数字 little-endian。偏移 0 的八字节 magic 为 `4B 50 41 4B 0D 0A 1A 00`；偏移 8 为 u32 version=1，12 为 u32 flags=0，16 为 u64 compressed_length，24 为 u64 payload_length，32…63 为 SHA-256(payload)。偏移 64 开始恰好一帧 Zstandard 压缩数据，文件长度必须等于 64+compressed_length。

### Payload

1. u32 文件数。
2. 每个文件：u16 路径 UTF-8 字节长、路径字节、u32 内容块索引。
3. u32 内容块数。
4. 每个块：u64 原始字节长、原始字节。

路径严格递增，必须包含 story.xml；区分路径的逻辑大小写但禁止大小写碰撞。相同字节文件共享同一块，块按首次出现的路径排序分配；所有块必须被引用，不能带孤立/尾随数据。实现不解包到磁盘，目录跨度映射到一个只读 Arc 字节缓冲；read 只复制被请求文件。

### 预算和路径

最多 10000 文件、1024 字节路径；单文件 128MiB，压缩/展开 payload 各不超过 512MiB，按文件引用累计的逻辑总字节也不超过 512MiB。长度在解压前检查，解压后核对精确长度和摘要。拒绝多帧/尾随、未知 flags/版本、截断、非法块引用、大小写碰撞及无 story.xml。

逻辑路径统一 `/`，每段必须非空普通名称；禁止绝对路径、盘符、反斜杠、./../、控制字符、Windows 特殊路径字符与尾随点/空格。工程扫描拒绝 symlink，目录读取仍检查真实根边界。工程中的 .git/.idea/.vscode/target/saves/node_modules、临时/编辑器备份和用户 slot-/auto-/settings/profile/read/save JSON 被排除；许可文件正常收集。

### 生成

v0.8 的 story schema 8 工程先以 story.xml 为入口沿显式 next 链装配，合并为包内单个 story.xml，并移除链上其余源剧本 XML。合并文档以 next end="true" 结束；UI/JS/链外普通文件不因这个步骤被删除，源工程不改写。包中仍存普通 UTF-8 XML 字节，此处理不改变 KPAK 1 二进制格式。

使用 --format 1 时，kakera-pack 验证完整内容并检查工程指纹稳定，再生成确定性、去重、solid Zstandard（默认级别 19，可选 1–22）数据；不对图像/视频做有损重编码。输出必须在工程外；已有输出默认拒绝，--force 才以同目录临时文件和平台原子替换写入。被运行程序打开的包不会被热更，重新启动读取新包。

KPAK 1 面向中小体积 AVG，仍一次性解压；大体积改用下述 KPAK 2。两者都不提供加密防提取或签名认证。


## KPAK 2（大内容，按需分块）

### 固定头

头长 80 字节。数据块紧随头；未压缩索引位于文件末尾。

| 偏移 | 类型/长度 | 值 |
| --- | --- | --- |
| 0 | 8 bytes | 与 KPAK 1 相同 magic：4B 50 41 4B 0D 0A 1A 00 |
| 8 | u32 | version=2 |
| 12 | u32 | flags=0，未知位拒绝 |
| 16 | u64 | index_offset |
| 24 | u64 | index_length |
| 32 | u64 | archive_length，必须精确等于实际文件长度 |
| 40 | u32 | chunk_size=1048576（固定 1MiB 原文块） |
| 44 | u32 | reserved=0 |
| 48 | 32 bytes | 完整原始索引字节的 SHA-256 |
| 80…index_offset | 可变 | 连续独立 Zstandard 数据块 |
| index_offset…EOF | 可变 | 未压缩索引；index_offset+index_length=archive_length |

文件位置和文件长度不截断为 u32，不将整个文件映射或读入内存。文件句柄保持期间读取同一对象；Windows 禁止原地写入但允许原子替换，已打开句柄继续读旧对象，不混合两个包。

### 索引

依次排列：

1. u32 file_count。
2. 每个文件：u16 path_length，path_length 字节路径，u64 raw_length，u32 reference_count，reference_count 个 u32 chunk_id。
3. u32 chunk_count。
4. 每个块固定 48 字节：u64 offset，u32 compressed_length，u32 raw_length，32 字节 SHA-256(raw bytes)。

路径按 UTF-8 字符串严格递增，大小写碰撞拒绝，必须包含 story.xml。路径限制与 KPAK 1 相同。文件长度为 0 时引用数量为 0；非空文件引用数量必须精确等于 ceil(raw_length/1048576)。每个引用除了文件的最后一个，原文长度必须为 1048576；最后一个必须精确匹配余下长度。重复 chunk_id 表示复用相同原文字节，允许跨文件共享。

块表按物理顺序排列：首块 offset=80，后块起点必须精确等于前块结尾，最后一块结尾必须等于 index_offset；不接受洞、重叠、倒序、指向索引的块或孤立数据。所有 chunk_id 必须在界内，所有块必须被至少一个文件引用；索引不接受尾随字节。零块仅在所有文件为空时合法（真正故事加载仍验证内容）。

每块恰好一个标准 Zstandard frame，携带明确原文长度，禁止 skippable frame、外部字典、第二帧和尾随数据。原文长度必须与表中值一致，解压输出严格限制，再核对块 SHA-256。验证成功后才将该块字节交给消费者；失败的流保持失败，不继续掩盖错误。

### 预算

| 项目 | 硬上限 |
| --- | --- |
| 包实际长度 | 1TiB（包含头/索引） |
| 逻辑文件原文字节总量（按引用累计） | 1TiB |
| 单文件 | 64GiB |
| 文件数 | 100000 |
| 路径 UTF-8 长度 | 1024 bytes |
| 索引 | 128MiB |
| 唯一块数 | 1048576 |
| 单块原文 | 1MiB，必须非零 |
| 单块压缩字节 | 2MiB，必须非零 |

长度、算术、引用数量、索引边界在相应分配前验证。每个读取流只保留当前原文块；共享受限索引和文件句柄，不建立全包或全部块的永久解压缓存。文件游标移动与压缩块读取在同一短锁内，解压在锁外，不同流的读取位置相互独立。

这些是容器预算；普通 ContentSource.read 仍限制 128MiB，图像、音频、字体、Live2D 原有解码预算不变。大文件通过 open/copy_to 逐块读取，最大 64GiB。视频流复制到后端临时文件，随后由 Media Foundation 解码；这不是直接从包 seek 播放或网络流。播放器仍准备全部已声明资源，不能将本容器功能说成所有解码资源的场景级惰性加载。

### 打开、检查与生成

普通打开只读取固定头和索引，验证摘要/路径/完整布局/引用/预算；不扫描所有数据块。读取某资源时只校验和解压它所需的块，读到损坏块失败。未访问的损坏块不保证在普通启动发现；播放器 --check 和打包自检显式读取全部唯一块。

KPAK 2 打包先流式复制源工程到私有磁盘暂存，逐文件记录长度/摘要，建立固定候选。完整验证后，在暂存中合并 next 剧本链，保留 UI/JS/链外文件且不改磁盘工程；以逻辑路径和文件内顺序分 1MiB 块，按 SHA-256 去重，并比较复用块字节以拒绝摘要碰撞。块按首次出现顺序写入临时输出，最后写索引和头。压缩级别 1–22，默认 19，压缩窗口固定不超过 1MiB；相同源字节/级别/工具实现确定性生成，无时间戳。

输出包完整验证（包括未使用文件的块）、独立故事/资源加载，以及源工程重新扫描的完整指纹全部通过后，以同目录临时文件原子提交；--force 才能覆盖，失败保留旧包并清理自身临时输出。输出必须在源工程之外。暂存和视频后端文件需要足够临时磁盘空间，资源生命周期结束后释放；不逐帧读盘或解压。

KPAK 1 打包保留原内存快照路径及其小包预算。工程运行/热更的固定候选改用磁盘暂存；候选验证和当前历史重放仍在提交前完成。
