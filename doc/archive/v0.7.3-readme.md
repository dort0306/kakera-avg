# Kakera AVG Rust · v0.7.3

Rust、QuickJS、XML/JavaScript 驱动的 Windows x64 AVG 播放器。本版区分工程与发布状态，提供 KPAK 资源包和打包工具，并将窗口、图片滤镜与 Live2D 合成接入原生 D3D11；保留 CPU fallback，预留 Vulkan/Metal 像素后端接口。

新剧本使用 story schema 7，UI schema 2、存档 schema 6、KPAK 1 不变。每个剧本 XML 显式 next 串联或 end="true" 结束，固定 story.xml 入口；工程加载整条链，打包合并为一个 XML。Windows 发布程序不显示命令行窗口，工程/--check 保留诊断。保留中文逐字、变量/条件、历史检查点、200 手动槽/10 自动槽、自动播放、视频、CG/设置、自定义 XML UI 和立绘动作。本版新增**按住 Ctrl 快进**（设置可选只快进已读或全部，已读进度存于独立 `read.json`），并让存档/读档页的槽位预览只显示台词，不再暴露内部 frame ID。[完整 API](doc/xml-js-api.zh-cn.md) 第 22 节介绍背景点击、HUD 隐藏与截图存档，第 23 节介绍 Ctrl 快进与已读进度；[落地策略](doc/v0.7.3-implementation-plan.zh-cn.md) 先于代码制定，结果见 [验收记录](doc/v0.7.3-validation.zh-cn.md)。上一版的功能验收见 [v0.7.2 验收](doc/v0.7.2-validation.zh-cn.md)，其后的四项维护修复见 [维护修复记录](doc/v0.7.2-maintenance.zh-cn.md)；旧版说明见 [v0.7.2 归档](doc/archive/v0.7.2-readme.md)。

[工程模式、发布模式与 kakera-pack 使用指南](doc/project-release-pack-guide.zh-cn.md) 提供完整命令行参数、热更新流程、Core 配置、打包范围、便携目录制作及常见错误处理。

## 工程运行

需要 Rust stable（最低 1.88）、MSVC C++ 工具及 Windows 系统媒体组件；使用仓库 Cargo.lock。

```powershell
cargo run --locked
cargo run --locked -- --project games/demo
cargo run --locked -- --project games/demo --renderer cpu --save-dir target/my-saves
cargo run --locked -- --check
cargo run --locked -- --check --renderer d3d11
```

--game 是 --project 别名。工程监控 XML/JS、图片、字体、音频、视频和模型，约 200ms 去抖后后台准备候选。通过当前变量/历史/选项及资源验证才提交；坏文件保留旧会话/音频/画面，修复保存后重试。展开“工程状态”查看结果。兼容更新保留剧情位置/历史，补全当前句，重建 UI/媒体、停止自动播放；不写自动档/重复 CG 解锁。不兼容时只允许明确点击从入口重载，story_id 改变需重启。大资源准备有耗时，不保证每次保存 200ms 内完成。

## 打包与发布状态

```powershell
cargo run --locked --bin kakera-pack -- games/demo target/game.kpak
cargo run --locked --bin kakera-pack -- games/demo target/game.kpak --force --level 22
cargo run --locked -- --package target/game.kpak --cubism-core runtime/live2d/windows-x64/Live2DCubismCore.dll --check
./tools/package.ps1
```

kakera-pack 先校验工程，把 next 链的剧本合并为包内单个 story.xml，移除链上其余剧本源 XML，再生成确定性的 KPAK 1：同内容文件去重、整体 Zstandard 压缩（默认 19，可选 1–22）、SHA-256 损坏检测；无加密、无有损转码。输出必须在工程目录外，已有文件默认拒绝，--force 才原子覆盖。文件/路径/长度/解压/摘要有严格预算与检查，失败保留旧包。详细二进制格式见 API 第 20.4 节。

发布脚本输出 target/package/kakera-avg-v0.7.3：kakera-avg.exe、game.kpak、Core 与许可证/手册，**不含游戏散文件或用户存档**。程序发现 exe 旁 game.kpak 即进入发布状态；坏包报错，不回退散装目录。发布不启动监控，修改工程或替换运行中的包不会改变当前游戏；重新打包并重启生效。--package 与 --project 互斥。kakera-pack.exe 在 target/release 可单独使用；脚本拒绝覆盖旧发布目录，可用 -Output 指定新目录。

资源包不是签名或加密保护；读取时整体解压至受限内存（最多 512MiB），当前无按需流式包。剧本链最多 128 文件，源 XML 累计与合并 XML 分别最多 16MiB；next 路径相对游戏根，不隐式生成剧情路由。PNG/MP4 已压缩，二次收益有限。demo 合并后约 27.7MB，默认压缩包约 21.6MB；实际大小以工具输出为准。

Windows 播放器采用 GUI 子系统，发布启动失败用原生错误框提示，kakera-pack 保持控制台输出。PowerShell 自动化需等待检查时，用 `./target/release/kakera-avg.exe --check | Out-Host` 后读取 `$LASTEXITCODE`，或使用 Start-Process -Wait；Cargo 运行会等待子进程。

## D3D11 和 CPU fallback

Windows 窗口使用原生 D3D11 swapchain，egui/winit 负责布局和输入，正常运行不使用 wgpu/D3D12。灰度/棕褐/像素化/预乘透明模糊和 Live2D 网格、蒙版、颜色/混合由 GPU 完成；GPU 输出直接作为原生纹理，不在正常播放时读回 CPU。Cubism Core 的参数/形变、媒体解码仍为 CPU。

- --renderer auto：硬件 D3D11 优先，不可用时 WARP 窗口 + CPU 像素算法。
- --renderer d3d11：要求硬件设备，创建失败报错。
- --renderer cpu：强制旧 CPU 滤镜/模型；窗口仍使用 D3D11，必要时 WARP。

像素操作失败回退 CPU；窗口设备失败尝试一次 WARP 重建并保留 Session，再失败明确退出。GPU 模型最长边 1024、最高约 60Hz；CPU 为 512/30Hz，存在采样/模糊精度差异。PixelBackend/ModelDraw/Image 接口为后续 Vulkan、Metal 预留，本轮未实现 Linux/macOS 原生像素后端。

## 背景输入与截图存档

游戏画面非控件区域左键继续，沿用“跳过转场 → 补全当前句 → 推进”的仲裁；完成的选项页不会默认选择。右键非控件区域隐藏/恢复 HUD；隐藏时第一次左键只恢复 HUD。按钮、禁用按钮、滑条、滚动列表与菜单阻挡背景操作，黑边和失焦不触发。scene 与 HUD 分开，XML 的 screen 背景事件 + JS 的 hudVisible 完成定制；不改变纯剧情控制器。隐藏 HUD 不暂停播放，空格行为保持原样。

Windows 窗口手动/自动保存附带本地时间和 320×180 PNG 缩略图，存入同一个 schema 6 JSON，失败保留旧档。手动保存优先捕获同场景打开菜单前的客户区画面（含 HUD，不含标题栏/桌面/存档菜单）；自动保存等待对应场景真正呈现，可能包含进入转场的首帧。GPU 正常帧只缓存副本，实际保存时才读回；CPU/WARP 窗口使用同一捕获入口。缩略图最多 256KiB，JSON 上限 2MiB；没有截图的原 save 6 仍可读取，显示“无截图”。未提供捕获能力的宿主不能执行带图 GUI 保存，自动保存失败会提示并停用。

## Demo、内容和存档

demo 现拆为 story.xml → chapters/visuals.xml → chapters/story.xml → chapters/actors.xml → chapters/media.xml，最后显式 end="true"；同类 ID 全局唯一，JS 可跨章路由。拆分只改变组织方式，content-version=6 和原场景/变量/路由保持。

问题页的“Live2D 测试”提供 Haru 待机、TapBody、F02 表情和 XML 参数姿态，可返回原凛剧情；另有图片效果/立绘动作/片头片尾演示。共 30 场景、4 变量、3 JS、11 UI 页面、2 视频、1 模型。

Haru 与 Core 来自用户提供的 CubismSdkForNative-5-r.5，模型许可在 games/demo/assets/licenses，Core 原许可/可再分发清单在 runtime/live2d，均随本地发布包保留。工程可回退固定源码 runtime；发布仅使用 --cubism-core、CUBISM_CORE 或 exe 旁 DLL，绝不从内容/脚本选择 DLL。没有公开上传行为；第三方内容不是项目自制 CC0 素材。

没有 `<interface>` 的旧内容（story schema 1–3）由内置兼容界面呈现：只有继续/补全、选项、手动存读档、历史与设置，不含 v0.4 以后的 XML 界面能力（CG、自动播放、视频跳过、截图存档页）。兼容路径冻结在加入 XML UI 之前的行为，不写自动档（否则会生成它无法读回的槽位），启动时打印一条提示；新内容应提供 ui.xml。demo 早期那份不被读取的 flow.xml 已移至 doc/archive/demo-flow-v0.3.xml，v0.3 规则的等价样例仍在 doc/v0.3-example。

所有内容统一经 ContentSource；XML/JS/图片/字体/音视频以游戏根为准，model3 内部引用以其目录为准，统一 `/`，拒绝绝对路径、..、反斜杠、大小写碰撞和越界链接。字体与 OFL 必须随内容保留。--no-live2d 显式选择静态 fallback；--no-audio 仅禁用设备，仍检查资源。

用户数据默认位于 Windows 用户数据目录（以启动日志为准），--save-dir 可隔离。手动 slot-1…200.json 与自动 auto-1…10.json 独立，schema 6 存变量、历史和检查点；实际加载严格重放，坏档/身份不匹配不改变当前 Session。设置、CG 与已读进度分别在 settings.json/profile.json/read.json，不随剧情槽回退：`settings.json` 记住 Ctrl 快进是「只快进已读」还是「全部」，`read.json` 记录整句显示过的场景（schema 1/story_id，坏文件按未读处理，约 3 秒节流写入并在退出时补写）。写档同目录临时文件原子替换；自动保存失败保留已提交剧情并停用 autosave。包内不写这些文件，工程监控与打包也排除它们；存档/读档页只显示台词预览与截图，内部 frame ID 仍写在槽位文件中用于校验，但不再展示。

## 验证与限制

```powershell
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo run --locked -- --check
$env:CUBISM_SDK='C:/CubismSdkForNative-5-r.5'
$env:LIVE2D_TEST_GAME='D:/codes/kakera-avg-rust/games/demo'
cargo test --locked --test live2d_native -- --ignored
```

--check 默认不打开窗口/GPU/设备，不穷举动态 JS；实际 GPU 输出与 GUI/听感分开记录。自动测试覆盖包完整性/去重/原子替换、真实文件通知、错误脚本回滚、D3D11 像素对比、真实 Haru GPU 输出、Ctrl 快进仲裁与已读进度、槽位预览去 frame ID。此前已检查 D3D11/CPU/资源包窗口、热更新、第 200 槽和媒体，历史证据见 [v0.7.3 原验收记录](doc/v0.7.3-validation.zh-cn.md)。2026-10-25 修复后回归：135 项测试通过、1 项默认忽略，真实 SDK 用例另行通过；首次复验发现的 Ctrl/自动播放仲裁、非暂停模态页穿透、已读数量上限三项缺陷已修复，并加入正式回归；修复结果及未覆盖范围见 [维护修复记录](doc/v0.7.3-maintenance.zh-cn.md)，失败复现保留在 [原复验报告](doc/v0.7.3-reacceptance.zh-cn.md)。设备丢失、多 GPU/高 DPI 与本轮实际音频设备/听感尚未现场验收。

视频仍是 Windows Media Foundation、1080p/约60fps/300秒以内，音轨启动解码；无 seek/网络流/精确音画同步保证。Live2D 无 physics3 求解、完整 Pose 渐变/动作混合、自动口型/跟随、动作声音与高级 offscreen/混合。UI 是基本 XML 布局而非 CSS/DOM。QuickJS 同步隔离、有预算且无宿主 IO/时钟/随机/异步；历史与领域控制器保持纯函数。工程增加原生监控和单候选构建线程，视频保留单有界解码线程，无异步 runtime/ECS/插件框架。
