# KPAK 1 资源包格式

规范来源：src/package.rs。当前版本 1，与 story/UI/save schema 独立。无加密、无时间戳、无签名；摘要只检查损坏。

## 外层

固定 64 字节头，所有数字 little-endian。偏移 0 的八字节 magic 为 `4B 50 41 4B 0D 0A 1A 00`；偏移 8 为 u32 version=1，12 为 u32 flags=0，16 为 u64 compressed_length，24 为 u64 payload_length，32…63 为 SHA-256(payload)。偏移 64 开始恰好一帧 Zstandard 压缩数据，文件长度必须等于 64+compressed_length。

## Payload

1. u32 文件数。
2. 每个文件：u16 路径 UTF-8 字节长、路径字节、u32 内容块索引。
3. u32 内容块数。
4. 每个块：u64 原始字节长、原始字节。

路径严格递增，必须包含 story.xml；区分路径的逻辑大小写但禁止大小写碰撞。相同字节文件共享同一块，块按首次出现的路径排序分配；所有块必须被引用，不能带孤立/尾随数据。实现不解包到磁盘，目录跨度映射到一个只读 Arc 字节缓冲；read 只复制被请求文件。

## 预算和路径

最多 10000 文件、1024 字节路径；单文件 128MiB，压缩/展开 payload 各不超过 512MiB，按文件引用累计的逻辑总字节也不超过 512MiB。长度在解压前检查，解压后核对精确长度和摘要。拒绝多帧/尾随、未知 flags/版本、截断、非法块引用、大小写碰撞及无 story.xml。

逻辑路径统一 `/`，每段必须非空普通名称；禁止绝对路径、盘符、反斜杠、./../、控制字符、Windows 特殊路径字符与尾随点/空格。工程扫描拒绝 symlink，目录读取仍检查真实根边界。工程中的 .git/.idea/.vscode/target/saves/node_modules、临时/编辑器备份和用户 slot-/auto-/settings/profile/read/save JSON 被排除；许可文件正常收集。

## 生成

v0.8 的 story schema 8 工程先以 story.xml 为入口沿显式 next 链装配，合并为包内单个 story.xml，并移除链上其余源剧本 XML。合并文档以 next end="true" 结束；UI/JS/链外普通文件不因这个步骤被删除，源工程不改写。包中仍存普通 UTF-8 XML 字节，此处理不改变 KPAK 1 二进制格式。

kakera-pack 验证完整内容并检查工程指纹稳定，再生成确定性、去重、solid Zstandard（默认级别 19，可选 1–22）数据；不对图像/视频做有损重编码。输出必须在工程外；已有输出默认拒绝，--force 才以同目录临时文件和平台原子替换写入。被运行程序打开的包不会被热更，重新启动读取新包。

当前设计面向中小体积 AVG，一次性解压使随机资源读取简单且不泄漏压缩细节；不提供 GB 级按需流式包、加密防提取或修改真实性保证。未来升级格式需显式提升包版本，不能悄悄重解释旧字节。
