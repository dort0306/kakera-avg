# 01 产品与创作流程

状态：拟实现。范围与基线见 [入口](README.zh-cn.md)。产品目标是让作者主要编辑“一幕、人物、背景、台词、选择和条件”，仍能随时查看、导出和维护普通 XML/JS 工程。

## 1. 工作台

| 区域 | 主要内容 | 必须避免的误导 |
| --- | --- | --- |
| 左侧项目树 | 章节、人物、变量、场景、UI 页面、资源、问题 | 章节文件链不是剧情路线 |
| 中央舞台 | 16:9 显示、当前幕完整构图、对话与安全区域 | 作者窗口可任意缩放，播放器的窗口比例约束不施加于编辑器 |
| 底部分镜带 | 每格缩略图、幕名、角色、台词摘要、路由类型、问题标记 | 每格对应一个 frame，不是每秒显示若干格的动画时间轴 |
| 右侧属性 | 完整画面、文本、音频、转场、立绘最终姿态、视频/模型 | 未填写背景意味着无背景，不是沿用上一幕 |
| 可切换的关系图 | 分支边、条件、变量更新、结束、自循环、未知动态目标 | 未能分析的动态 JS 目标不能画成确定边 |
| AI 辅助区 | 剧本拆幕、素材候选、提案差异、缺失素材清单 | AI 推荐不是已应用内容，也不是经校准的正确概率 |
| 调试/构建面板 | 诊断、真实播放器、测试路线、资源预算和发布日志 | MVP 外部试玩不是已实现的断点调试 |

无代码模式隐藏默认 ID、文件路径和 JS 细节，以中文名展示；高级模式可显示 ID、资源引用和源码。二者使用同一份内容，不能分别维护两套剧情。

## 2. 一幕的含义

一幕包含一段非空台词、可选说话人、完整 visual、完整音频声明、转场和路由。通常每句或每个需要独立保存/恢复的状态一幕，不把整章剧本强塞到同一个 frame。

允许同一背景连续多幕、同一幕自循环、选择跳到远处和章节交叉。分镜带的“下一格”只是组织关系；普通顺序创作时，编辑器明确创建 Advance 路由。拖动分镜排序默认不修改路由；“按新顺序重连”单独显示差异并执行。

舞台图层是作者侧的属性入口：背景、left/center/right 三个立绘槽、对话 UI、选项和菜单。当前引擎没有任意数量/任意坐标的剧情立绘轨道。拖动立绘只提供当前支持的槽位及姿态/效果参数，不能导出不存在的坐标属性。UI 节点可用现有设计坐标。

“复制上一幕画面”复制最终状态，导出每幕仍完整；编辑器不发明跨幕继承。修改共享 visual 时显示全部使用幕，提供“修改全部”与“复制为此幕独有”。动作小时间条只解释本幕转场/立绘进入退出，不能被当成引擎未实现的 Flash 补间系统。

## 3. 初次创作

1. 新建工程，选择游戏名、故事标识、设计画布和字体；使用随编辑器发行的当前 XML UI 模板。模型可以稍后安装，手工创作始终可用。
2. 导入背景、立绘、点九图和图集等素材；填写角色、表情、地点、时间、用途、授权来源。PSD/工程母版保存在内容目录之外。
3. 粘贴或导入 UTF-8 纯文本/Markdown 剧本，按段落、角色和显式场景提示拆成草稿。MVP 不承诺直接解析 DOCX/PDF；后续格式用明确导入适配器转换并保留段落来源。
4. 选择章节，运行“AI 拆幕并关联资源”。显示进度，可取消；模型只看到该任务需要的文字、素材清单和受限缩略图。
5. 审阅每幕：原段落、拆分台词、背景/立绘候选、推荐依据、未解决项目。角色和表情歧义必须可手工改选；缺图可用作者工作区占位图预览，正式导出必须替换成真实资源或明确空画面。
6. 确认路由、条件及更新。所有选择都要有明确目标或明确结束安排，不生成默认第一项选择。
7. 接受提案后生成 XML/JS 候选，经过引擎校验后提交。生成不要求安装 Rust 编译器；最终产品随附匹配版本的播放器和打包器。
8. 从入口真实试玩，保存一条测试路线，再构建游戏发行目录。

## 4. 手动无代码编辑

| 操作 | 可视化行为 | 导出要求 |
| --- | --- | --- |
| 新增幕 | 创建一次稳定 ID，添加完整属性和路由待办 | 保持 story schema 8 |
| 对话编辑 | 角色下拉、普通文本和字数/换行预警 | 普通 text，不注入 HTML 或变量插值 |
| 条件选择 | 类型化比较、与/或/非、已声明变量 | 编译为同步 JS boolean，int 使用 BigInt |
| 更新变量 | 有序赋值/加减，声明范围可见 | ctx.set/add，顺序与草稿读取语义一致 |
| 目标分支 | 有序判断加显式最终目标 | 不将任意 JS 表达式伪装成可视规则 |
| 修改外观 | 背景、立绘槽、姿态、转场枚举 | 只提供当前宿主支持的参数 |
| UI 图集 | 在原图上选择像素矩形，点击状态/区域预设 | image 的 region/region-bind，JS 复用 setUi |
| 点九背景 | 显示边框标记、伸缩段、内容区和 density | 专用 nine-patch 资源与节点 |
| 窗口标题 | 静态文本或绑定 UI 变量 | UI 根 title/title-bind，不新增剧情存档字段 |

条件编辑器 MVP 只覆盖明确的小语言：类型化常量/变量、比较、布尔组合；目标为固定幕引用，更新为 set/add。复杂计算、动态目标、共享函数保持“代码块”。不是恢复旧版 Rust flow 解释器，运行仍交给 QuickJS。

## 5. 导入现有项目及双向修改

先只读扫描、校验并展示，再决定哪些部分由编辑器管理。所有 XML frame 都能显示成卡片，即使其 JS 无法视觉编辑；该卡片会标识“高级逻辑”，可查看原文、声明选项及运行时轨迹。

合法手写 JS 可能包含跨文件函数、循环注册和动态目标。读取注册清单只知道路由类别/选项，不等于知道所有返回目标。只对已识别且可逆的受限语法开放条件表单；其余代码逐字保留，禁止保存一次就重排或覆盖整个文件。

源码发生外部编辑时比较文件指纹和工程 revision。无冲突部分重读，有冲突部分进入三方比较；编辑器不以旧缓存覆盖作者的新文件。切到代码模式只影响编辑方式，不丢弃尚未提交的分镜草稿。

## 6. 资源工作流

资源库展示缩略图、类型、实际尺寸/时长、标签、用途、授权、依赖和引用幕数。文件名只是线索，作者确认的角色/表情标签才是可靠关联。相同资源可被多幕使用，不复制相同图片到每幕。

资源替换先比较所有使用位置：图集区域越界、立绘比例变化、模型动作消失、字体缺字或视频预算超限都进入候选诊断。重命名更新资源路径/所有已知引用；动态 JS 字符串无法安全改写时禁止静默批量重命名，改为保留旧资源 ID 或人工处理。

删除资源先展示反向引用及动态代码不确定项，默认仅从待导出清单移除并保留可恢复源文件。批量去重只合并确认相同且语义等价的资源，不能因画面相似合并不同表情。模型动作/贴图和许可证必须作为资源依赖整体管理。

## 7. 作者可理解的错误

诊断优先显示“第 2 章 / 门口选择 / 邀请选项：目标场景不存在”，展开后显示 JS/XML 文件位置。必须区分语法错误、资源缺失、逻辑不确定、模型建议待确认和播放设备错误。

“继续不了”要能解释：台词未完成、正在转场、菜单暂停、全部选项隐藏、结束幕或视频阻挡；不能用自动选第一项来掩盖问题。AI 修复仍是一个可撤销提案，不在后台改写工程。
