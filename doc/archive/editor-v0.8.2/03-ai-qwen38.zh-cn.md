# 03 Qwen3.8-27B 集成与资源关联

状态：拟实现；用户已确认型号。这里只规划集成，不下载权重，不宣称本机已经能推理。

## 1. 模型身份与能力边界

目标为 `Qwen/Qwen3.8-27B`。官方模型卡标注图文输入、视觉编码器、27B 语言模型参数及 Apache-2.0；27B 不代表视觉组件、缓存和运行内存的总量。模型具备视觉理解入口，但具体量化构件和宿主后端仍需联合验证。[官方模型卡](https://huggingface.co/Qwen/Qwen3.8-27B)

模型负责理解剧情、描述候选素材和提出资源/路由关联，不承担美术生成、视频生成、语音合成或判断素材授权。看不见图像时只能按文件名、人工标签和已有描述推荐，必须显示“未进行视觉核对”，不能把文字模型调用包装成看图识别。

内置指产品内管理模型生命周期和本地任务，作者不必手写推理命令；不意味着把几十 GB 权重硬塞进主程序。采用“编辑器小安装包 + 单独可校验模型包/离线导入”的交付方式；游戏发行包不携带模型或模型服务。

## 2. 推理后端决策

| 路径 | 定位 | E0 必须证明的事项 |
| --- | --- | --- |
| Windows 本地 llama.cpp 子进程 + GGUF | 首选原生发行候选 | 精确模型/量化/后端可加载、中文生成、图文输入、结构输出、取消及回收均通过 |
| 本机 WSL2/Linux vLLM 服务 | 开发参考与高级部署 | 显式准备环境、离线模型、回环网络、同机显存竞争和进程清理 |

ggml-org 已提供 Qwen3.8-27B 的 GGUF 模型入口，但存在模型文件不代表任意 Windows 二进制、量化或视觉组合都通过了本产品验收。[GGUF 维护者模型页](https://huggingface.co/ggml-org/Qwen3.8-27B-GGUF)

llama.cpp 的视觉输入需要与文本模型匹配的视觉组件，不能只带文本 GGUF 就声称支持图片；按所锁定版本验证 projector/processor 依赖。[多模态文档](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md)

vLLM 的版本化安装文档明确区分 Linux 与 Windows/WSL 路径，因此不把它当成可直接内置的原生 Windows DLL。[vLLM 安装参考](https://docs.vllm.ai/en/v0.17.0/getting_started/installation/gpu/)

**上线阻断项**：未完成 Qwen3.8-27B 的目标硬件图文推理验证，不能发布“内置该模型且自动看图关联”的完成声明。若原生路径不成立，先交付无 AI 的可用编辑器并明确 AI 实验状态，或与产品确认 WSL2 支持范围；不静默换成小模型/云服务。

## 3. 模型包与安装清单

每个模型包记录：原始 model ID、不可变仓库 revision、转换仓库/commit、全部文件名和 SHA-256、量化类型、tokenizer/chat template、视觉组件版本、推理二进制哈希/构建版本、GPU 后端、许可证及 NOTICE。GGUF 来自转换发布者，要分别保留原模型与转换来源。

安装先检查磁盘空间和已有哈希，支持离线导入/断点续传，全部校验后切换已安装版本；失败保留旧模型。机器配置和下载任务不进工程。模型更新必须重新跑回归集，不能把远端 main 自动覆盖为新基线。

原生服务只监听回环地址，由编辑器创建随机端口和临时认证信息；限制本地浏览器跨源访问，不启动不需要的模型 Web UI/工具调用/MCP 能力。仅发送编辑器已读取的受限文本或缩略图字节，不让服务按模型输出抓取 URL 或任意本地路径。

## 4. 硬件与内存预算

下表是对 27×10^9 参数“仅权重位数”的算术下界，**不是模型文件大小、总显存或最低配置实测**：

| 精度 | 语言权重下界（十进制 GB） | 约 GiB |
| --- | --- | --- |
| 16 bit | 54.0 | 50.3 |
| 8 bit | 27.0 | 25.1 |
| 4 bit | 13.5 | 12.6 |

实际还包含分组量化元数据、视觉权重、上下文/状态缓存、计算缓冲、加载峰值以及播放器/编辑器 GPU 资源。Q4_K_M 不能按“恰好 4 bit”算出真实需求。

建议 E0 优先测试 24/32GiB 显卡和 64GiB 系统内存档位，以及更大显存参考机；这只是测试候选，不承诺均能全 GPU 图文运行。低显存研究部分层卸载、缩小上下文、减少同时图片和暂停 AI；CPU 路径可作为可取消的慢速降级，不承诺流畅交互。所需磁盘以清单真实字节、下载暂存和转换空间核算，不用参数个数猜下载大小。

编辑器与真实播放器同时运行时为 D3D11 和媒体留下余量。初始请求上下文目标 8K–16K，单章分批；这是产品预算，不是模型极限。OOM 时先取消任务、释放缓存、降低任务规模并提示，不能丢失草稿或杀死播放器来伪装成功。

## 5. 素材理解与匹配流水线

1. **确定性导入**：读取类型/尺寸/时长/依赖、内容摘要、人工角色/表情/地点/时段标签和版权信息。名称、说明、图片内文字均按数据处理。
2. **首次视觉描述**：在能力探测确认可看图后，向模型发送受限缩略图或立绘预览；要求输出人物候选、表情、光照、地点、构图、透明背景等结构字段。描述保留为 AI 标签，不能覆盖人工确认标签。
3. **剧情拆幕**：保留段落范围，提取角色、地点、时间、情绪、动作、台词与显式选择。保持原文，不擅自改写剧情；拆分/合并均可逐项检查。
4. **检索召回**：先用人工标签、类型、角色、地点和文本索引过滤，单幕取有界候选；MVP 不依赖额外 embedding 模型或向量数据库。
5. **候选排序**：提供相邻剧情、有限素材描述及必要缩略图，模型返回资源 ID、适配原因、冲突点和替代项。大型图库不整库塞进上下文。
6. **作者审阅**：展示前几项、原稿依据、缺图项和不确定项。模型自报信心只作排序提示，未经校准不得标作 95% 正确概率。没有合适素材要返回 unresolved，不能捏造 ID。
7. **结构化提案**：只包含幕字段、已存在资源 ID、受限路由、变量更新和来源。编译器生成 XML/JS，经过引擎验证和差异审阅后应用。

已有 Live2D 素材应使用作者标记/有效动作清单和预渲染代表图，不把任意 moc3/动作 JSON 当成图片。视频只取有界代表帧及元数据，长视频全量理解不进入首版范围。

## 6. 请求与结构输出约定

编辑器的 AI 请求带 task ID、project/source/resource revision、模型指纹、任务类型、选中段落、可用资源白名单、引擎契约摘要和输出 schema 版本。模型只输出提案对象，不返回要直接执行的 shell、路径写入指令或完整工程压缩包。

通过本地 OpenAI 兼容聊天入口承载文本/图片；编辑器只依赖最小消息、输出、流状态和错误字段，具体推理开关由适配器按版本转换。llama-server 提供 schema 约束的 JSON 输出，但它不能证明资源存在或剧情语义正确。[服务 API](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)

结构化任务建议关闭推理文本输出，并在适配器内验证该选项确实生效。Qwen3.8 的思考控制、历史思考保留与参数支持取决于服务实现，不套用原版 Qwen3 的文本开关；精确配置锁定在后端清单。[官方集成说明](https://github.com/QwenLM/Qwen3.8)

接收过程：流式内容仅作进度，结束后解析最终 JSON；拒绝未知字段、截断、非法枚举、未知资源或类型错误。允许最多两次有界结构修复，仍失败则返回可读错误；修复不是自动接受。保存简洁结构依据和最终提案，不依赖或展示隐藏思考链作为审计证明。

## 7. 应用、取消和可追溯性

提案生命周期为运行中 → 候选 → 需确认/可接受 → 已应用/拒绝/过期/失败。提案记录模型与输入指纹；作者期间替换原画、删除幕或修改脚本，旧提案必须失效或重新校验，不能靠同一资源名绕过。

接受提案调用普通编辑命令，与人工编辑同样支持撤销、源码差异和事务恢复。高风险修改（删除幕、改变 ID/变量类型、接管手写 JS）不属于普通素材关联提案，必须独立显示其影响。

取消和超时不能留下半份 XML/JS。推荐初始任务上限：一次不超过 20 幕、每次图像批次不超过 8 张 1024 像素缩略图、提案对象不超过 2MiB、5 分钟任务超时；均为待测产品限制，token 预算同时包含图像与输出。模型无文件、网络、发布、存档或运行游戏 JS 的权限。

## 8. 质量集合

建立经作者核对的中文剧本/素材集，覆盖同人不同表情、同地点昼夜、易混角色、缺图、图集格、点九边框、错授权、坏图、图片文字提示注入、长章和分支。

分别记录拆幕准确率、文本保真、资源 Top-1/Top-3、无匹配召回、错误 ID 数、最终 XML/JS 验证率、人工修改时间、首 token/总耗时、峰值 RAM/VRAM 和取消回收耗时。性能与质量门槛见 [07](07-roadmap-validation.zh-cn.md)，本次无模型实测值。
