# 06 调试与构建发布

## 1. 先分清三种预览

| 模式 | 能力 | 当前状态 |
| --- | --- | --- |
| 单幕构图预览 | 从某个 Frame 的完整状态显示画面、台词和效果 | 编辑器拟实现；不创建可保存的合法剧情会话 |
| 真实试玩 | 从入口经过 Controller/QuickJS、UI、音频、媒体和历史 | 当前外部播放器已支持启动，编辑器需做任务封装 |
| 帧级交互调试 | 断点、暂停、进入步进、只读运行快照和事件轨迹 | 播放器拟扩展，当前没有远程协议 |

选择一个分镜就能看构图，不等于能把 Session.frame_id 任意改成那一幕。已有历史、条件和变量必须可验证；调试工具不能通过写假存档实现“跳转”。

## 2. MVP 即刻可复用的工作流

编辑器为已验证内容生成不可变试玩目录，通过现有 --project 和独立 --save-dir 启动匹配播放器，保留退出码和日志。当前 --check 可先验证内容与媒体，--no-audio 只禁设备输出，资源解码仍发生。

宿主以固定可执行文件和参数数组启动自己管理的任务，不拼接来自模型/原稿的 shell 命令。GUI 子系统播放器必须显式等待退出并捕获退出码；进程启动成功不代表检查通过。Core 使用受信任宿主配置，不能由游戏资源或 AI 提案提供任意 DLL 路径。

每个试玩会话标记 sourceFingerprint/generation；修改后可生成新代次并重启，或在后续协议支持时明确请求替换候选。不要把对多个文件逐个保存、播放器自动监控的结果叫作同一作者事务的原子热更。

诊断先显示引擎原始文本与可识别的文件行列，再映射到分镜。无法定位时保留原文，不伪造对象或吞掉错误。当前没有机器稳定的 JSON 诊断；结构化诊断接口是后续扩展。

从入口维护一条“测试路线”：Advance/明确 Choose 的序列，加变量/位置/可用选项断言及内容指纹。实际执行复用 Controller/ScriptLogic，隐藏选项不能选，条件异常立即停止。存档检查通过 Snapshot 完整校验恢复，不根据 UI label 猜状态。

从某幕开始排查的 MVP 路径为：已有可重放测试路线/检查点重放到该幕；没有合法路线时只做构图或离线条件预览。变量面板先只读。修改变量只用于离线条件模拟，不能无校验覆盖当前 Session 后继续写正式档。

## 3. 帧级调试宿主的边界

此能力确实需要 Rust：游戏 XML/JS 没有进程通信、任意状态查询或挂起提交权限。新增接口只在工程调试模式显式启用，正式发布模式拒绝；游戏脚本不能接入编辑器 AI/文件系统。

建议协议名 `KakeraEditorDebug`、版本 1。由编辑器启动子进程并建立受限本机通道，优先继承的专属管道；若使用 Windows named pipe，限制本机、当前用户及预期子进程，带启动随机凭据。精确启动参数/句柄约定在 E4 开发时落地，不把它写成当前可运行 CLI。

协议不得复用混有日志的标准输出裸文本而不分帧。采用长度有界的消息帧与独立日志通道；普通消息建议最多 1MiB，截图走独立二进制消息并遵守现有捕获预算。没有网络调试监听、任意 JS eval、任意路径或 shell。

### 握手与共用字段（拟议）

| 字段 | 用途 |
| --- | --- |
| protocol/version | 不兼容版本拒绝，不猜旧字段 |
| sessionId / launchNonce | 关联编辑器自己启动的进程 |
| engineVersion / engineHash | 防止编辑器与播放器版本不匹配 |
| storyId / contentVersion | 绑定游戏契约 |
| sourceFingerprint / generation | 绑定实际运行的快照 |
| capabilities | 明确是否支持断点、快照、候选替换等 |
| requestId / eventSequence | 去重请求、检测事件缺失与过期响应 |

### 命令与事件（拟议）

| 命令/事件 | 参数或数据 | 边界 |
| --- | --- | --- |
| debug.setBreakpoints | 幕实际 ID/稳定别名、可选受限条件 | 别名按当前快照解析；不会创建 JS 新入口 |
| debug.pause/resume | 当前会话及代次 | 在更新边界处理，UI 不冻结窗口事件循环 |
| debug.step | continue/reveal/skipTransition/advance/choose(optionId) | 沿用正常仲裁；一次更新至多一个剧情操作 |
| debug.inspect | 只读快照范围 | 输出字段见下表，不暴露 GPU/Core/解释器对象 |
| debug.replay | 匹配指纹的测试路线/已验证检查点 | 从合法状态重放；不是随意设 frame_id |
| debug.replaceCandidate | 已验证的新代次标识 | 兼容性检查与当前事务全部成功才替换 |
| debug.stop | 所属 sessionId | 正常退出/收尾；断线不留下不可恢复的等待 |
| ready/paused/resumed | phase、原因、当前 ID、事件序号 | 表明停在准备前后还是已提交态 |
| transitionPrepared/committed/rejected | 源/目标/选项、更新摘要、错误 | rejected 必须保留旧 Session/音频/效果 |
| contentAccepted/contentRejected | 新旧代次、兼容性诊断 | 坏/过期候选不改变运行状态 |
| diagnostic/exited | 文件栈、退出码、会话 | 保留原始错误，不凭日志关键词判定成功 |

Frame 级断点建议放在候选条件、更新、目标及媒体验证后、正式提交前；此时可读旧状态和候选计划，不能已经播放新语音/写自动档后才称“进入前断点”。入口首次暂停需单独标记初始化阶段，在首个画面呈现前建立明确状态，不伪造上一幕。

暂停同时冻结逐字、转场、自动播放、快进、视频时钟/音轨和模型动作时间，保留窗口重绘与输入。恢复按当前时间重设时钟基线，不补算停顿。断点不能绕过自动存档等待、目标校验或每次更新只提交一个意图的约束。自动档只在实际剧情提交后按原规则处理。

调试 next-frame 可由有界控制序列组合跳转场/补全/推进，但每个更新仍只执行一个动作，到选择幕不替作者选择；所有命令标明其产生的实际操作。

### 只读快照（拟议）

包含实际 frame ID、作者别名、story/content 版本、generation、已提交变量类型和值、候选更新摘要、可用选项、历史条数/检查点摘要、UI 页面栈/局部变量、标题、设置快照、暂停原因、媒体状态、资源预算与诊断。整数用十进制字符串传输。

不返回宿主文件句柄、绝对资源路径、Core 指针、纹理指针、原生库入口或 QuickJS 对象。历史重放/条件求值轨迹与真实提交事件分开标记，避免作者把同一回调多次校验误认成剧情多次执行。

## 4. 源码映射与高级代码

EditorSourceMap 将生成的 XML 属性/JS 注册/条件/更新范围映射到幕与原稿段落。当前 story_chain 已有章节源位置映射，编辑器只在其上增加作者对象定位，不能丢掉原始文件名。

动态路由只记录运行时观察到的边，标记“已观察”而非“全部可能”。Opaque JS 出错显示代码范围/原始栈，支持跳到源文本；首版不承诺逐行进入函数、修改闭包或通用 QuickJS 行级断点。

## 5. 发布流水线

1. 固定已提交 revision 和生成器版本，导出纯游戏内容到根外私有暂存；冻结 ID 策略。未解决占位、未知必要资源、契约错误直接阻断。
2. 检查文件清单，排除 .editor/缓存/原稿母版/模型权重/用户档；保留字体、模型依赖及许可证。不靠当前打包器自动排除未知目录。
3. 运行当前资源/媒体/Core 完整校验和约定的测试路线；明确检查范围不能证明所有动态分支。
4. 使用匹配版本 kakera-pack，默认 KPAK 2；小项目可显式 1。输出根在内容根之外，旧输出只经明确覆盖意图原子替换。
5. 对生成包执行完整 --check，扫描全部唯一块；组装匹配播放器、包外受信任 Core（若需要）、第三方许可证和用户启动说明。
6. 将发行目录复制到源码/SDK/模型缓存之外，使用程序旁 game.kpak 启动检查，再实际试玩目标路线；缺源码时仍应可运行。
7. 输出 build manifest：源/模板/工具/模型提案来源指纹、content-version、包格式/哈希、实际 ID 策略、检查结果及许可证清单。模型来源是作者过程记录，模型文件不随游戏分发。
8. 通过后将暂存产物提交为一个新发行目录；失败保留诊断与旧发行物，不先删旧目录。公开上传不是“打包完成”的自动下一步。

现有 package.ps1 的宿主 Core 和许可来源固定于仓库 runtime，且会构建 Rust 二进制。编辑器发行版应改为已验证的播放器/工具资源清单和显式 Core 配置，不假设作者有源码、SDK 或 cargo；这属于编辑器构建服务的拟实现能力。

## 6. 发布门禁

| 检查 | 处理 |
| --- | --- |
| 语法、类型、资源缺失、超预算、未替换占位、入口错误 | 阻止发布 |
| 可证明的非法路由/所有选项在给定测试态隐藏 | 对该场景阻止通过，提供测试态与来源 |
| 任意 JS 动态目标未穷举、未覆盖路线 | 报告未证明范围，由发布策略决定是否要求更多测试 |
| 缺省 ID 重打包、契约变化 | 显示旧档影响，要求明确 content-version/ID 决策 |
| Core/字体/模型许可证或再分发材料缺失 | 阻止生成声称完整的发行目录，提供缺失清单 |
| AI 资源选择尚未作者确认 | 保持草稿，不悄悄当作最终素材 |
| 游戏包内出现模型权重/编辑器私有数据 | 阻止交付并显示泄漏文件 |

## 7. 不宣称的能力

本规划不等于已经有通用脚本调试器、任意状态跳转、跨平台媒体、精确视频 seek、自动授权检查、云发布或 AI 绘图。相应需求应独立评估宿主能力与工程成本。
