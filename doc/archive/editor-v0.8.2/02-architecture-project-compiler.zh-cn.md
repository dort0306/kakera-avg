# 02 架构、工程与编译

状态：拟实现，基于当前单 crate 和 XML/JS 优先约定。已有 API 定位见 [04](04-current-engine-api.zh-cn.md)。

## 1. 技术与进程边界

建议首版沿用 Rust/egui 桌面技术，在根 crate 增加独立编辑器入口；不是直接复用有固定 16:9 约束的播放器 Host。编辑器主窗正常可调整大小，舞台预览区域单独等比。沿用现有依赖降低首版成本，不立即拆 workspace、引入 Web 服务、ECS、异步 runtime 或插件框架。

| 组件 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 编辑器主线程 | UI、选区、撤销、命令提交和任务状态 | 大图解码、模型推理、打包阻塞 |
| 编辑器领域/文档层 | 来源定位、分镜、资源引用、类型化路由草稿 | 游戏实际变量更新/历史裁决 |
| 编译与验证工作进程 | 冻结快照、确定性导出、引擎校验 | 绕过引擎验证的另一个剧情解释器 |
| 缩略图/索引任务 | 有界读取、解码和缓存 | 在绘制回调中扫描文件 |
| 模型子进程 | 本机 Qwen3.8-27B 推理 | 直接访问工程或调用 shell |
| 外部播放器 | 最终显示、媒体、真实路线和存档行为 | 首版编辑器面板的嵌入式 GPU 纹理 |
| 打包器/构建任务 | 冻结导出、KPAK 自检和便携目录组装 | 云上传、自动公开发布 |

新增宿主能力仅用于作者工具的文件管理、编译、模型服务和调试；游戏作者仍只需 XML/JS。游戏 Model/Controller 不依赖编辑器或 AI。编辑器重任务建议先使用一个有界后台任务队列和可终止工作进程；不要让模型把主界面卡住。并行上限初始为单推理、单验证、少量缩略图任务，具体值经测量配置。

MVP 舞台允许 CPU 静态缩略预览，精确显示使用外部播放器。当前 D3D11 原生纹理不能直接承诺嵌到 eframe 的 wgpu 画布；若后续内嵌，必须单独设计设备/纹理互操作和资源生命周期，而不是逐帧 readback 冒充原生共享。

## 2. 工程目录与发行隔离

建议编辑器工程根布局如下，目录名为规划约定：

```text
MyGame/
  project.kakera-editor.json       编辑器清单、版本与内容根定位
  content/                         唯一游戏内容根
    story.xml
    chapters/
    scripts/
    ui.xml
    assets/                        可运行资源及其许可证
  authoring/                       原剧本、PSD/原画母版、作者注释
  .editor/                        编辑器元数据、事务日志、恢复信息
  .cache/                         缩略图、AI 描述缓存、可删除索引
  .work/                          冻结验证/试玩/发布代次
  builds/                         游戏发行目录、构建清单和测试结果
```

模型权重、推理二进制和机器特定配置放在编辑器自己的应用数据目录，不进该工程的 content。试玩存档位于独立用户/工程测试目录，也不放入 content。

当前打包器只排除一小组名称，并不按 XML 引用裁剪；.editor、.cache、authoring 和模型文件没有“天然不会被打包”的保证。所有打包入口必须指向冻结后的纯游戏内容根，不能指向 MyGame。构建前扫描发行清单，发现工程元数据、模型权重、私有剧本原稿、缓存或用户档即失败。

导入原有平铺游戏根时不擅自搬文件。记录外部内容根，编辑器元数据/缓存使用根外位置；提供显式迁移向导。资源导出需保留所有 XML/JS 和受支持模型文件依赖；无法分析手写动态引用时默认保留内容根内作者资源，不按静态可达图激进裁剪。

## 3. 单一事实来源与编辑表示

**已提交 XML/JS 源文件是游戏内容的事实来源。** 编辑器解析它们形成内存 AuthoringDocument，含幕 ID、章节/显示顺序、资源引用、完整画面和路由草稿；该表示不是另一个运行格式。

编辑器 sidecar 只保存显示名、面板坐标、原稿段落映射、标签/授权、管理范围、生成器版本、文件指纹和源码节点映射。不能在 sidecar 中再维护一套优先于源码的台词/剧情。崩溃恢复中的未提交草稿必须明确标记 revision，不得静默取代磁盘源文件。

资源 ID、真实文件路径、编辑器对象 ID、显示名称四者分离。Frame 主键始终为存档契约 ID；没有 ID 的导入幕暂按 name 定位，不能把分镜序号当 ID。标签和目录排序不改变引用。

## 4. 源码往返与管理范围

XML 使用保留原始文本/注释/空白的范围编辑或具体语法树。roxmltree 可提供读取与范围，不提供完整的保格式写回器，不能直接把 Model 重序列化来宣称无损编辑。

JS 有三种管理级别：

| 级别 | 识别条件 | 允许的可视操作 |
| --- | --- | --- |
| Managed | 编辑器生成的独立脚本文件，生成指纹与内容一致 | 全部受限路由/条件/更新可编辑，重新生成该文件 |
| Recognized | 经语法解析确认的可逆固定注册和受限表达式 | 只改定位明确的语法节点，保留其他原文 |
| Opaque | 动态注册、共享复杂函数、任意语句或解析不确定 | 显示代码块/声明契约/运行时目标，不自动重写 |

不能用正则替换或仅执行 on 注册就恢复全部 JS 控制流。JS 解析器的具体依赖在 E0 原型锁定，必须覆盖 BigInt、源位置与保留未知语句；模型不能自行把 Opaque 代码升级为 Managed。

初次接管一段逻辑必须显示源文件范围和前后差异，留下可恢复旧版。MVP 建议一个专用 Managed 文件拥有一组明确场景；跨文件公共脚本保持只读，避免双重注册。game.enter 全故事只有一个同名 UI 回调，生成器应合并所管理行为，不反复追加新注册。

## 5. 稳定标识和存档契约

新建幕时生成一次 UUID 并显式写入 id，后续保存、重排、编译、构建都不重新生成；作者可增加稳定且唯一的 name 提供 JS 引用。复制幕创建新 ID，移动/改名不改 ID。工程内素材、选项和 UI 节点也使用稳定唯一引用。

现有引擎允许缺省 id 并在每次打包候选中随机生成 UUID。编辑器不更改该行为：导入时标明“重打包可能使旧档失效”，固定 ID 是显式源码修改。发布过的内容不能自动以 name 猜测旧 UUID 或迁移旧档。

content-version 由作者控制。删除/更换幕 ID、改变变量声明/历史语义或固化已有发布的随机 ID，都进入兼容性风险清单；不能把更新版本数字当成自动迁移。构建清单记录引擎版本、源指纹、ID 策略、content-version 和实际包哈希。

## 6. 编译流水线

1. 冻结 project revision、source fingerprint、resource revision、模板版本和编译器版本。
2. 校验 AuthoringDocument：字段、资源类型、完整 visual、重复引用、路由所有权、未解决占位和 Opaque 范围。
3. 将可视条件/有序更新编译到受限 JS 结构；普通幕明确生成 Advance/Choice/End 注册。int 常量按十进制字符串保存，再生成 BigInt，避免浮点精度损失。
4. 生成 XML/JS 到私有候选目录。转义 XML 实体与 JS 字符串，禁止把原稿文本当模板程序插入。没有引擎支持的视觉属性时拒绝生成。
5. 生成 EditorSourceMap：每个幕/选项/属性/路由的对象引用、原稿段落范围、源文件与输出行列。随机生成时间戳不写入游戏内容。
6. 使用现有 loader 校验内容/注册，Bundle 做资源与初始生命周期验证。附加图检查只作编辑器检查，动态逻辑保留未证明标记。
7. 复查磁盘文件和 revision。结果过期则丢弃，不能覆盖作者新修改。
8. 在 UI 展示变更和诊断，通过后提交源码事务，并发布新的不可变试玩/构建代次。

相同输入、模板和编译器应产生逐字节相同的 Managed XML/JS。AI 非确定性在“提案”阶段结束，已接受提案的编译不再调用 AI。无缺省 ID 时 KPAK 保持当前确定性条件；带缺省 ID 的工程不承诺独立打包同哈希。

### 受管逻辑的精确映射

| 编辑表示 | 编译约束 |
| --- | --- |
| Advance 幕 | 一个 on.advance 注册，同步返回明确目标 |
| Choice 幕 | 每个 XML option 对应一个 on.choice；不能从回调直接“结束”而不返回目标，需指向显式 End 幕 |
| End 幕 | 一个 on.end 注册，没有隐式下一幕 |
| guard | 仅类型化比较与 And/Or/Not，读取更新前变量，不允许写入 |
| orderedUpdates | 有序 set/add；引用草稿新值时重新读取 ctx.vars，避免旧快照 |
| branches | 主回调更新之后按显示顺序判断，首命中返回，必须有明确最终目标 |
| integer | 以 i64 十进制字符串保存并校验，生成 BigInt；不经 Number 中转 |
| game.enter 行为 | 汇总成单个 UI 回调，按候选场景引用区分，执行顺序与预算可见 |

这种受限编辑语法只用于生成 JS，不能另建 Rust 条件解释器代替 QuickJS。添加表达式算术/函数时必须扩充类型检查和双向映射测试，不能让模型自由塞入未验证表达式字符串。

## 7. 事务、撤销与崩溃恢复

一个作者操作对应一个 Command + ChangeSet：前置 revision、涉及文件旧哈希、对象变更、新文件、依赖、兼容性影响及诊断。撤销/重做逆转已记录的变化，不重新运行 AI。外部改动使逆操作冲突时必须先合并，不能无条件覆盖。

多个普通文件的逐个原子替换不等于整工程原子提交。源码提交使用日志记录“准备/验证/提交中/完成”，保留旧内容与恢复清单；崩溃后先恢复到完整旧/新状态，再允许编辑或试玩。不要向用户承诺 Windows 目录覆盖天然原子。

编辑器启动的播放器只读取外部 .work 中的完整代次快照，不监控正在多文件改写的 canonical content。MVP 成功编辑后可重启到新代次；保持历史的连贯热更需要后续受控替换协议。若作者自行启动 --project content，现有监控仍会完整验证候选，但不能保证识别作者一次多文件逻辑事务的边界。

## 8. 缓存、资源与任务取消

缓存键至少包含文件内容哈希、解码/模型版本、缩略图参数和标签修订；同名文件替换后不得复用旧图或旧 AI 描述。大视频/模型用流式摘要，不能整文件读进内存。图集区域只是视图元数据，不为每个格生成发行纹理；点九预览使用当前标记规则。

分镜带和资源树必须虚拟化，只为可见区域及少量邻近项准备缩略图；后台索引可暂停和恢复。不要在编辑器滚动时触发全量 Bundle 重建，最终资源完整校验与快速作者反馈分层执行。

推理、验证、构建都带 job ID 和代次。取消后可以保存未完成诊断，但不得提交部分输出；杀工作进程只影响其私有暂存。任务结束后复查引用，不因为源图片在推理期间换了内容而应用过期关联。

工程中的脚本/资源均为不可信内容；校验进程使用引擎原预算与受限宿主，模型只收到编辑器挑选的输入。不要把游戏 JS 拿到具有文件/网络权限的编辑器脚本环境执行。
