转场仅影响 scene 画面；进行时暂停逐字并关闭选项，继续/空格先跳过转场。菜单/失焦暂停计时，读档直接恢复最终画面，不保存动画指针。滤镜在启动时缓存，额外过滤缓存上限 256MiB；不逐帧处理图片。可用 `ctx.transition` 在 game.enter 选择本次转场，`ctx.animate` 在 UI 事件播放单次动画。仍无任意关键帧、离屏后处理、自定义 shader 或资源遮罩转场。

基于 XML 场景和纯 Rust 控制器的 Windows 桌面 AVG 播放器。一句台词对应一个可独立还原的 Frame。当前用 JavaScript 触发器/回调组织剧情逻辑，QuickJS 执行计算，Rust 原子提交结果。实现依据见原始 [MVC 方案](doc/rust-mvc-plan.zh-cn.md)、[v0.2 策略](doc/v0.2-implementation-plan.zh-cn.md)、[v0.3 规则策略](doc/v0.3-implementation-plan.zh-cn.md) 和先于对应代码制定的 [JS 改造策略](doc/js-trigger-implementation-plan.zh-cn.md)。

当前支持 int/bool/string 变量、组合条件、顺序更新、条件选项和优先分支；保留背景与三个立绘槽位、中文逐字、历史、六个手动槽，以及 BGM/语音/音效三通道。游戏区域固定 16:9，窗口变化时等比缩放并留黑边。可运行样例为原七个剧情场景和十八个立绘演示场景、四变量、三种结尾。

v0.4 使用外部 XML 定义界面，通过 JavaScript/QuickJS 添加互动，无需游戏作者编写 Rust。HUD、存读档、覆盖确认、设置、历史、CG 画廊与大图查看等页面均在 [ui.xml](games/demo/ui.xml) 定义；交互见 [ui.js](games/demo/scripts/ui.js)。实现先于代码写入 [v0.4 落地策略](doc/v0.4-implementation-plan.zh-cn.md)。

## 启动与校验

需要 Rust stable（最低 1.88）及 Windows MSVC C++ 构建工具。首次构建需下载依赖；提交了 Cargo.lock，请使用 `--locked`。

```powershell
cargo run --locked
cargo run --locked -- --game D:/codes/kakera-avg-rust/games/demo
# 无需窗口和音频设备，校验剧情/UI XML、JS 注册/初始条件、图片、字体及 WAV/Ogg
cargo run --locked -- --check
# 禁用音频输出，但仍检查音频文件
cargo run --locked -- --no-audio
# 隔离存档和设置目录，用于调试或便携使用
cargo run --locked -- --save-dir target/my-saves
```

默认先查找可执行文件旁的 `games/demo`，再回退到编译时的源码样例目录。显式命令行相对路径相对于工作目录；XML 中的素材路径始终相对于游戏目录。原 `doc/rust-mvc-example` 不含素材，只作为 v0.1 数据契约保留；运行请使用 `games/demo`。

XML、JS 和素材在程序启动时从外部读取，不需要重新编译 Rust；编辑后重启生效。启动后使用该次读取的固定内容，当前没有热重载。`--check` 校验脚本语法、触发器注册和初始条件，不会穷举任意 JS 的所有动态分支；目标 ID、回调返回值及更新在执行时继续严格检查。

## 逐字、历史与输入

- 默认每秒显示 30 个 Unicode 字素簇，支持中文、组合字符和 emoji；换行按整句布局保持稳定。设置中速度为 0 表示整句显示。
- 文字未显示完时，“补全”或空格只补全当前句；完成后再按一次才推进。选择按钮在当前句完成后开放，空格不会选择默认分支。结尾完成后显示“已结束”。
- “历史”显示当前变量、角色、台词及已选项，包含当前句。只读、不支持回滚；循环访问也记录，最多保留最近 1000 条。
- 打开历史、存读档、设置或提示时暂停逐字；失焦也暂停，返回后不补算暂停时间。
- 重新开始清空历史、恢复变量初值并重新逐字。读档替换当前位置、变量及整个历史，当前句整句显示。存档不保存逐字进度或音频播放指针。

## 六个手动槽位与旧档

“保存”“读档”分别打开槽位页面，显示空槽、场景预览或错误原因。已有文件需要应用内确认覆盖；取消保留原文件。空槽、损坏或不兼容槽禁止读取，其他槽仍可正常使用。旧界面额外显示相对保存时间。

默认 Windows 用户数据目录为 `%LOCALAPPDATA%\kakera\kakera-avg\data\<story_id>`，以启动日志中的实际路径为准：

```text
slot-1.json ... slot-6.json  schema 3 快照，互相独立
settings.json              文字速度、总静音、三通道音量
profile.json               独立 CG 解锁，schema 1 / story_id
save.json                  v0.1 旧档，只读导入入口
```

schema 3 包含故事/内容版本、当前位置、历史、当前变量、历史起点变量检查点及保存时间；示例见 [v0.3-save.example.json](doc/v0.3-save.example.json)。读档检查变量键、类型及范围，从检查点重放保留历史的条件、目标与更新，并核对终点变量，全部通过才提交。历史裁剪时同步推进检查点。错误不会改写当前会话或重播音频。写档使用同目录临时文件、sync_all 和平台原子替换，不先删除旧档。每份 JSON 上限 1MiB，超限拒绝写入并保留旧档；变量数量和单值上限不能代替此总量限制。不承诺所有文件系统的断电持久性，历史一致性校验也不是防篡改签名。

旧 schema 2 槽位仅在无变量且内容版本匹配的故事中转换到内存，原文件不自动改写。检测到旧 `save.json` 时，读档窗口提供显式 v0.1 导入，也仅对无变量故事开放：恢复合法位置并建立一条历史，明确提示缺失历史。之后手动保存才写 schema 3。有变量故事拒绝 schema 1/2 旧档，不能从位置猜测变量。

存档 schema 与 XML content-version 独立。本轮样例使用内容版本 3，明确拒绝内容版本 1/2 旧档；不自动迁移其他内容版本。脚本更新若改变路由或变量语义，作者也必须提升 content-version。上面的 schema 3 JSON 示例保留 v0.3 内容版本 2，作为历史格式示例，不能直接用于当前样例。

## JavaScript 触发器（当前格式）

`story.xml` 负责完整画面、台词、选项文字和变量声明；schema 4 增加入口与脚本清单，当前 schema 5 进一步引用外部 UI：

```xml
<story schema="5" id="kakera-demo" content-version="3" entry="opening">
  <interface src="ui.xml" />
  <scripts>
    <script src="scripts/endings.js" />
    <script src="scripts/story.js" />
    <script src="scripts/ui.js" />
  </scripts>
  <!-- assets / characters / visuals / variables / frames -->
</story>
```

脚本顺序加载，可抽出共享辅助函数。当前不使用 ES module/import、Node.js 或浏览器 API。例子见 [回调注册](games/demo/scripts/story.js) 和独立的 [结尾计算](games/demo/scripts/endings.js)：

```javascript
on.advance("opening", () => "question");
on.choice("question", "accept", ctx => {
  ctx.add("trust", 1);
  ctx.set("met", true);
  ctx.set("mood", "期待");
  return "walk";
}, ctx => ctx.vars.trust < 3n);
on.advance("walk", () => "question");
on.end("accept");
```

- `on.advance(frameId, callback)` 响应继续；回调同步返回目标场景 ID，普通 JS 的 if/else、函数调用即可表达条件路由。当前场景正常显示，不自动穿越多句。
- `on.choice(frameId, optionId, callback, when?)` 响应指定选项；when 必须同步返回 boolean，省略表示可用。when 为 false 则隐藏，伪造选择同样拒绝。
- `on.end(frameId)` 声明结束。每个场景必须恰好属于一种触发器类型；选项与 XML 一一对应，不允许重复、缺失或未知 ID。
- `ctx.vars` 为只读快照视图，`ctx.frameId/optionId` 提供当前输入。所有 int 使用 BigInt（例如 `>= 2n`）；`ctx.set/add` 收集顺序更新，接受 BigInt 或安全整数 Number；bool/string 不转换类型。更新后再次读取 ctx.vars 可见草稿值。
- Rust 逐项校验更新的 i64 溢出、声明范围及字符串限制，再和位置、历史一起提交。异常、非法目标、错误返回值或目标选项条件失败，整个输入失败，旧状态与音频保持不变。条件回调不能更新变量。

每次求值建立新的隔离上下文并从缓存源码注册回调，避免闭包计数器和全局变量成为隐藏存档。共享函数可以复用，持久剧情状态必须写入声明变量。可用选项在提交边界计算缓存，绘制和逐字 tick 不执行 JS。历史检查点和存档重放使用同一套回调，不保存 JS 堆、函数或调用栈。长历史会增加重放计算量。

运行时通过 `rquickjs = 0.14.0` 使用 QuickJS 系列引擎（该绑定随包源码为 QuickJS-NG 分支），Windows MSVC 已实际编译。单次求值含源码注册的预算为 200ms 或 10000 次中断检查，JS 堆 16MiB、栈 256KiB；脚本最多 32 个、源码总量最多 1MiB，每次更新最多 128 项。没有宿主文件/网络/系统能力、原生模块加载器或计时器；时钟、随机入口禁用，异步返回与待处理 Promise 任务拒绝。许可证随 [licenses](licenses) 分发。

主程序通过 `ContentSource::read(相对路径)` 读取所有内容，`DirectorySource` 实现目录与真实路径边界检查，图片/字体/音频从字节解码。测试中的内存来源已完整加载 XML、JS 和素材；以后资源包实现同一接口即可接入。当前尚未实现压缩包格式、加密或自动解包。目录中保留的 `flow.xml` 仅作旧版参考，schema 4/5 完全不读取它，发布包也不包含它。

## XML 界面与 JS 互动

UI schema 1 使用 16:9 设计坐标，子节点位置相对父节点，并按父区域裁剪。支持 `scene/panel/image/label/button/slider/toggle/repeat`；基础属性为位置、大小、颜色、字号、圆角和图片 fit（stretch/contain/cover）。按钮可提供普通、悬停、禁用三种图片。

```xml
<ui schema="1" width="1280" height="720" initial="hud">
  <screen id="hud" modal="false" pause="false">
    <scene id="scene" width="1280" height="720" />
    <button id="settingsButton" x="1100" y="20" width="140" height="40"
            text="设置" event="open-settings" image="ui.button" />
  </screen>
  <screen id="settings">
    <panel id="settingsPanel" x="240" y="115" width="800" height="490" image="ui.panel">
      <toggle id="mute" x="30" y="30" width="500" height="38"
              text="总静音" value="settings.muted" event="mute" />
      <button id="back" x="650" y="420" width="120" height="40" text="返回" event="close" />
    </panel>
  </screen>
</ui>
```

图片 ID 必须在 story 的共享 assets 中声明。`screen` 默认 `modal="true" pause="true"`；模态页入栈，非模态页替换根页，只有顶层接收交互。唯一根页不可关闭，页面栈最多八层。`repeat` 将模板放入可滚动网格，source 可用 choices、slots、history、gallery、variables；模板内以 `item.*` 取该条数据，不支持 repeat 嵌套。

`bind`（文字）、`value`（滑杆/开关）、`image-bind`、`visible/enabled` 仅接受受支持路径；布尔可写 true/false 或 `not:路径`。来源有 `game.*`、`settings.*`、作者声明的 `ui.*` 及模板的 `item.*`；完整字段与类型见 [v0.4 契约](doc/v0.4-implementation-plan.zh-cn.md#4-只读绑定与数据集)。属性不接受内联 JS 表达式。绘制只读缓存，不逐帧执行脚本或读盘。

```javascript
on.ui("open-settings", ctx => ctx.open("settings"));
on.ui("close", ctx => ctx.close());
on.ui("mute", ctx => ctx.setting("muted", ctx.value));
on.ui("save-slot", ctx => ctx.save(ctx.item.slot));
on.ui("game.enter", ctx => {
  if (ctx.game.frameId === "accept") ctx.unlock("cg.lin");
});
```

回调获得只读 `ctx.game/vars/ui/settings/item/value`。`vars/ui` 的 int 为精确 BigInt；按钮 value 为 null、滑杆为 Number、开关为 boolean。可调用 `open/close/setUi/save/load/importLegacy/restart/advance/choose/setting/unlock/message`，同步返回 undefined。每次最多 32 条命令，先验证整个列表，再执行至多一种剧情/IO 操作；同类设置或多个 CG 解锁可聚合。不允许混合存档、设置等多类副作用，也不能直接跳转场景或访问文件。继续/选项仍经过逐字门控及控制器。save 默认不覆盖，须由作者确认页显式传 `ctx.save(slot, true)`。

局部 UI 变量和页面栈只在本次运行有效，不进剧情槽。CG 在 XML gallery 清单声明，`ctx.unlock(id)` 写独立 profile.json，读旧剧情槽、重开或关闭应用不会撤销解锁。`game.enter` 在候选 Session 提交前执行，允许 unlock/setUi/message/transition/animate；验证或写入失败保留旧会话及音频，历史重放不触发它。坏 CG 文件提示并使用初值，原文件不自动改写。新增页面、皮肤或已有能力的组合仅修改 XML/JS；新增宿主能力须扩展 Rust 命令与校验。

未知节点/属性、重复 ID、绑定类型、图片/回调引用和非法坐标均严格报错并附 XML 行列；节点最多 1024、深度八层，UI 文件最多 1MiB。目前不提供 CSS、DOM、复杂布局、富文本、任意关键帧或编辑器；超出文字节点高度会显示溢出诊断，作者需调整布局。正常菜单由 XML 定义，故障提示保留引擎最小窗口。

## 旧版声明式规则兼容

story schema 1–4 保持原生界面兼容，schema 5 必须提供 UI XML；旧 schema 4 契约归档于 [v0.3.1-example](doc/v0.3.1-example)。schema 5 不读取 flow.xml。UI-only 更新未改变剧情语义，样例 content-version 继续为 3。

story schema 3 可声明变量，flow schema 2 配置旧规则；完整历史样例保留于 [v0.3-example](doc/v0.3-example)，用于旧契约回归。schema 4/5 沿用相同变量声明限制：int 使用 i64，可声明 min/max；bool 只接受 true/false；string 最多 4096 UTF-8 字节。最多 128 个变量，ID 为 1–64 个 ASCII 字母/数字/下划线且不能以数字开头。可选 label 用于历史窗口展示。

```xml
<!-- story.xml 的 story 内 -->
<variables>
  <int id="trust" label="信任" initial="0" min="0" max="3" />
  <bool id="met" label="已相识" initial="false" />
  <string id="mood" label="心情" initial="平静" />
</variables>

<!-- flow.xml 的 choice 内 -->
<on option="accept" to="walk">
  <when><cmp var="trust" op="lt" value="3" /></when>
  <effects>
    <add var="trust" value="1" />
    <set var="met" value="true" />
    <set var="mood" value="期待" />
  </effects>
</on>
```

条件支持 cmp、all、any、not；整数支持 eq/ne/lt/le/gt/ge，布尔和字符串支持 eq/ne。每个 when 恰好一个表达式，最多 16 层、128 节点。effects 支持 set 和整数 add（可负值），每条列表最多 128 项，按顺序执行。条件在更新前求值；任一步类型错误、溢出或越界，整个场景/历史/变量更新失败。无效或隐藏选项也被控制器拒绝。

branch 按 XML 顺序取首个满足条件的 case，必须有一个最终 otherwise；next/on/case/otherwise 可带 effects，next/otherwise 不带 when。规则加载时严格检查所有节点；潜在可达性检查不穷举变量状态。完整语法和边界见 [v0.3 策略](doc/v0.3-implementation-plan.zh-cn.md)。

体验样例：初始直接结束进入安静结尾；散步一次再结束进入友好结尾；散步两次解锁邀请，邀请进入一同出发结尾。信任到 3 时隐藏散步，邀请仍可用；条件选项均在逐字完成后开放。历史中的过去选择不受当前条件影响。

## 音频与设置

音频使用 rodio 0.21.1，支持 WAV 和 Ogg Vorbis。启动时解码并缓存，绘制不读盘、不触发播放。BGM 循环；连续场景声明同一 BGM 时继续播放；切换资源或省略 BGM 时替换/停止。语音和音效在进入场景时单次播放，离开时停止旧音轨。读档、重新开始从头重建音频。

菜单/提示暂停语音和音效，BGM 继续；失焦暂停三通道。设置提供总静音、独立音量和文字速度，XML/JS 设置变更即时原子保存为独立偏好（旧界面关闭设置或退出时保存）。无设备或输出中断时提示并降级静音，剧情和存读档仍可使用。`--no-audio` 可显式禁用设备输出。

音频限制：单/双声道、8000–96000Hz、单资源最长 5 分钟/PCM 上限 128MiB、总 PCM 缓存上限 256MiB。样例中的 `lin.wav` 是验证语音通道的合成提示音，不是实际角色配音。所有演示音频均由本项目生成，来源与许可见 [素材说明](games/demo/assets/licenses/README.md)。

## 内容契约与模块

story schema 1/2/3 和 flow schema 1/2 继续兼容；音频从 story schema 2 开始支持，变量从 story schema 3 开始支持；声明式规则用 flow schema 2 配 story schema 3，当前 XML/JS UI 用 story schema 5（schema 4 JS 兼容）：

```xml
<audio id="bgm.room" src="assets/audio/room.wav" /> <!-- assets 内 -->
<frame id="opening" visual="room.empty">
  <text>午后的房间里，传来了轻轻的敲门声。</text>
  <audio bgm="bgm.room" se="se.knock" />
</frame>
```

每场景最多一个 audio，bgm/voice/se 可选；省略表示该通道静音，没有隐含继承。图片、字体、音频须使用游戏目录内相对路径。未知元素/属性、命名空间、重复 ID、类型错误、缺失引用和不一致路由都会阻止加载，XML 错误附文件与行列。文本与选项只接受普通 XML 文本，保留空格和换行，不接受内嵌标签。每个场景必须显式对应 next/choice/branch/end，选项与 choice 路由一一匹配；循环合法、不可达场景警告。

```text
src/model.rs         纯领域数据：场景、变量、规则、会话与历史检查点
src/model/rules.rs   纯条件求值、顺序更新及路由选择
src/controller.rs    注入 model::Logic，原子提交场景/变量/历史
src/script.rs        QuickJS 适配、注册验证、隔离与受约束计划
src/script/bridge.js 引擎内部接口；游戏 JS 从 ContentSource 外部读取
src/content.rs       内容字节读取接口与目录来源，预留资源包接入点
src/interface.rs     UI 拥有类型、严格 XML、绑定和资源/事件引用校验
src/interface/host.rs 受约束 UI 命令、页面栈、局部状态与 CG 持久化
src/interface/data.rs 提交边界准备只读绑定及重复列表缓存
src/interface/render.rs 通用 XML 节点绘制，返回一个事件
src/app/custom.rs    UI 脚本、候选状态、剧情/IO 操作的装配
src/presentation.rs  逐字时钟、字素边界、补全/推进仲裁
src/loader.rs        XML 严格校验及预设展开
src/loader/rule_xml.rs 变量、条件树和更新的严格解析
src/assets.rs        图片/字体准备与纹理缓存
src/audio.rs         PCM 缓存、纯通道计划、设备输出与降级
src/save.rs          六槽、schema 3、历史重放、只读旧档兼容、原子写入
src/settings.rs      独立偏好与范围校验
src/view.rs          只读场景绘制与 UI 意图
src/menus.rs         历史、槽位、设置窗口
src/app.rs           成功提交、呈现计时与进入副作用的装配
```

本轮明确需求已将“后续选型”落为 JavaScript + QuickJS 实现；schema 4/5 只在 scripts 清单接受外部 script 引用，不支持 XML 内联 JS。不引入 ECS、异步运行时或事件总线。GUI 固定 eframe/egui 0.33.3 与 wgpu，XML 固定 roxmltree 0.21.1，完整依赖版本以锁文件为准。
