# v0.2 落地策略：逐字显示、历史记录、手动多槽与音频

制定日期：2026-10-23。基线：根目录单 crate 的 v0.1 实现，以及 `rust-mvc-plan.zh-cn.md` 第 11 节。本文先于 v0.2 代码落地；实现完成后追加实际验证记录。

## 1. 交付范围与实现顺序

本版继续使用 Rust、eframe/egui 0.33.3、wgpu 和 XML，不改变“一句台词对应一个完整 Frame”的模型。目标是可操作、可重启恢复的完整播放器，而不仅是四个孤立功能演示。

顺序为：①文档与契约；②历史模型和控制器；③逐字呈现与输入仲裁；④schema 2 存档、多槽与旧档入口；⑤音频数据、缓存及场景进入事件；⑥界面装配、样例、测试、Windows 实机验收。保留 v0.1 原始文档与数据示例，更新可运行的 `games/demo`。

明确不做：回滚、从历史跳转、已读快进、自动播放、自动存档、缩略图、无限槽位、音频淡入淡出/精确寻址、音画时间轴、变量条件与脚本。历史属于会话数据；逐字进度、音频播放指针属于呈现状态，存档不承诺恢复到半个字或音频中间。

## 2. 逐字显示：基于时间与 Unicode 字素簇

- 新增 `presentation.rs`，维护当前文本的字素簇边界、已显示数量与小数时间积累，默认每秒 30 个字素簇。使用 `unicode-segmentation`，避免截断 UTF-8、组合字符及 emoji 序列。
- 由 App 在每帧绘制前推进呈现时钟；View 只读完整文本、可见前缀和完成状态。使用真实间隔，不以绘制次数计数；动画未完成时按约 16ms 请求重绘，空闲时不持续忙绘。
- 第一次继续/空格补全当前句，不同时推进；整句完成后下一次继续才调用控制器。选择场景也可补全，但选项只在文字完成后开放。结尾可先补全，然后显示“已结束”。
- 历史、存读档、设置、提示打开时暂停时钟；窗口失焦也暂停，恢复时不补算暂停时间。设置中速度为 0 表示整句显示。
- 正文换行以完整句子的布局为基准，隐藏未显露的字形，防止逐字期间末行重新换行造成文字跳动；原有长台词开发提示保留。
- 读档后当前句整句显示，重启/重新开始和正常进入新场景从头逐字。保存时不强制推进或补全，不影响剧情状态。

## 3. 历史记录：显式 Session 状态

`Session` 扩展为当前位置与按访问顺序排列的 `Vec<HistoryEntry>`。每条记录包含 `frame_id` 和可选 `choice_id`。进入故事时记录入口；有效推进/选择时，在离开的记录上登记选项，再追加目标记录。循环访问同一 ID 也记一条；重绘、补全、打开菜单、无效输入和已结束节点的 Advance 不追加。

历史窗口只读，显示角色/旁白、完整台词与已选选项文本，可滚动；当前句也在列表中展示完整内容。重新开始清空为一条入口记录；读档用保存的历史整体替换，不与当前历史拼接。

最多保留最近 1000 条，超过后丢弃最早记录，以限制循环故事的存档和 UI 成本。保留序列不要求从 entry 开始；保存校验仍要求每个相邻记录符合实际路由、所选选项存在、最后一条等于当前位置且尚无 choice_id。由于裁剪和旧档导入，第一条可以是任意合法场景。

控制器增加明确的“是否进入场景”结果：即使自循环或历史已达到上限，也必须能触发一次新的逐字/音频呈现，不能仅比较 frame_id 或整个 Session 是否相等来判断。

## 4. 六个手动槽位与可审阅的存档界面

- 提供 1–6 共六个槽位。文件为同一故事用户数据目录内的 `slot-1.json` 至 `slot-6.json`，槽号使用受校验的类型，不能由任意路径字符串构造。
- 保存/读档打开同一槽位窗口的对应模式。显示槽号、空槽/可用/损坏状态、保存时间的相对描述、场景 ID 和台词预览。空槽禁止读档；损坏槽显示错误且可被显式覆盖。覆盖已有槽前由应用内确认，读档失败保留原 Session、历史、逐字和音频状态。
- JSON schema 升级为 2，包含 `story_id`、`content_version`、`frame_id`、`history`、`saved_at_unix_ms`。整个快照验证成功才提交。继续使用同目录临时文件、sync_all、原子替换及失败清理；列表逐槽读取，不引入易不同步的索引文件。
- 原 `save.json` 不自动改写或删除。界面提供明确的“导入 v0.1 存档”入口，仅接受严格 schema 1 的旧结构。恢复当前位置并建立一条当前记录，提示“旧档不含历史”。之后用户自行存到六槽之一。槽位文件不假装兼容缺失历史的 schema 2。
- XML 的 content-version 与存档 schema 独立。此次示例仍保留原场景 ID 和 content-version=1，允许旧位置恢复；真正不兼容的剧情更新仍由作者提升版本。

## 5. 音频：完整目标状态与一次性的进入事件

### 内容契约

新增 story XML schema 2，加载器继续接受原 schema 1；schema 1 不接受新音频元素。flow 仍使用 schema 1。新格式如下：

```xml
<story schema="2" id="kakera-demo" content-version="1">
  <assets>
    <!-- 原 image/font 保持不变 -->
    <audio id="bgm.room" src="assets/audio/room.wav" />
    <audio id="se.knock" src="assets/audio/knock.wav" />
    <audio id="voice.lin" src="assets/audio/lin.wav" />
  </assets>
  <!-- characters / visuals 省略 -->
  <frames>
    <frame id="opening" visual="room.empty">
      <text>午后的房间里，传来了轻轻的敲门声。</text>
      <audio bgm="bgm.room" se="se.knock" />
    </frame>
  </frames>
</story>
```

每个 Frame 最多一个 audio 子元素，bgm/voice/se 分别表示背景音乐、语音、单次音效。仅接受 audio 类型资源引用，未知属性、重复 audio 和缺失/错误类型引用报告文件及行列。省略 audio 或对应通道表示该通道静音，不沿用之前场景的隐含状态。BGM 固定循环，voice/se 单次播放。

### 播放与容错

- 使用固定 rodio 0.21.1，启用播放和 WAV、Ogg Vorbis 解码；由其底层音频线程送出采样，应用逻辑保持单线程。不自行实现设备或混音线程。
- 新增 `audio.rs`：启动时读取并解码所有音频为共享 PCM 缓存；`--check` 同样验证音频，无需打开音频设备。限制单资源最长 5 分钟、PCM 上限 128MiB，限制缓存总量 256MiB，错误带资源 ID 与路径。
- 三个独立通道允许 BGM、voice、se 同时播放。App 在启动、有效剧情转换、重新开始、成功读档时执行一次进入事件，绘制与逐字 tick 不产生播放操作。
- 连续场景声明同一 BGM 时继续播放，不从头重复；BGM 改变则替换，省略则停止。新场景先停止旧 voice/se，再播放本场景单次资源。自循环也是一次进入，voice/se 会重新开始；读档/重新开始强制重建三通道，从头播放。关闭历史、保存完成或补全文字不重新播音频。
- 菜单/提示打开时暂停 voice/se，BGM 继续；失焦时三通道暂停。返回后继续。音量与静音可以即时调整，不重新创建音轨。
- 无设备或播放流错误只降级为静音并显示清楚的提示，剧情、历史、存读档仍可使用。提供 `--no-audio` 供无设备环境/测试显式禁用输出，但仍解码校验文件。
- 提供总静音、BGM/语音/音效独立音量。与文字速度一起写入独立 `settings.json`，不绑定某个槽位。设置关闭和应用退出时原子保存；坏设置提示后使用默认值。
- 演示包提供由本项目程序生成的低音量 WAV 音乐/敲门/提示音，附来源说明与可复现生成器。voice 通道使用合成提示音验证链路，明确不是实际角色配音。不引入不明授权录音。

rodio API 与特性依据：[0.21.1 官方文档](https://docs.rs/rodio/0.21.1/rodio/)。实际编译组合固定进 Cargo.lock。

## 6. 模块与提交边界

| 模块 | v0.2 职责 |
| --- | --- |
| model/controller | AudioCue、HistoryEntry、历史一致性、显式转换结果，无 UI/音频库类型 |
| presentation | 可单测的逐字时钟及字素边界；不读写 Session |
| loader/assets | schema 1/2 严格校验；图片/字体与音频各自缓存 |
| save/settings | 六槽、元数据、schema 2 校验、只读旧档导入、独立偏好文件、共用原子写入 |
| audio | PCM 缓存、纯通道计划、真实设备执行；错误通过通道回传 App |
| view | 场景/可见前缀/完成状态 → UiIntent，菜单读数据不修改 Session |
| app | 时钟与意图仲裁、模态窗口、成功提交后执行一次进入副作用 |

优先用普通 struct/enum 和函数。为了测试音频副作用，将通道计划与硬件执行分离；不因此引入通用事件总线或大范围 trait 框架。
