# v0.8.2 点九图、图集与 UUID 验收记录

日期：2026-10-25。依据 [实现策略](v0.8.2-implementation-plan.zh-cn.md)。应用版本 0.8.2；story 8 / UI 3 / save 8 / demo content-version=8，KPAK 1/2 不变。

## 实现结果

- 资源及 UI 新增专用 `<nine-patch>`，读取带一像素标记边框的源 `.9.png`。加载时校验并去掉边框，缓存多段伸缩与内容区，绘制共享纹理网格；固定边角、内容 padding、素材 density 和过小目标收缩均有明确规则。demo 对话背景内容图由 1208×180 改为 64×32，另有两种宽度的并列演示。
- 普通 image，以及 panel/button 图片皮肤，支持 `region="x,y,width,height"` 和 `region-bind="ui.xxx"`。JS 复用 `ctx.setUi` 修改字符串，提交时验证最终图像、区域及按钮状态皮肤，缓存后只改 UV，不切图或重新上传纹理。非法区域使包含剧情/保存等操作的整批计划失败。
- 用户确认使用稳定作者别名：省略 frame.id 时必须提供唯一 name；entry、JS 注册和目标可引用名字。工程使用稳定临时 ID，KPAK 1/2 打包候选为缺省 ID 插入 UUID v4，保留名字映射；显式 ID 和源工程不改写。存档/历史使用实际 ID，JS/UI 的 frameId 优先暴露作者名字。
- XML/JS 本身无法解析源 PNG 标记、改变渲染 UV 或在发布候选分配实际 ID，因此扩展 Rust 对应边界；演示布局和交互仍在 XML/JS，不增加脚本随机、文件 IO 或逐帧回调。AGENTS、API 第 26–27 节、README、发布指南和脚本已同步；v0.8.1 的三份现行手册留存 doc/archive。

## 契约与验证边界

**重新打包无 ID 场景会重新生成 UUID，因而改变槽位契约。** 同一个包重复启动/读档时 ID 固定；跨构建稳定存档应显式固定 id，否则重新生成时提升 content-version。name 提供作者引用映射，不执行旧档迁移；工程临时 name 档不能冒充发布 UUID 档。

只支持 Android Studio 保存的源 `.9.png`，不支持 APK 编译 NinePatch；每轴最多 8 个伸缩段，内容区每轴至多一段。点九节点当前不接受图片滤镜/区域裁剪/ctx.animate。图集不自动拼接散图或做纹理压缩，整图模糊可能混入相邻格，应留间隔。图片仍按既有策略预加载，本版没有引入场景级惰性解码。

本轮没有完整重做自动槽跨进程加载、末页第 200 槽、Ctrl 持续按住、视频菜单暂停/结束/跳过、所有热更可见编辑、真实窗口拖边/跨显示器 DPI 的人工矩阵；相关自动回归通过，历史人工记录仅作参考。GUI 使用 --no-audio，未验收设备音频流与主观听感；未实际测试其他操作系统。
