# 工作包 A：宿主 Fluent 框架验收方案

日期：2026-10-30。目标 v0.10.1；本文件保留验收方案，逐项执行范围以实际验收记录为准。本表是接手任务，不是通过记录。依据 [宿主落地](engine-i18n-implementation-plan.zh-cn.md)，与 [B 验收](game-localization-validation-plan.zh-cn.md) 分开计数。

## 1. 自动与静态审计

| 编号 | 输入/操作 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | 初始化正式宿主资源 | 只声明 zh-CN；无英文/日文正式提示，全部嵌入，不从 cwd/game 读取 |
| A02 | 默认 --help、未知 CLI 参数、无游戏/坏目录/坏包 | 在游戏尚未载入时仍得到中文；版本/参数名/退出码准确 |
| A03 | FTL 单文件及跨文件重复 ID/术语/属性 | 构建校验失败，位置指出文件/行列；没有后加覆盖 |
| A04 | 语法错误后仍含其他合法词条的 FTL | 整份候选拒绝；不得接受 try_new 的部分资源 |
| A05 | 缺失消息/value/术语、循环、超深/超边、未知函数 | 校验失败；没有 key 原文、部分句子或递归卡死 |
| A06 | 参数缺失、多余、类型错、null/对象、超长 | 有稳定诊断 code，旧提示缓存/会话不被部分更新 |
| A07 | 数值 0/1/多值、超过安全整数的参数 | select 分支与整数展示准确；不因 f64 四舍五入更改槽位/计数 |
| A08 | 低层错误含 XML 位置、JS 栈、资源 ID、路径及第三方原因 | 中文上下文完整，技术原文和源位置保留；内部逻辑不匹配中文字符串 |
| A09 | 全部正式 message ID 与注册参数闭包 | 每个可达消息都有完整样例并成功格式化，FluentError 列表为空；select 覆盖全部分支 |
| A10 | 合法格式化但注入缺参触发运行期错误 | 捕获错误，不输出 Fluent 部分结果；日志有稳定 code，集中紧急中文兜底，不 panic/递归 |
| A11 | 词条解析/函数/错误链的格式化 | Model/Session/存档/协议不出现 bundle、AST 或翻译缓存；Controller 保持纯依赖 |
| A12 | 工作线程准备坏热更与主线程提示 | 跨线程只传拥有的诊断/候选，不共享 RefCell bundle；未改变旧 UI/音频 |
| A13 | 游戏提供同名宿主 key、任意 FTL 路径 | 不覆盖内嵌宿主目录，不执行 IO/脚本函数 |
| A14 | 混合数字、文件名、非 ASCII 参数及隔离符 | 按 Fluent 默认隔离处理；不可见格式符不误报缺字；其他控制字符仍受目标限制 |
| A15 | 1000 次静止重绘，状态不变 | bundle 创建/FTL 解析次数不增；无逐帧 IO/JS；绑定文本只读缓存 |
| A16 | 语言/词条代数变化（仅测试伪目录） | 已缓存提示正确失效；生产没有因此添加新语言 |
| A17 | 超文件/总量/消息/参数/输出/引用 DAG 膨胀 | 格式化前有界拒绝，不先分配巨大 String 再发现超限 |
| A18 | 不同 requested 游戏文本/语音语言 | 宿主仍按自身唯一 zh-CN 正常显示；游戏开关不禁用宿主提示 |
| A19 | 键位中文标签和持久 canonical token | 只迁移易读名称；配置文件/比较/捕获结果仍保存原 token |
| A20 | 所有字体种子/宿主词条分支 | 随包字体覆盖当前中文与参数边界；UI_TEXT 无双重维护遗漏 |

## 2. 迁移完整性门槛

接手者必须交一份“旧输出位置 → 稳定 code/message_id → 参数 → 测试”的清单，按 main/pack/launch、loader/content/interface、controller/rules/script、save/settings/read/profile、App/view/render、media/audio/Live2D/GPU、shortcuts/colors/debug 分组。

用 rg 查中文字面量及 format!/bail!/ensure!/context 等，所有命中逐项分类。通过条件不是把所有中文从 Rust 源码抹掉；允许中文注释、测试/作者夹具和明确批准的集中紧急常量，但不允许遗漏普通用户提示。旧的中文 assert 字符串逐步改为 code/参数断言，保留少量真正验证中文最终输出的端到端断言。

核对错误链中的每一层：不能“最外层 Fluent + 里面十层硬编码中文”。泛型 anyhow/第三方原始文本不在翻译覆盖承诺之内，清单要明确区分。

## 3. 真实输出与 GUI

分别记录 CLI 重定向 stdout/stderr/退出码、原生启动错误窗口、播放器提示窗口、工程窗、快捷键捕获/冲突、坏设置/坏槽/缺资源/静音降级。触发失败使用独立临时工程/存档，不损坏用户原文件。

检查中文无乱码、稳定换行、长路径/数字参数、不因方向隔离符丢字或出现方框；窗口保持 16:9。提示打开时暂停剧情/菜单门控；关闭不穿透一次继续，不重复执行原命令。缺字体的负例不得靠开发机字体偷偷通过。

至少各用 D3D11、CPU 像素模式原生窗口检查提示；记录 CPU 模式仍使用原生 UI 渲染的事实。不把自动格式化测试当成 GUI、不把静音回退提示当成设备听感。

## 4. 发布与交付

两种资源包从源码外运行 --check；启动/错误/帮助仍有中文，不要求 game.kpak 附带宿主 FTL。检查二进制分发的依赖许可；系统中不存在 locales 目录、cwd 有恶意同名目录时结果不变。

完成 fmt/clippy/test/check/diff 后，填写实际版本、OS、命令、数量、日志、GUI 路径、未执行矩阵。**A 通过只证明宿主框架及中文迁移完成，不证明 B 已有游戏多语言，也不证明已完成其他语言的宿主翻译。**

实现状态与偏差说明见 [v0.10.1 实际验收记录](v0.10.1-validation.zh-cn.md)。本文中的原代码事实和“拟定”描述保留为设计依据，不代表当前尚未实现。
