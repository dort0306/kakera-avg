# v0.11.3 总音量与 2D 粒子效果实现记录（已实现）

日期：2026-11-01。当前已实现应用版本为 v0.11.3；本轮同时交付总音量与 2D 图片粒子，`story 8 / UI 3 / save 9 / profile 1 / read 1 / 隐藏槽 1 / KPAK 1、2` 与 demo `content-version=11` 均未改变。实际执行结果与未验证项记录在 [v0.11.3 验收](v0.11.3-validation.zh-cn.md)，作者可用契约见 [API 第 39 节](xml-js-api.zh-cn.md)。

本文保留方案、范围与实施顺序；拟议语法在实现完成后已并入 API 手册，手册与代码是唯一现行契约。

## 1. 交付范围

| 能力 | XML 绑定 / JS 命令 | 结果 |
| --- | --- | --- |
| 总音量 | settings.master_volume / ctx.setting("master_volume", value) | 已实现，与四项分项相乘并覆盖 UI 音效与 UI 视频 |
| 2D 图片粒子 | `<particles>` 节点 / ctx.particles(id).start/stop/clear/burst | 已实现，按页面归属、UI 时钟、硬预算 |

未实现（保持不做）：UI 音效独立滑条、角色专属音量、混音总线、淡入淡出、分贝曲线、任意脚本音频播放；粒子碰撞/物理、3D、自定义 shader、脚本 tick、逐粒子写入、剧情层（随台词切换）粒子。

## 2. XML/JS 优先评估结论

- 总音量无法只靠既有 API 无损实现：把四个通道改写成乘积会丢失分项值，UI 瞬时变量也不是可靠的跨进程偏好。因此只扩展 `Settings` 字段、绑定白名单、命令校验与统一播放增益，页面、滑条与事件仍由 XML/JS 编写。
- 粒子无法由既有能力组合实现：组件只在加载期展开，JS 没有 tick、时钟与随机，`ctx.animate` 与 UI media fade 只能做有限固定图片动画。因此新增宿主解析、预算、呈现更新与只读绘制；声明、层级、裁剪和页面归属仍写在 XML，交互仍写在 JS。

## 3. 总音量契约

- `master_volume` 为有限 number，0–1，默认 1.0；有效增益 = `muted ? 0 : master_volume × channel_volume`。UI 音效使用 `se_volume`，UI sequence 视频使用 `video_volume`。
- 总音量改变不重写任何分项值；`master=0` 保留分项与 `muted`，取消静音后恢复当前 master 与分项的乘积。
- 调节正在播放的 Sink 只更新增益，不重建、不重播、不改变进度或暂停条件；新建 Sink 在首次播放前应用已提交设置。
- 数值范围在 f64 输入阶段先校验，再转 f32，`1.0000001` 这类近界值不会被舍入成合法值；沿用既有 `ctx.setting` 整批校验与 settings.json 单文件原子写入，任何错误或写入失败都保留旧 UI、偏好与实际声音。
- settings.json 必须包含全部当前字段（含 `master_volume`）；缺失的旧文件按“坏设置”提示并使用完整默认值，不做字段补齐。
- 设置与播放句柄都不进入剧情 Model/存档；活动隐藏交接仍禁止设置持久 IO。

## 4. 粒子契约

- `<particles>` 是 screen 或 panel/nine-patch 的普通子节点，位置随父节点偏移、按兄弟顺序绘制、被自身矩形裁剪；不能声明在 repeat 模板内。
- 属性、取值范围与预算见 [API 第 39.2 节](xml-js-api.zh-cn.md)：`rate 0–200`、`burst 0–128`、`max 1–512`、`life 0.1–10s`、`size 0.5–512`、速度 ±2000、加速度 ±2000、自转 ±720；每页最多 4 个发射器、整份 UI 最多 32 个、全局存活 2048、单次更新生成 256、物理步长 0.1s。
- 归属：发射器属于声明它的页面；页面移出页面栈时实例与自动发射状态一起清除。`autostart` 页面可见即发射，显式 `stop`/`clear` 在离开页面前保持关闭。
- JS 只收集明确的 `start/stop/clear/burst` 候选命令；同一发射器一批只能有一个操作，发射器必须存在且其页面必须在本批提交后的页面栈中，`game.enter` 与 `screen.open/screen.close` 生命周期回调不接受粒子命令。整批校验成功才提交，失败保留旧 Session/UI/音频/效果。
- Model 只保存静态配置（`Definition::particles`），实例、随机、时钟与纹理句柄都在 App 呈现层；绘制只读已准备的几何与纹理，不做 IO/解码/资源创建。
- 时钟沿用 UI 演出：菜单（剧情暂停）时继续，失焦、宿主提示与调试暂停冻结且不补积累；长帧限制步长与生成量，不补发大量粒子。
- 读档、重开、首次进入与成功热更按当前页面栈重建声明初态，不重放历史 burst；热更与设备重建不保留旧实例或旧句柄。

## 5. 实施顺序（已完成）

1. 扩展 `Settings`、绑定白名单与命令校验，统一所有音频入口的增益计算。
2. 实现 `particles` 纯呈现模块（预算、固定种子随机、停止/清空语义、长帧有界更新）。
3. 严格解析 `<particles>` 节点并解析所属页面，加入每页/总量预算与资源引用校验。
4. 新增 `Command::Particles`/`Plan::particles` 校验、`ctx.particles` 桥接与只读网格绘制。
5. 接入 App：字段、UI 时钟、页面同步、提交应用、读档/重开重建、热更重建。
6. demo 增加粒子页与总音量滑条，更新素材生成脚本。
7. 更新 API 手册、数据契约、限制、README、发布脚本与验收记录，构建双二进制。
