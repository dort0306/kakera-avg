# v0.5.1 立绘动作落地策略

日期：2026-10-24；先于本版代码。延续 MVC、v0.4 XML/JS 与 v0.5 呈现层，旧 story schema 1–5、UI schema 1、存档 schema 3 继续兼容。

## 1. 最终姿态与动作

每个 Frame 仍为完整显示状态。portrait 新增 pose（normal/flipped/fallen-left/fallen-right/hidden），以及 enter、exit、duration、strength、easing。pose 默认 normal；入场/动作完成后必须回到该 XML 最终姿态，存档仅保存场景等既有内容，读档不重播动作。

enter 支持 none、fade-in/out、enter-left/right/up/down、exit-left/right/up/down、shake、bounce、turn、spin、fall-left/right。enter-* 从画面外进入；exit-* 退出到隐藏；turn 水平压缩/翻转到目标朝向，spin 连续模拟两圈后回到目标朝向；fall-* 旋转 ±90°并向下移动 64 设计单位，最终保持倒地。

动作时长 0–5000ms，默认 600；strength 为 0–128，默认 32，控制震动/弹跳幅度；方向进退使用保证移出画面的固定设计距离；缓动延续四种已有类型。fade-out/exit-* 要求目标 pose=hidden；fall-* 要求对应倒地方向；turn 要求 normal/flipped；其他可见动作不能以 hidden 为终点。exit 属性只接受 none/fade-out/exit-*，用于旧立绘被移除或同槽位替换时的自动退场。

## 2. JS 与提交

新增 `ctx.portrait(slot, action, duration=600, strength=32, easing="ease-in-out")`，slot 为 left/center/right。普通 on.ui 与 game.enter 均可，32 条命令预算不变。宿主先验证目标场景中确有该槽立绘、动作与最终 pose 相容，再提交任何剧情/IO/呈现变化；错误保留旧状态和动作。UI 事件与剧情操作组合时，以操作成功后的候选 Frame 为目标。

同槽动作后者替换前者，不建立队列或隐藏剧情状态。JS 重播 turn/fall 等会从该动作规定的起始状态开始；希望改变长期朝向/隐藏/倒地状态，应先通过剧情进入声明了对应 pose 的 Frame。纯震动/spin/bounce 不改变最终姿态。

## 3. 呈现与兼容

Model 只持有普通配置；App 的 Player 持有动作时钟、有限的退场快照与单槽动作。旧立绘退出、新立绘进入可以同场播放。新剧情输入取消未完成动作，按旧帧最终姿态开始退场。自循环重新触发声明的 enter。菜单/失焦暂停，不补算；读档直接最终姿态；重开正常进入。

全场转场仍优先决定旧画面的可见区域，退场动作可在旧层播放；退场快照最迟在全场转场结束时清理，避免角色在转场后重新出现。无全场转场时，在新背景上绘制退场快照，随后清理。旧 v0.5 图片预设继续叠加，静态镜像/旋转与立绘动作均由纹理网格完成，不重新上传纹理。

## 4. 验证与交付

覆盖严格 XML、参数/姿态相容性、JS 候选目标与整批回滚；动作首尾/中点、水平翻转/旋转、进退场裁剪、快照清理、自循环、暂停、读档及存档不含动作指针。demo 增加可进入的立绘演示分支与专用 XML 页面，包含所有动作及返回剧情，保持旧历史可重放，不改变原四变量语义。
