# v0.7 工程/发布、资源包与 D3D11 落地策略

制定于 2026-10-24，先于实现。本轮按 v0.7 开发；不更改故事/存档 schema 6、UI schema 2 的剧情契约。用户明确更新旧“启动读取、无热重载”阶段限制。

## 1. 运行状态

工程状态显式 --project <目录>（--game 保留为工程目录别名），默认源码运行工程 demo；发布状态 --package <game.kpak> 或自动发现 exe 旁 game.kpak。发布状态只读包，绝不回退散文件、绝不启动监控；Core DLL 是固定宿主原生依赖，放在包外程序旁，不从包/脚本加载任意原生代码。用户存档/设置始终在包外。

工程以原生文件变更通知监控目录树，合并短时间连续保存并去抖；恢复/新增/删除/重命名/图片、字体、音频、视频、Live2D、XML、JS 均触发候选构建。构建使用一致的只读内容快照，后台解码和验证，旧游戏继续运行；构建期间继续发生修改则丢弃过时结果后重建。没有内容读取或脚本执行放进绘制。

候选先验证格式/资源/脚本/初始生命周期，再对当前 Session 做 story_id、content_version、完整变量/历史重放及当前可用选项验证，并准备候选生命周期/媒体/纹理，成功后一次提交。失败保留原会话/声音/画面，通过工程状态窗显示错误；下次修改重试。兼容更新保留剧情历史，呈现时钟与 UI 页面从声明状态重建，不产生自动档或重复解锁 IO。契约不兼容时不自动清空剧情，工程窗提供显式“从入口重新载入”。

## 2. 自定义 KPAK 1 资源包

自定义、未加密的二进制格式，不采用 ZIP。外层固定头写 magic/version/flags、压缩与展开长度、SHA-256；有效载荷为严格目录表和去重内容块，整体使用 Zstandard 高压缩级别（默认 19）。按逻辑路径排序、确定性生成；内容相同的文件共享字节块，solid 压缩利用 XML/JS/模型 JSON 的重复。PNG/MP4 不做有损转码或谎称可显著二次压缩。

加载前校验长度/版本/flags/压缩帧边界，解压有硬上限，再核验 SHA-256、严格路径/唯一 ID/块边界和非重叠规范。单文件 128MiB、总展开 512MiB、文件数 10000；拒绝路径穿越、绝对路径、大小写碰撞、symlink 和畸形/损坏包。包完全读入受限快照，read 仅按目录表返回字节，不解包到内容目录。媒体内部临时文件仍仅是后端实现细节。

## 3. 打包工具

同 crate 新二进制 kakera-pack，输入工程目录和输出 .kpak。遍历工程内容（包含字体/模型许可，排除明确的编辑器/用户数据与构建目录），校验故事及所有资源后构建；输出在工程根外，拒绝隐式覆盖，--force 才原子替换。采用已有平台原子文件替换，失败保留旧包。报告原始/压缩字节、去重与文件数；发布脚本只复制 exe、game.kpak、Core 与许可证，不复制散装游戏资源。

## 4. GPU 与跨平台接口

Windows 首发原生 D3D11 渲染：egui/winit 负责输入/布局，D3D11 swapchain 绘制 UI/场景网格，转场、立绘平移动画/镜像/旋转/染色/闪白继续生成几何与常量，由 GPU 光栅化。将旧 CPU 滤镜迁至 HLSL（灰度、棕褐、像素化、预乘透明高斯模糊），将 Live2D 网格/蒙版/混合迁至 D3D11 顶点/像素着色器。

Cubism Core 官方参数/形变计算仍调用 CPU ABI；迁移的是纹理采样、网格光栅/蒙版/颜色/混合，不宣称把 Core 的 moc3 求解迁至 GPU。GPU 结果注册为宿主纹理，正常播放不回读 GPU 再上传；CPU 路径与测试截图可读回。

定义渲染能力/图像输出/滤镜与模型合成边界，领域 Model/Controller 不依赖 D3D11。未来 Linux Vulkan、macOS Metal 实现同一后端接口，本轮不提供伪实现。--renderer auto/d3d11/cpu；auto 优先硬件 D3D11，不可用时 CPU 效果/Live2D 回退并使用 WARP 提供兼容窗口呈现，显式 d3d11 失败应明确报告；运行时效果失败回退 CPU 并报告原因。设备丢失与超预算必须有明确处理，不无限重试或静默白图。

## 5. 验证与交付

包：确定性、去重/压缩率、非文件系统来源完整加载、坏头/截断/尾随/损坏摘要/路径/长度/解压预算、原子覆盖失败，目录与包得到同一剧情。

热更：真实文件修改/原子重命名/删除恢复、坏 XML/JS 保留旧状态、过期候选丢弃、兼容位置/变量/历史保留、不兼容阻止自动切换、发布无监控；实际窗口编辑文本/图片/脚本观察，无重启。

GPU：实际 D3D11 设备与 swapchain、CPU/GPU 固定样例像素对比（允许采样误差）、正/反蒙版和隐藏源、混合/透明度/滤镜、真实 Haru 动作和菜单暂停、强制 CPU fallback；实际窗口中文/16:9/存读档。记录设备/后端，不用编译通过替代 GPU 验收。

完成 fmt/Clippy/全部测试/工程与包 --check，更新 API、README、AGENTS、版本、打包脚本及验收。旧文档/用户文件/旧包保留，不提交或推送 Git。


## 6. 实现结果

已实现 KPAK/打包工具、原生监控与固定快照候选构建、App 事务式替换、D3D11 原生窗口、HLSL 滤镜与模型合成、CPU fallback 和 WARP 重建。GPU 结果保持原生纹理引用，读回仅用于测试/离屏诊断。工程内容提交帧抑制普通剧情输入，避免把旧画面的点击应用到新内容。

落地与验收边界见 v0.7-validation.zh-cn.md。首次 GUI 检查因桌面锁定中断，用户解锁后已完成真实窗口验收：XML/JS/图片热更新及错误恢复、GPU/CPU/发布窗口、200 槽跨进程恢复、自动档、模型/视频暂停与转场。修复热更新/CPU 重建后旧转场源丢失问题，补充事务测试；设备丢失和实际音频设备/听感仍未现场验收。以后版本实现 Vulkan/Metal 时应复用 PixelBackend/ModelDraw/Image，而不是把平台句柄引入 Model。

实现参考：[Microsoft D3D11 swapchain](https://learn.microsoft.com/en-us/windows/win32/direct3d11/overviews-direct3d-11-devices-create-swap-chain)、[混合状态](https://learn.microsoft.com/en-us/windows/desktop/api/d3d11/nn-d3d11-id3d11blendstate)、[Windows 文件变更通知](https://learn.microsoft.com/windows/win32/fileio/obtaining-directory-change-notifications)。工程通知由 notify 的原生后端提供，不在绘制中轮询读取文件。
