# v0.6 新基线落地策略

制定日期：2026-10-24。先于本版代码。用户授权建立新基线，不承担旧版本兼容；原始 doc 与旧版本验收记录保留。首发仍为 Windows x64。

## 1. 范围与数据契约

当前正式内容采用 story schema 6、UI schema 2、存档 schema 6，demo content-version 提升为 6。旧存档不自动转换、覆盖或猜测变量。仍以完整 Frame、纯控制器、QuickJS 隔离回调、ContentSource 和原子文件替换为基础。旧格式解析若暂留在历史代码中，不构成新基线的兼容承诺。

手动槽固定 200 个，按每页 10 个共 20 页展示，允许直接跳页；槽号使用 u16。菜单只读取当前页资料，绘制不读盘。UI 通过受约束分页命令换页；完整存档的历史/变量检查在实际加载边界执行。手动槽和 10 个自动槽独立命名，自动槽不能通过普通保存覆盖。

## 2. 自动保存与自动播放

成功进入场景后自动保存，包括选项和自循环；读档不再写自动档。自动档按单调序号轮换 10 份，使用同目录临时文件与原子替换；损坏槽不阻止其他槽加载。App 中已经经过控制器/读档校验的会话可直接捕获，避免每次进入重放全部历史。失败保留已有文件，报告状态并关闭 autosave 开关以免反复失败，不撤销已经成功提交的剧情。是否开启自动保存为独立设置。

自动播放为瞬时呈现状态，进入时重新计时，读档/重开和手动剧情输入停止；不保存自动播放指针。文字显示完成、全场转场结束、语音结束后再等待 auto_delay 秒，才提交一次 Advance。选项与结尾停止自动播放，不替玩家选择。菜单、提示、失焦和视频暂停计时，不补算暂停时间。每次 UI 更新仍最多提交一个剧情意图，用户输入优先。

## 3. 视频

新增 video 资源与 Frame 视频声明，用于片头/片尾。资源通过 ContentSource 读取，解码器内部一次性建立临时来源，不向规则/UI 暴露路径。Windows 使用 Media Foundation Source Reader 解码图像与音频；不依赖用户安装 ffmpeg。ffmpeg 只用于生成许可明确的合成演示素材。

视频覆盖 scene，HUD/字幕/菜单仍由 XML 定义；视频中关闭选项和逐字。支持结束后显式 Advance、允许/禁止跳过、暂停与静音音量；自然结束和跳过共用同一个已验证剧情提交边界，不从渲染内推进。读档从当前视频起点重新播放，不保证精确视频时间恢复。

视频解码在专用单工作线程运行，使用有界请求/帧结果，内存与分辨率/时长有限；图像上传在 App 更新阶段，绘制只读纹理。为真实媒体需求放宽旧“完全单线程”限制，不引入异步 runtime、ECS 或消息总线。失败有明确提示并可按声明允许跳过，不静默播放假画面。

## 4. Live2D

接入用户提供的 `C:/CubismSdkForNative-5-r.5`，使用官方 Cubism Core Windows x64 动态库计算 moc3 形变。Core 为独立运行依赖，保留原 SDK 许可与模型使用限制；不把测试模型默认纳入可公开分发包。

模型资源指向 model3.json；加载 moc3、贴图、motion3、expression3 仍通过 ContentSource。XML 为每帧声明模型、槽位、初始参数、动作/表情以及静态 fallback 图片。JS 命令仅触发已登记模型动作，不开放 DLL、文件或任意宿主 IO。模型实例、时钟、Core 句柄和纹理不入档，读档重建 XML 声明的状态。

先实现 Core 参数/网格、绘制顺序、透明度、裁剪蒙版、普通/加法/乘法混合和颜色；motion3 的线性/贝塞尔/阶梯曲线与 expression3 参数混合。采用受限分辨率的 CPU 离屏合成再上传现有 egui 纹理，保持当前 wgpu 界面；真实模型验收后记录性能与暂不支持的 Cubism 高级特性，不能以静态图片替代真实 SDK 支持的验收。

## 5. 交付与验证

顺序：契约文档 → 存档/分页/自动保存 → 自动播放 → 视频 → Live2D → XML/JS API、样例与新基线文档 → 完整回归、Windows 实际窗口和便携包。

自动测试覆盖槽 1/200/越界/隔离、分页、自动槽轮换/损坏/原子失败、自动播放输入仲裁/暂停/选项/语音、媒体状态机/坏资源/结束与跳过/新旧会话保持、真实视频解码、真实 moc3 参数与网格/动作及资源边界。

完成后执行 fmt、Clippy、完整测试和 --check；实际操作最后一页/第 200 槽，退出后读手动和自动档，自动播放与暂停，视频声音/结束/跳过、Live2D 动作和模型显示。按实际证据分别记录纯逻辑、解码、设备声音和 GUI 结果；未验证项明确列出。更新 API 手册、README、AGENTS、版本、包脚本，使 v0.6 成为后续工作的主要依据。


## 6. 实现结果与边界

本版已落实上述五项能力。Live2D 使用真实 Core，基础 Pose 支持互斥部件和链接切换，不含 physics3 求解、完整 Framework 动作混合、自动口型/鼠标跟随及新版 offscreen。CPU 合成最长边 512 像素、约 30Hz，超预算明确报错。视频首发仅 Windows Media Foundation，已验证 H.264/AAC MP4，音频启动预解码，视频流式解码；读档从零秒开始。资源预算、完整 XML/JS 签名见 [API 手册第 19 节](xml-js-api.zh-cn.md#19-v06-分页自动保存自动播放视频与-live2d)。

交付以 README、API 手册与 [v0.6 验收记录](v0.6-ui-validation.zh-cn.md) 为准。历史契约继续保留在原 doc 中，不据此承诺旧档兼容。默认包不带 SDK/Haru；本地样例由 tools/prepare-live2d-demo.ps1 从用户 SDK 生成，保留许可。


## 7. Live2D 测试接入默认 demo（2026-10-24）

用户追加要求将 Live2D 测试加入 demo。本轮直接扩展 games/demo：question 增加独立入口，新增待机/表情/参数三个完整场景，保留普通剧情立绘；在 XML 声明 Haru 和 F01/F02/ParamAngleX，在 UI JS 收集 TapBody:0 动作。测试舞台提供重置、自循环和返回剧情，允许普通手动/自动读档。

从用户 SDK 复制完整 Haru 模型及原许可到游戏素材目录，Windows x64 Core 放在固定宿主 runtime/live2d/windows-x64（非内容动态库路径）。宿主优先命令行/环境变量/程序旁 DLL，再使用源码内固定 runtime；打包复制到 exe 旁，正常 cargo run 和包内 exe 均可直接启动。此举更新此前“默认 demo 不含 SDK 模型”的约定，限本地集成与测试，不作公开发布操作；第三方分发约束仍由所附原许可说明。

新增场景/选项不修改原剧情更新语义，保留 content-version=6；原 schema 6 历史仍可重放。完成后更新 README/API/验收与包脚本，验证路由、动作命令和跨进程恢复，并实际操作窗口。
