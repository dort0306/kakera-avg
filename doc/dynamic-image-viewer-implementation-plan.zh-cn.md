# 工作包 A：动态图片框与 CG 单页查看落地方案

起草日期：2026-10-29；版本定稿：2026-10-30。本文保留原落地设计，功能及后续修复统一归入 **v0.10.0**。下文现状、拟定接口和分工描述对应起草阶段；当前支持的接口与限制以 [API](xml-js-api.zh-cn.md) 为准，实际通过项和未验项见 [验收记录](ui-extensibility-validation.zh-cn.md) 与 [独立复验](ui-extensibility-independent-review.zh-cn.md)。

## 1. 已有能力与缺口判定

以下已经存在，不应重复实现：

| 能力 | 源码依据 |
| --- | --- |
| image/panel 的 image-bind 绑定 UI string | src/interface.rs 的 image-bind 解析及类型/资源校验 |
| JS 改绑定值 | src/script/bridge.js 的 ctx.setUi；src/interface/host.rs 的 SetUi/validate_images |
| 单页单图 CG 查看 | games/demo/ui/cg-view.xml：cgFull 使用 ui.cgImage，fit=contain；ui.js 的 view-cg 同时设 cgImage/cgTitle 后打开 cg-view |
| gallery 图片、标记、标题、解锁 | interface/data.rs 的 gallery 列表，Profile 及专用 CG 资源 |
| 纹理复用 | assets 静态缓存、interface/render.rs 按绑定资源 ID 读取现有纹理 |

结论：用户要求的“一个页面和一个标签，只改图片内容”已经有底层实现。本工作包交付重点是把这条能力说明清楚、检查专用 CG 的完整路径，并完善复用查看页的浏览体验及回归。除发现被测试证实的宿主缺陷外，仅改 XML/JS/文档。

## 2. 冻结行为

- 一个 cg-view 页面，一个固定 ID 的 image 控件；不可按每张 CG 复制 screen 或在 JS 拼接 XML。
- 图片来源是已声明 image/专用 CG 的资源 ID，不是文件路径、URL、Base64 或任意宿主纹理名。不要增加 ctx.loadImage(path)、图片 IO 或游戏脚本的网络权限。
- 列表项通过 item.image 给出资源 ID；CG 解锁/持久标记仍用 item.id，不能混为一谈。同一资源用于多个收藏项时，要以收藏项 ID 导航和记忆当前位置。
- JS 只更新 ui.cgImage 等拥有的变量，再打开/更新现有查看页。已经位于查看页时切图只改变量，不重复 open 同一模态页；重复打开应按现有规则报错，不为它增加兼容分支。
- 初始绑定也必须是有效资源，页面隐藏时仍须通过校验。第一版不新增“空路径/空字符串表示隐藏图片”；确实没有图片时使用 visible=false，但绑定保留一个有效占位资源。
- 切换图片、标题、当前收藏 ID、按钮状态作为一批 UI 局部更新校验；任一图片/区域/类型非法则整批回滚。图像来自静态缓存，不在绘制或每次翻页重新读盘、解码、上传。

## 3. 全屏的两种含义

本包的默认目标是覆盖 1280×720 逻辑舞台的图片查看页：fit=contain 保持整图可见，空白区由作者背景填充；默认黑色可改。fit=cover 会裁切，stretch 会变形，只允许作者明确选择，不自动切换。

与此不同，显示器无边框全屏已经由 settings.fullscreen 和 ctx.setting 提供。打开 CG 不应自动写设置或记住另一套窗口位置。作者若提供全屏按钮，应作为独立设置事件提交，不能与某种新图像 IO 混写。本工作包不新增 F11、Esc 等硬编码快捷键，也不以系统全屏代替正确的图片布局。

覆盖查看页可继续作为模态页，黑色背景须覆盖整个舞台，保证底层画廊不会透出。隐藏工具栏后只留图像也仍是同一 image；关闭/重新显示工具栏采用顶层 background-click 的现有事件与 UI bool。屏幕黑边、底层页面、关闭按钮不会成为翻页点击区。

如果作者要求页面中**真的只有一个 image 节点**，可将查看页设为 modal=false，替换页面栈，使用宿主已有黑色舞台底色；contain 留边或图片透明区就不会露出旧页面。此时不能 close 唯一根页：返回事件必须显式重建作者已知的页面组合，例如非模态 HUD 根页再打开 gallery 模态页。若起点可能来自主菜单，作者用有限分支保存/选择返回上下文，不假定宿主提供任意页面栈恢复 API。两种布局都复用一个查看页/图片控件，最低验收须包含这种单节点根页变体。

## 4. 建议的 XML/JS 组织

复用现有 ui.cgImage、ui.cgTitle；增加独立的当前收藏 ID、工具栏可见性、上一张/下一张是否可用等 UI 变量。名字由实现者与当前 demo 对齐，不能把这些瞬时状态放进剧情槽。

| 操作 | 作者层职责 | 宿主层职责 |
| --- | --- | --- |
| 点击缩略图 | 校验收藏项已解锁，设置当前 ID/图片/标题/导航状态，打开同一查看页 | 一次验证整个局部变量与页面计划 |
| 上一张/下一张 | 从当前解锁收藏列表按稳定顺序找邻项，并更新同一控件绑定 | 只读取已准备缓存并绘制 |
| 隐藏/显示工具栏 | 只修改 UI bool；首次点击补回工具栏，不顺带切图 | 顶层背景命中、控件/滚动区域阻挡、单事件 |
| 返回 | close 当前查看页 | 恢复原画廊和滚动状态，不修改 Session |

浏览范围只包括当前解锁收藏。顺序按 gallery 输出的稳定顺序，第一/最后项禁用对应方向，不默认循环。初始化与每次切图重新计算状态，不能让被隐藏的解锁项成为默认兜底。

现有 UI 回调未提供“任意完整列表查询”。如果要新增查看页内翻页，优先在作者 JS 用自己维护的稳定收藏 ID→资源/标题表，以及当前已有的可信状态传递实现；不要假定 ctx.gallery 已存在。对任意作者图库做通用导航确需宿主 gallery 快照时，先单列小扩展评审：只能给出已存在只读条目，不给路径/IO。本包的最低必交付是从任意缩略图更新同一查看页，翻页扩展不能阻挡这个已有能力的验收。

## 5. 解锁与安全边界

gallery 解锁是作者交互约束，不是资源加密；image-bind 能引用已声明资源，不应被误称为防止作者脚本展示未解锁图片。demo 仍需在 on.ui 分支校验 item.unlocked，而不是只依赖 disabled 属性。

本包不得修改 profile 解锁集合，不因查看 CG、读槽、重开而撤销/增加解锁。调用无效资源不能把当前 Session、偏好或页面切换一半。UI 变量共享：不同页面故意共用 ui.cgImage 就会同步指向同一资源，需要独立图片时作者声明独立变量。

## 6. 资源与打包

沿用 ContentSource、当前资源类型/尺寸/解码/滤镜预算；普通 image-bind 不接受视频或 Live2D。fit 仅改变布局，不产生新纹理或滤镜副本；图集 region-bind 与最终图像组合仍在提交边界校验，越界拒绝。不能把 CG 大图需求顺手扩展成无界大图/磁盘惰性加载。

两种包按声明资源和 UI 依赖收集。动态候选必须事先声明资源，不能假定 JS 字符串引用会让打包器自动发现磁盘文件。新查看页被 include 引入时，包内仍合并到原 UI 入口，不改源 XML/JS。截图保存的剧情状态与查看页图像仍按既有规则，不能把查看 CG 当作新的剧情幕。

## 7. 实施步骤与完成条件

1. 核对当前 image-bind 从 XML→JS→整批校验→资源缓存→绘制的证据；若已满足，明确报告“复用”，不要造新 API。
2. 完善 demo 的单页查看、黑背景/contain、标题/工具栏开关和返回；可选翻页遵守第 4 节能力边界。
3. 增加有效切图、失败回滚、共享纹理和解锁分支测试，实际操作三种宽高比图片。
4. 跑现行检查和两种包、真实窗口。更新 API/README 的现有功能说明及新的验收记录。

完成证据必须包含“同一个页面 ID、同一个 image 控件 ID，在多张资源间切换”，以及切换前后 Session/历史/profile 不变。不得仅靠两张独立页面的截图宣称本需求完成。
