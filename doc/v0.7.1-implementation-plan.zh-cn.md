# v0.7.1 无控制台发布与多文件剧本落地策略

制定日期：2026-10-24，先于本轮功能代码。依据用户追加要求：发布启动不出现命令行窗口；协作编写的剧本 XML 从 story.xml 显式串联，打包合并为单一 XML。原 v0.7 文档保留。

## 1. 版本与边界

程序提升到 0.7.1。新增 story schema 7 表达严格的剧本链；UI 2、save 6、KPAK 1 保持不变。旧 schema 1–6 的历史/单文件解析保留原行为，不把缺失 next 当作 schema 7 的隐式结束。demo 改用 schema 7，但场景 ID、变量、JS 路由和 content-version=6 不变，纯拆分不会破坏旧剧情档的身份契约。

入口及后续剧本都用 story 根元素。只有入口 story.xml 声明 id、content-version、entry 和 interface；后续文件根只声明 schema="7"。assets/characters/visuals/frames/variables/effects/scripts 可以分散到任意链文件，每个文件每种分组至多一次；合并后同类 ID/脚本引用全局唯一，跨文件前向引用合法。interface 仍为单独 XML，不在剧本链中。

## 2. next 契约

```xml
<!-- story.xml -->
<story schema="7" id="example" content-version="1" entry="opening">
  <interface src="ui.xml"/>
  <scripts><script src="scripts/story.js"/></scripts>
  <assets>...</assets>
  <next src="chapters/first.xml"/>
</story>
```

```xml
<!-- chapters/first.xml -->
<story schema="7">
  <frames>...</frames>
  <next end="true"/>
</story>
```

每个文件恰有一个 next，只接受非空 src 或 end="true" 二选一；end="false"、两者并存、遗漏、重复、未知属性/子元素/普通文本均拒绝。src 使用游戏根相对 .xml 路径，不相对当前章节目录。链最大 128 文件，累计/合并 XML 各最多 16MiB；同时遵守 ContentSource 路径与单文件预算。拒绝循环、大小写重复、缺失/非 UTF-8/坏 XML、根/分组未知字段、跨文件重复 ID 与非法引用。

next 是内容文件装配顺序，不创建默认剧情路由；最后一个 end="true" 只结束文件链，不等于当前场景 on.end。跨章节仍按稳定 frame ID 注册 on.advance/on.choice/on.end，所有回调在同一全局故事上校验。

## 3. 编译、诊断与热更新

新增直接的剧本编译模块，通过 ContentSource 迭代读取链，校验每份文件，按分组合并为单一 story schema 7，并以 next end="true" 结束。保留原子节点原文和源位置映射；领域加载错误从合并坐标映射回章节文件/行/列。输出使用拥有的数据，不让 XML Node/借用离开加载阶段。

主加载入口和旧目录工具使用同一编译流程；规则、Controller、Model 不感知多文件。工程已有原生监控继续监控整个树，修改章节/next 同样构建完整候选；兼容进度/历史重放与事务替换沿用 v0.7，坏章节不能覆盖当前 Session/音频/显示。不按场景进入临时读下一章节。

## 4. 打包合并

kakera-pack 先验证原工程与完整剧本链，确认固定快照/指纹，再用合并 XML 替换包内 story.xml，移除链上其余剧本 XML。UI、JS、素材和许可仍按原逻辑路径收集；不合并 JS，不修改图片/音频/模型路径，不修改磁盘源文件。链外普通文件仍遵循原收集规则，不按扩展名误删 UI XML。

合并后再编码、自检并验证包内故事可独立加载，最后原子写入；已有输出仍需 --force，失败保留旧包。合并结果含单一 next end="true"，发布只读 story.xml，不依赖原章节文件。压缩/去重/摘要/预算与确定性规则沿用 KPAK 1。

## 5. Windows 启动与错误输出

播放器所有 Windows 构建使用 GUI subsystem，避免先创建控制台再隐藏导致闪窗。发布正常运行不分配/附着控制台；工程正常运行允许附着父控制台，没有父控制台时创建工程日志窗口。--check/--help 作为 CLI 操作尽量附着已有控制台，保留重定向 stdout/stderr，不额外弹窗口；kakera-pack 继续为控制台工具。

发布启动错误通过原生错误对话框报告，不能因隐藏控制台而静默退出；--check 的错误仍使用 stderr 和非零退出码。不会关闭用户已经打开的终端。实现依据 [Microsoft 控制台创建说明](https://learn.microsoft.com/en-us/windows/console/creation-of-a-console)、[AttachConsole](https://learn.microsoft.com/en-us/windows/console/attachconsole)、[AllocConsole](https://learn.microsoft.com/en-us/windows/console/allocconsole)。
