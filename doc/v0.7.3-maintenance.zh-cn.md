# v0.7.3 复验问题修复记录

日期：2026-10-25。依据 [失败复验报告](v0.7.3-reacceptance.zh-cn.md) 修复三项问题，不提升版本或修改 story 7 / UI 2 / save 6 / KPAK 1。历史验收及失败日志保留。

## 修复

1. **Ctrl 与自动播放仲裁。** App 跟踪上一更新的原始 Ctrl 状态；按住 Ctrl、松开当帧、宿主输入被阻挡时，自动播放均按未就绪处理，清除等待。松开当帧的间隔不能计入新的 auto_delay，后续从零等待。快进和自动播放仍通过同一个单次剧情操作分支提交，选项/结尾仍停止。状态只在 App 内，热更新候选同步该状态，不入领域数据或存档。
2. **非暂停模态菜单。** Ctrl 和自动播放使用已有 `State::keyboard` 的栈顶门控。`modal=true pause=false` 仍允许底层呈现时钟继续，但阻挡宿主快进/自动推进；页面本身的合法按钮命令沿用原契约。关闭菜单后可继续快进或重新等待自动播放。
3. **已读条数预算。** `mark` 在 100000 条时忽略新增 ID，保留原集合和未知 frame ID，不淘汰旧记录；`save` 再次验证数量与 ID。序列化超过 2MiB 或原子替换失败仍保留旧文件和 dirty，按原策略记录日志/重试。达到数量上限本身不写坏文件，也不将已有集合清空。损坏文件的既有空集回退保持不变，不增加隐式迁移。

修改位置：`src/app.rs`、`src/app/development.rs`、`src/app/skip.rs`、`src/read_history.rs`。README、API 第 23 节同步当前行为和预算限制；原验收/复验页增加本记录入口。
