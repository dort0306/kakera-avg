## 2. XML/JS 优先评估

| 请求 | 现有能力 | 最小宿主修改理由 |
| --- | --- | --- |
| 统一 image/panel 内部表示 | 已共用绘制分支，但 Kind 仍有两个变体 | 内部数据及遍历归一化只能改 Rust；作者 XML 不需要迁移 |
| JS 扩展 XML 标签 | tabs 等可手工组合，但解析器固定标签白名单 | 需要加载期注册和展开边界；新控件本身仍由已有标签与普通事件组合 |
| 任意 repeat 分页 | 只有手动槽专用分页，其余列表无切片 | 需要宿主按 repeat 缓存切片、元数据，存档源还需要按范围读取 |

保留 toggle 的现有 XML、绑定和值事件行为。不新增内置 tabs/pagination，不移除 image 写法，不新增自定义 Rust 控件插件、原生动态库入口、绘图 API、JS tick、DOM 或事件总线。

## 3. image/panel 内部归一化

建议将 Kind::Panel / Kind::Image 归为一个内部 Kind::Panel，名称可由实现者按惯用 Rust 调整。解析器仍分别接受两种 XML 标签：

- image 保持必需 image/image-bind、二者互斥、不允许子节点；仍不接受 panel 专用 radius。
- panel 保持可选背景、允许子节点、radius、父级坐标与裁剪能力。
- 两者的 fit、region、region-bind、effect、color-bind、资源类型和预算按原规则验证。
- 不因内部归一化放宽 image 的作者契约。原始标签和文件/行列留在诊断信息中，不通过运行期 Kind 区分输入合法性。
- 动画、图集区域、颜色缓存、国际化遍历、媒体目标、脚本绑定源验证等所有 Kind 匹配一并审计；只读节点仍不能获得按钮事件权限。
- 静态纹理、滤镜缓存、动态图片切换沿用现有路径，不产生额外解码、纹理或逐帧工作。

合并后的 Node 不持有 XML 节点或 QuickJS 对象。若需要构造期标记，限于解析中间数据；没有真实运行需求不新增长期 tag/兼容分支。

## 4. 接入位置与实施顺序

当前事实：src/interface.rs 声明 Kind 并严格解析节点；src/interface/render.rs 的 Panel/Image 已走同一分支；src/script.rs 收集独立事件和绑定；src/loader.rs 先加载脚本，再编译 UI include、解析并装配；src/interface/data.rs 以 source 名称保存列表；src/app/custom.rs 刷新当前手动页和缩略图；src/save.rs 的 list_page 固定十槽。

建议依次实施：

1. 单独归一化 image/panel，保持现有 XML 行为，并验证全部匹配点。
2. 增加组合标签注册 manifest 与受限展开；include 展开之后、最终严格 Node 校验和事件绑定装配之前执行。组件注册、事件定义与控件绑定都允许前向引用，不依赖文件碰巧先后顺序。
3. 为分页 repeat 建立按节点 ID 的页计划与缓存；不要将 source 名直接当作唯一可见列表缓存键。扩展宿主存档范围查询，不改变文件格式。
4. 接通 App 候选验证、热更、渲染重建、隐藏交接恢复、打包和 --check。任何新语法先完整验证，再允许状态或 IO 提交。
5. 增加实际可运行示例：用组合标签实现 tabs 与通用分页器；至少画廊和手动槽展示独立分页。此步属于后续实现，本轮不改 games/demo。
6. 完成专项与完整验收后，才将新语法写入当前 API 的已实现部分，并重写 README 中的规划状态。

不要求固定文件拆分；可新增小型 interface::components / pagination 模块，职责分别为纯展开校验与页范围计算。Model/Controller 不依赖这些模块，不向剧情存档加入控件或解释器对象。

## 5. 格式、版本与发布

本轮版本为 0.11.2，仅修改文档与 Cargo.toml、Cargo.lock 根包版本、发布默认目录等元数据。功能代码、脚本业务和 demo 保持原样。README 明确“未实现”。实现时继续按届时用户请求执行版本规则，不因这份文档而重复使用或跳过补丁递增。

方案沿用 story 8/UI 3/save 9/profile 1/read 1/隐藏交接槽 1/KPAK 1、2/demo content-version=11；不引入旧格式解析或自动迁移。新增的是 UI 3 的显式标签注册/分页语法，旧播放器仍应拒绝未知语法。若后续确需改变存储契约，必须另行说明，而不是悄悄补字段。

布局状态优先使用既有 UI 变量。普通剧情槽不保存它们；活动隐藏交接继续按已有机制保存 UI 变量，不新增解释器/分页纹理字段。应用版本变化本身不等于剧情内容不兼容。
